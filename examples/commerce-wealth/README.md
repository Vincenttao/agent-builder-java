# i豆商城与理财购买预制示例

这是人工编写、可编辑的模拟业务资产，不是 MOA 模板默认业务，也不是本次 Coding Agent 的生成结果。安装后提供 i豆商城、理财购买、综合业务主Agent 三个应用。主 Agent 使用模型判断意图，在 benefits/wealth 两个 Skill 中选择；这两个 Skill 在同一运行内执行，不冒充两个远程业务 Agent。

- i豆商城：余额/礼品目录/兑换；兑换前确认，默认 1280 i豆。
- 理财购买：购买演示理财A 3000元，模拟理财账户初始1000元、本人模拟储蓄账户5000元；提示先转入2000元，用户确认后转账，重新核对，再单独确认购买。
- 拒绝转账：零转账、零购买。转账后拒绝购买：保留已转账结果，零购买，不声称已回滚。

主Agent负责归属，Skill描述业务步骤与分支，模型选择授权操作。实际金额校验、资金不足拒绝、账本修改、幂等、确认绑定由程序/工具实施。工具用Python脚本访问独立HTTP Mock；工具名call_mcp不表示本示例另外部署了MCP服务器。

运行工作台后，另开终端 `MOCK_PORT=8772 npm run start:mock`，随后 `node --import tsx scripts/install-business-examples.ts`。安装从 MOA 空应用开始，只创建新应用，保存安装清单于本机忽略目录，重复安装核对原修订，不覆盖人工修改。安装会将本分支最新运行源码保存为新的平台模板发行，旧应用/旧发行保持原样。

在“综合业务主Agent”调试运行中，可以分别发送：

- “查询我的i豆余额，查询后结束。”
- “我要兑换1张咖啡券，giftId是coffee，quantity是1，请发起确认。”
- “购买演示理财A3000元；余额不足时先询问是否从本人模拟储蓄账户转入差额，转账后再单独确认购买。”

第二次确认前只完成转账，没有购买。金额单位在工具契约中为整数分（100分=1元），演示产品最低1000元、最高10000元。服务地址、demo客户和本人账户由保存配置固定，不由模型选择任意收款人。

余额变化只在当前Mock进程内保存。未知写入结果禁止重发，按原key核对；当前Demo核对未知转账结果后结束任务，后续购买需重新发起并确认。示例不包含真实金融系统、真实产品推荐、收益或真实交易。
