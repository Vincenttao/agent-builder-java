# 双角色与开发阶段组合走查

日期：2026-10-24。批次：DEMO-01；变更层：静态 Demo 与设计文档。以 `4d9cda9` 为修改前基线，使用独立浏览器实际访问 `http://127.0.0.1:8768/`，从“员工福利助手”的 i豆需求出发，再切换平台维护者。未启动第二、三阶段的真实前后端开发。

## 判断与修正

新建路线已可走通，但返回工作时仍需要知道“停在哪里、现在能做什么、看到的是哪一个版本”。本批把这些状态放入应用列表、工作区提示、历史入口和发行/交付页。

| 修改前实际复现 | 本批处理 |
| --- | --- |
| 两角色未保存代码刷新丢失；应用列表只显示“应用草稿” | 按角色暂存未保存代码；显示待审阅、待配置、待检查、待交接等真实页面状态 |
| “继续开发”总回应用概览 | 记住最后页签和文件；已有应用的右侧助手也提供继续入口 |
| 当前连接不可用时，调试页挡住历史 Trace | 新增独立“运行与轨迹”；筛选历史、查看 Trace/快照不要求当前连接可用 |
| 选择旧运行后，未完成确认不容易找回 | 提供返回未完成测试入口，保留原运行关联与确认/结果核对规则 |
| 交接后修改容易混淆旧结果与当前草稿；新候选替代旧候选入口 | 分别展示当前修订和历史交接；保留候选历史，支持指定旧候选预览与下载 |
| 平台同一份工程反复点击发行，版本从 1.4.0 再升到 1.5.0 | 已发行的工程修订禁止重复发行；下一版需要新修改和对应检查 |
| 平台只有应用诊断，没有工程操作来路 | 分开“工程活动”和“应用运行诊断”；保存、应用建议、检查、发行均有本地操作记录 |
| 平台工作草稿、检查与应用使用的发行版本不容易区分 | 发行页并列草稿、固定版本、检查报告和只读发行历史 |

## 已走过的角色与阶段组合

| 编号 | 角色 / 阶段 | 操作与核查结果 |
| --- | --- | --- |
| A01 | 应用 / 方案到一半 | 刷新后从应用列表识别“待审阅开发方案”；继续进入同一应用与方案 |
| A02 | 应用 / 配置到一半 | 名称及连接选择刷新保留暂存；已保存配置不变；放弃暂存恢复原值 |
| A03 | 应用 / 代码修改到一半 | 未保存映射刷新恢复且修订不增加；恢复后返回列表，再继续仍进入映射文件 |
| A04 | 应用 / 当前环境不可用，查看旧轨迹 | 运行后改为未接通企业环境；仍能打开旧 Trace、回放及执行快照，旧数据不变 |
| A05 | 应用 / 待用户确认时查看旧记录 | 发起兑换、切换到旧运行，再返回未完成测试；拒绝后订单数仍为零 |
| A06 | 应用 / 准备交付但检查失败 | 示例映射检查失败，候选按钮禁用；问题入口进入映射文件，修正后检查通过 |
| A07 | 应用 / 已交接后继续修改 | 新修订显示待重新检查；旧交接注明所属修订，不能直接交接新草稿 |
| A08 | 应用 / 固定新候选后查看旧版本 | 历史列表保留两个候选；下载旧候选与其原始快照完全一致 |
| P01 | 平台 / 尚无运行或操作记录 | 应用运行诊断和工程活动都显示真实空态，不预造成功历史 |
| P02 | 平台 / 工程编辑到一半 | 刷新恢复本角色未保存文件；恢复或保存后继续操作 |
| P03 | 平台 / 未修改已发行工程 | 发行按钮禁用，同一修订不增加模板版本 |
| P04 | 平台 / 工程检查失败 | 移除指导中的工程分层内容后，检查失败；发行页列出失败项并提供工程代码入口 |
| P05 | 平台 / 修复并准备发行 | 修复、检查通过后发行一次，刷新后版本不重复增加 |
| P06 | 平台 / 发行后修改下一版 | 页面显示未发行修改；历史发行快照不变；已有应用继续固定旧模板 |
| P07 | 平台 / 看轨迹与工程记录 | 应用诊断标明应用来源，并显示模拟 Span；工程活动记录实际页面动作，无伪造工程 Trace |
| X01 | 跨角色 / 来回切换 | 两角色各自的工作位置、对话及工程范围保留；平台新版本不会覆盖已有应用 |
| X02 | 历史 / 只读查看 | 打开 Trace、前进回放并关闭，完整持久状态不变；旧快照缺失字段不补造 |
| X03 | 手机 / 中途页和历史页 | 390 宽度下检查应用概览、运行、交付及平台工程、发行、活动、诊断，无横向溢出 |

上表在 [verify-stages.cjs](scripts/verify-stages.cjs) 中按 7 组执行，不把矩阵行数当作独立真实业务验收数量。既有回归另覆盖确认失效、成功写入一次、未知写入按原交易核对、陈旧建议拒绝、模板固定与非 i豆需求等约束。

## 实际点击与页面核查

独立 HTTP 浏览器依次走过：创建应用 → 待审阅时刷新 → 继续开发 → 绑定 Mock → 未保存代码刷新 → 查询 → 改为未接通连接 → 历史 Trace → 恢复 Mock → 待确认时查看旧运行 → 返回并拒绝 → 检查失败定位 → Agent 修复 → 固定候选并交接预演 → 修改并固定下一候选。随后切平台：查看应用 Span → 工程代码暂存刷新 → 检查失败 → 修复并发行 → 修改下一版 → 查看工程活动 → 返回原应用。

实际最终状态：应用草稿 r7，候选 r6/r7，交接只属于 r6；平台工程 r5，已发行内容固定 r4/MOA 1.4.0；应用仍固定 MOA 1.3.0。数据均来自本次实际页面操作，业务与发行结果仍为浏览器模拟。详见 [走查状态记录](../../test-results/prototype-v2-role-stages/after/walkthrough.json)。

## 验证与边界

- 新矩阵先在修改前页面因应用卡片不显示“待审阅开发方案”失败；[红灯截图](../../test-results/prototype-v2-role-stages/red/failure.png)保留。既有测试与独立验收断言未放宽。
- [最终阶段矩阵](../../test-results/prototype-v2-role-stages/final-checks/result.json)：7 组通过。[最终应用旅程](../../test-results/prototype-v2-role-stages/final-journey/result.json)：4 组通过。[最终既有回归](../../test-results/prototype-v2-role-stages/final-regression/result.json)：7 组通过。均为模拟 UI 检查，真实业务 E2E 为 false。
- 核查源码语法、可编辑源码与单文件 HTML 一致性、实际页面渲染、文档链接和完整变更差异。新增浏览器输出固定在本批目录，旧批次输出和原有未提交证据不改写；本批中间结果与失败截图保留。
- 文档检查发现概述中残留“五个工作区”，已随新增历史入口统一为六个。全工作区 diff 检查提示一个原有未提交日志的尾部空行；该历史文件未改动，本批文件的 diff 检查通过。本批截图、清单与检查记录约 6.4 MiB，无 SDK 副本或新运行容器。
- 只保存一个活动应用；代码暂存按角色各一个文件。数据保留上限为运行 20 条、候选/交接/发行各 10 条、工程活动 30 条。浏览器存储被清除后无法恢复，没有服务端持久化、并发编辑或已有应用兼容升级能力。
- 平台工程活动仅记录保存/检查/发行等页面动作；尚无真实模型工程 Trace。应用 Trace 及回放数据也是模拟。候选下载是设计 JSON，无可执行 JAR、真实 CI 或部署。
- 模型调用、Java 编译/JAR 打包及 Docker 构建均未执行，不计真实产品 V2-AC 验收。隔离浏览器完成后关闭，已有静态预览服务保留。
