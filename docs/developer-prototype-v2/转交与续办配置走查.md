# 转交与续办配置走查

日期：2026-10-25。批次：DEMO-01。目标是让应用开发者配置业务 Agent 的行为，并核查配置的交互效果；不是制作一段与配置无关的固定业务故事。

## 1 配置结果与概念

“开发 → 编排”现在包含四个入口：

| 入口 | 配置或检查对象 |
| --- | --- |
| 业务范围 | 当前业务及已配置 Agent/Skills 的分工；明确范围外示例 |
| 转交与续办 | 范围外交给谁、原任务未完成时怎么办、新任务结束后如何继续 |
| 业务 Skills | 同一份 Skill 内容、可用工具/Agent 操作、确认与完成规则；执行归属固定为当前业务任务 |
| 规则预演 | 单条输入判断，以及读取保存配置的转交/Skill 规则测试 |

接管目标可选择模板示例“企业总助理”，或应用添加的 A2A Agent；不能选择工作流作为这里的接管 Agent。目标不存在或缺少服务标识时提示修复，不自动改交其他目标。作为接管目标并不自动扩大本应用业务范围。

原任务策略支持“保留进度，先处理新请求”和“切换前询问用户”。结束后支持“提示是否继续”和“自动回到原任务”。自动返回仍先复核业务条件并重新确认，不自动执行写操作。已经提交的操作继续跟踪原回执，不伪装暂停、撤回或重复提交。

任务是一次业务办理实例，Skill 是其中使用的可复用能力。Skill 的一次调用可以包含多步、补充信息或确认，完成后返回所属任务，不新增独立业务待办。这是产品中的业务归属；不限制 Runtime 内部执行标识、子会话或 Trace。

## 2 开发者操作路线

1. 创建 MOA 应用并应用明确的福利需求方案；已有应用可以直接进入“转交与续办”，无需清空浏览器。
2. 选择接管 Agent 和两项任务策略，阅读随选择更新的摘要；未保存内容有明显提示。
3. “保存并预演”默认打开未提交原任务的测试条件；修改策略并保存后，询问/保留/自动返回分支会跟着变化。
4. 分别测试无原任务、已提交待回执、当前任务调用 Skill。查看原任务 A、新任务 B、状态和用户下一步选择；Skill 情形只有 A。
5. “查看配置文件”读取同一应用的范围及 `handoff` 投影；Skill 投影保留固定执行归属。新定义不是 MOA 原生运行配置。

配置与预演位置按应用隔离，支持刷新和身份切换。无修改保存不加修订，变更后旧预演过期且操作禁用；陈旧表单不能覆盖。旧应用无策略时要求显式补齐；旧“返回上级”预演明确过期，不自动解释为新接管行为。旧运行、候选、账本和模板快照保持原内容。

## 3 验证及修复记录

本批证据独立保存在 `test-results/prototype-v2-handoff-config/`，没有覆盖历史批次。代码生成、浏览器模拟与真实业务验证分开。

| 检查 | 结果与证据 |
| --- | --- |
| 最小红灯 | 旧 Demo 缺“转交与续办”入口，`red/failure.json` 记录预期失败 |
| 配置与规则 | 9 组通过，`final/result.json`：保存/投影、策略分支、参数复核、回执归属、Skill 归属、隔离/陈旧保护、目标错误、旧配置和 PC |
| 编排回归 | 9 组通过，`orchestration/result.json`：同一对象编辑、操作确认、无效输入、失效引用、候选限制及旧应用 |
| 双角色旅程 | 6 组通过，`roles/result.json`：应用调试/失败修复/Trace/交付，平台能力/指导/检查/发行及多应用保留 |
| 业务范围与兼容 | 最后补旧预演类型失效检查；`legacy-preview-red/failure.json` 复现旧结果被误显示为多候选。修复后重跑受影响的业务检查，`business-final/result.json` 记录 8 组结果 |
| 产物与文档 | JS 语法、生成 HTML 与源文件一致性、本地文档链接、范围内 diff 检查；现有服务与产物字节一致性记录在 `http.json` |

按最终各检查范围计 32 组，开发过程的重复运行不重复计数。配置/编排/双角色检查完成后，最后只增加单条输入预演对旧类型的失效判断；受影响的业务检查重新运行。前后构建身份分开记录，`pre-compatibility-validation.json` 保留先前检查的 HTML 摘要；不把旧报告改成最终制品报告，也不将这些页面检查当成完整 PRD 或真实业务验收。

过程里还修复了一个实际交互问题：首次编辑或无效保存后，“放弃暂存”没有立即出现；现在随暂存同步显示。测试先前也误把保留的空目标暂存当成预设方案未生效，已调整为显式放弃暂存后检查方案；没有删除陈旧保护或负向断言。临时编辑脚本的一次语法错误未应用到应用源码，随后修复；相关失败均不计为通过。

原业务检查脚本根据产品语义更新了导航名称和范围外目标预期，并新增旧预演兼容检查；未降低业务确认、历史快照、未完成配置、候选限制及隔离要求。原机器验收清单、V2-AC 和 TD15 证据未修改。
