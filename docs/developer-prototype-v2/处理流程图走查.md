# 处理流程图走查

日期：2026-10-25。范围：第一阶段静态 PC Demo；不开发真实 Runtime、LLM、A2A 或 Skill 执行。

## 用户可观察结果

“开发 → 编排”默认打开“处理流程”。输入请求与任务上下文后，页面定位到结果和图示，高亮预演去向，并说明原因。点击节点只查看规则，不改变请求的处理选择。

- 原任务补充或确认：校验任务和参数后续接，不重新全局分发。
- 当前范围内自己处理：调用已绑定业务 Skill，完成后返回当前任务；操作展示为可选集合，不连成固定执行链。
- 当前范围内委派处理：显示业务分工绑定的 Agent、触发示例和服务标识。
- 明确范围外：显示已配置的兜底 Agent，以及原任务处理和续办策略；可继续进入原有任务切换预演。
- 信息不足或多个候选：先澄清，不能把未命中当成范围外。
- 业务范围冲突、定义不完整或目标失效：阻断，不高亮成功转交，也不自动换目标。真实权限检查不在本次实现内。

图与节点详情都从当前应用保存定义生成。复用原来的单条输入预演状态与判断，未引入第二套路由配置。未保存表单有提示；输入、上下文、修订变化会移除旧高亮。节点查看位置与预演按应用隔离，同版刷新和角色切换可恢复。

新应用无预置 i豆范围和业务分工。应用福利示例方案后才出现相应 Skill 与兜底示例；其他 Agent 通过既有能力及业务分工编辑入口加入。图是设计投影，不是真实执行轨迹，实际运行记录仍使用原入口。
