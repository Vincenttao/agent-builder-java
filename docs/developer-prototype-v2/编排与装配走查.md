## 用户可观察的变化

开发页提供“应用设置 / 能力 / 编排 / 文件”。能力详情可进入编排，配置入口与能力绑定、Skill 过程和可用操作约束，再预演一个请求。业务 Skill 与原内容文件保持同一对象；编排 JSON 是只读设计投影。平台公共能力页增加模型与 Rail 职责说明，继续使用原模板维护与发行流程。

新应用没有福利入口。应用 i豆需求方案后才加入示例定义；旧应用经审阅建议后显式补齐，不改历史运行和候选。已有手工编排不由预设方案覆盖。

## 应用与平台路线

1. 应用用户从空列表选 MOA 模板创建福利应用，查看新增方案差异并应用。在编排中查看福利入口、Skill 与操作绑定。
2. 先按原路线绑定 Mock、修复余额映射、运行检查并固定候选。返回编排修改入口和过程：检查与预演过期，旧候选和运行不变；新自定义编排不能沿用 Mock 检查发布。
3. 为采购 Agent 添加入口，分别预演福利请求、采购请求、无匹配请求和多候选请求。预演不调用模型/服务，不写运行、订单或报告。移除能力后引用失效，必须修复或删除入口。
4. 保存 Skill 过程和约束，从文件页查看/修改同一内容。兑换确认保持模板固定；非法调用上限不保存；无修改保存不增加修订。
5. 未保存内容跨刷新、身份及应用切换保留。其他保存已改变基础修订时，旧暂存不能覆盖新内容。已有报告和快照保持独立。
6. 切换平台用户，查看公共能力中的机制分工；回归开发指导、工程编辑、检查失败与修复、预览、发行、新旧应用固定版本和只读诊断。
