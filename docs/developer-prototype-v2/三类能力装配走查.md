# 三类能力装配走查

日期：2026-10-24。范围：DEMO-01 静态页面、PRD 与交互设计；只按 PC 页面交付，不启动第二、三阶段开发。

## 本批变化

| 修改对象 | 原状 | 修改后及原因 |
| --- | --- | --- |
| 应用开发入口 | 只有业务技能、预置工具等详情页，没有统一装配入口 | 默认进入能力装配，选择 Agent／工作流、业务 Skill 或工具；具体执行方式在第二步选择，避免混淆协议、资产与执行方式 |
| 新增能力 | 只把新工具需求交给 Coding Agent | 新增装配草稿，可保存、编辑、移除和继续讨论；Skill 编辑 Markdown，工具选择 HTTP API、MCP 或 Python，脚本内容可简单修改 |
| 模板开放范围 | 只展示配置与文件开放边界 | 平台维护三类入口范围，检查、发行后供新应用使用；已有应用固定旧版范围 |
| 代码与状态 | 主要展示预置应用文件 | 新增只读 `capabilities/assembly.json`；草稿变更形成新修订，刷新、多应用和历史快照各自保留 |
| 验证边界 | 原有检查面向 i豆 Mock | 未实现装配项使完整候选检查失败并可定位回装配页；原有 Mock 仍可调试，移除草稿不改变历史运行 |
| PRD | Skill/Tool 责任已定义，缺少统一装配分类 | 新增 3.5，更新 V2-FR-03、模板/应用契约、MOA 约束与分期，新增 DMO-08；原 V2-AC 和 DMO-01～07 不变 |

三类入口不等于三种协议。远程 Agent 和工作流在当前 MOA 参考快照中都通过 A2A 执行；本地 Skill 内分 A2A/SCRIPT 操作；TOOL 有候选类型但默认未注册通用执行器。Demo 的新增装配项全部标记待实现、`simulation: true`、`runnable: false`，没有访问远程地址、运行脚本或获得企业授权。

## 过程记录与限制

首次浏览器启动被受限环境的本地 socket 约束阻止，未执行页面检查；使用获准的本机隔离 Chrome 后，旧页面在缺少“添加能力”处失败，记录于 `red-browser/`。第一版仍把新应用默认开发对象设为“应用指令”，同一步失败，记录于 `green-1/`；修正为能力装配后 `green-2/` 通过。最终补充三种工具方式切换、必填检查和无提示遮挡的截图，结果以 `final/` 为准，不覆盖失败证据。

这次验证只证明静态交互及本地状态逻辑。任意工具执行、真实 A2A/MCP/API、真实 OpenCode、Skill 装载、服务端权限、Java 制品与 CI/CD 均未接入。平台开关当前只限定三类新增入口；真实阶段还需细化执行方式及服务端校验。草稿弹窗内容须点击保存后才持久化，取消或刷新未保存弹窗不构成已保存修改。

复用已有 8768 静态服务；本批浏览器检查结束关闭。保留有限报告和截图，无模型调用、Java 编译、Docker 构建或复制工作区。旧 PRD、机器验收清单、历史走查和 TD15 未提交证据保持原状态；按仓库约定本地提交，不推送。
