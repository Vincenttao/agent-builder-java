# 统一能力与等待状态走查

日期：2026-10-24。范围：DEMO-01 静态页面、PRD 与交互设计，只针对 PC。第二、三阶段和 Runtime 开发未启动。

## 修改内容与原因

| 对象 | 原来 | 现在 |
| --- | --- | --- |
| 开发导航 | 能力装配、应用指令、业务技能、工具、连接、文件六个入口 | 应用设置、能力、文件三个入口，默认能力；连接在应用设置中维护 |
| 能力对象 | 装配草稿与预置业务 Skill/工具分在不同页面 | 同一列表展示已选与新增能力，按类型筛选、就地查看详情；预置对象仍引用原字段，不复制历史数据 |
| 内容编辑 | 新增草稿只在弹窗编辑，能力清单只含草稿 | Skill/脚本内容可在详情与文件双向修改；只读清单包含完整能力列表；修订、过期检查和历史快照规则不变 |
| 应用指令 | 名称未说明作用对象 | 改为角色与行为，标注应用层 System Prompt；区别于业务 Skill 和给 Coding Agent 的开发 Skill |
| 异步等待 | 用户难以区分等下游与等用户 | 远程能力详情提供 A2A 交互示例，明确等待下游、等待用户确认、原任务续接、完成和失败；已有兑换显示等待用户确认 |
| PRD | 六入口；异步回调边界不够明确 | 更新 3.5、8 章与 DMO-08，新增 3.6、7.3 和 DMO-09；V2-AC-11 明确等待对象与原任务续接，仍保留 27 个 V2-AC 编号 |

应用设置的 System Prompt 定义业务 Agent 的角色、范围和回答方式。模板与框架还可能叠加提示；权限、工具授权、确认绑定和幂等仍由执行层控制。Demo 不调用模型验证提示效果。

## 交付核查与边界

JavaScript 语法、单文件与源文件一致性、本机预览内容、文档链接/编号、相关 diff 及 45 个原有未提交文件的字节保持检查，记录在本批 `delivery-checks.json`。浏览器检查后仅补齐概览和演示路线的导航文案，没有改变受测行为；最终源码摘要随交付记录固定。

A2A 示例使用固定示例 taskId/contextId。它不调用 Runtime、不创建运行或 Trace、不修改应用、业务、报告或候选。静态核验 Runtime `c42eea2b`：发送器只推送 `COMPLETED/FAILED`，不能据接收端代码宣称中间 `INPUT_REQUIRED` 推送已完成；真实异步确认和持久化恢复需先讨论技术方案。

复用 8768 静态服务；本批浏览器均在脚本结束关闭。只保留有限截图、日志和设计 JSON；模型调用、Java 编译和 Docker 构建均为 0。真实 API/MCP/A2A、脚本执行、OpenCode、JAR 和 CI/CD 均未接入。旧机器验收清单、历史走查、TD15 证据与输入材料不随本批修改。按仓库要求本地提交，不推送。
