## 1 本批结果

“入口与路由”调整为“业务范围与转交”。应用方定义自己的职责，自己处理使用业务 Skill，委派处理使用挂载 Agent，范围外沿调用链返回上级。“业务 Skills”内保留同一份 Markdown 和“操作与规则”，不把模型指导与程序约束混在一起。

请求预演增加任务上下文，区分新请求、补充、确认、同域业务变化、委派、返回、澄清与配置错误。应用方不再手填上级意图标识；既有内部标识仍保留。无目标或无服务标识报错，不自动寻找兜底服务；范围内外冲突提示修正。

旧编排不自动改写：没有定义时审阅补齐建议；已有绑定但缺业务范围时明确提示，填写并保存后启用新预演。范围与 Skill 暂存按应用隔离，陈旧修订不能覆盖新内容。原候选、运行、Mock 账本及模板版本固定规则保留。

源码发现和业务规则单独保存为 [MOA 业务 Agent 分层与转交规则分析](../MOA业务Agent分层与转交规则分析.md)。PRD 3.7、DMO-10、交互设计、Demo README 与推进计划同步。原 V2-AC、机器验收清单及历史 TD15 证据未修改。

## 4 未验证边界与退出条件

预演是确定性示例，不证明真实 LLM 理解、A2A 委派、中间回调、Skill/Rail 执行或控制信号贯通。远端 L2 有转交路径；Native Skill 当前拒绝意图切换，上级不自动重路由 Skill。旧计划自动恢复尚无实现入口。这些边界已在页面和文档说明。

本批真实模型调用、Java 编译/打包、Docker 构建均为 0；Node 只生成静态 HTML。没有外部发布或真实业务写入。新增浏览器进程在脚本 `finally` 中关闭，复用已有静态服务。仅保留本批报告和有限截图，没有启动新的运行工作区或清理历史材料。

交付方式：审阅完整改动、相关文档检查后在 `demo/prd-v2-workbench` 本地提交；本次不推送。第二、三阶段继续先讨论技术方案。
