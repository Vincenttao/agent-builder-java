# 开发工作台 2.0 · 双角色交互 Demo

本目录交付第一阶段 DEMO-01。参考原 `docs/developer-prototype/` 的红白灰风格，按 [PRD 2.0](../Agent开发工作台_PRD_v2.0.md) 重组为两个工作区，以 Coding Agent 辅助编排贯穿 MOA → i豆 → 企业交付。原设计稿保持原样。

## 打开方式

直接用浏览器打开 [开发工作台2.0.html](开发工作台2.0.html)，无需安装依赖。也可在仓库根目录启动本机静态服务：

```bash
node docs/developer-prototype-v2/scripts/serve.cjs
```

访问 **http://127.0.0.1:8768/**。端口可用 `DEMO_PORT` 修改。该入口只提供本目录指定页面与资源，不读取 `.env.local`，不要求访问令牌、Docker、Java、数据库或模型 Key；关闭进程即停止服务。

## 推荐演示路线

点击左下角“演示路线”，从平台工作区开始：

1. **平台准备范式。** 查看 MOA 工程、公共能力、开发 Skill 来源。请 Coding Agent“开放场景可配置的资格校验”，预览差异并应用。
2. **发布并交接。** 检查开放契约，在“模板发行”发行新示例版本。点击“以场景开发者接手”，从模板创建应用。Demo 只保存一个活动应用，替换前有明确提示。
3. **场景编排与代码。** 请 Agent“兑换前增加资格校验”，应用差异。查看配置代码并简单修改名称；未保存内容不会被导航覆盖，旧建议不能覆盖已保存的新修订。
4. **查询及故障修复。** 联合调试“查余额”；把接口夹具切为“嵌套余额返回”，再次运行得到映射失败。交给 Agent 修复映射，再运行成功；旧运行快照保持原内容。
5. **确认与兑换。** 运行“兑换礼品”，确认后查看模拟订单。等待确认时改变礼品，旧确认失效。也可运行“写后超时”，再查询原交易结果，观察没有第二笔订单。
6. **Trace 与回放。** 在联合调试打开“Trace / 回放”，查看每步输入输出、播放/暂停/跳转。切到平台“联合诊断”可看 Span 标识。回放只读，不执行新业务。
7. **测试与交付。** 运行示例检查，固定候选，预览包结构，下载设计交接 JSON，预演企业 CI/CD。修改草稿后旧候选保留，旧检查不再允许当前草稿交接。

刷新保留本浏览器中的草稿与记录。“演示路线 → 重置本 Demo”只重置本设计稿。不同来源（文件直开和本机 HTTP）可能使用各自的浏览器存储。运行列表最多保留 20 条；旧记录不因修改草稿而改写，但超出列表上限会移出本 Demo。

## 演示范围

| 已实现的点击能力 | 尚未接入的真实能力 |
| --- | --- |
| 两角色导航、开放范围、模板发行/接手 | 登录身份、服务端权限、范式发行后端 |
| 简单代码编辑、预设建议、差异应用与冲突检查 | 真实 OpenCode 会话、开发 Skill 装载与模型生成 |

| 模拟 Trace、输入输出详情、只读回放 | OTLP 接收、观测存储查询、完整业务状态记录 |

所有页面标明模拟来源。Java/Python 编辑器只保存文本；Python 预演器仅识别两份预置映射，修改为其他代码时显示未验证。下载清单含 `kind: design-only`、`simulation: true`、`runnable: false`，不可作为部署包。

## 源文件与验证

布局源文件为 [src/index.html](src/index.html)、[src/style.css](src/style.css) 和 [src/app.js](src/app.js)。单文件页面是可交付设计产物，随源文件一起提交。修改后运行：

```bash
node --check docs/developer-prototype-v2/src/app.js
node docs/developer-prototype-v2/scripts/build.cjs
node docs/developer-prototype-v2/scripts/verify.cjs
```

浏览器检查复用仓库已有 `@playwright/test`，默认使用 `/opt/google/chrome/chrome`，其他环境设置 `DEMO_BROWSER_PATH`。检查输出在仓库忽略的 `test-results/prototype-v2/`；只覆盖本检查的固定文件，不清理历史证据或其他目录。

2026-10-24：7 组浏览器检查通过，对应 PRD DMO-01～07。检查包括桌面 1440/1280 与手机 390 宽度、未保存/过期建议保护、失败修复、确认失效/拒绝/超时核对、只读回放、候选过期、下载边界、重置隔离和输入转义；检查期间零外部 HTTP 请求、零浏览器异常。已查看场景、平台、回放截图。本机 HTTP 入口另通过静态内容一致、指定资源 200、非开放路径 404、角色切换与代码编辑器冒烟检查。以上是模拟交互验证，不计为 V2-AC 或真实业务 E2E。
