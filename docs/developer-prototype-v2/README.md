# 开发工作台 2.0 · 双角色交互 Demo

第一阶段 DEMO-01 的可点击设计稿。应用开发者从空应用列表出发，用 **MOA 开发模板**创建应用，提出业务需求，与 Coding Agent 一起开发、测试和交付。i豆是创建后提出的业务需求，没有 i豆模板或预建应用。原 `docs/developer-prototype/` 保留。

## 打开方式

直接打开 [开发工作台2.0.html](开发工作台2.0.html)，或在仓库根目录运行：

```bash
node docs/developer-prototype-v2/scripts/serve.cjs
```

访问 **http://127.0.0.1:8768/**，端口可用 `DEMO_PORT` 修改。无需访问令牌、Docker、Java、数据库或模型 Key。静态服务仅提供本目录允许的页面与资源，不读取 `.env.local`。

**新版 Demo 加载时自动清空旧演示数据。** 每次修改页面、样式或脚本后运行构建命令，内容版本自动变化；刷新新版会清除旧应用、草稿、对话、运行、候选、交接和平台演示记录，回到初始状态。同一版本内刷新保留当前进度，也可在“演示路线 → 重置本 Demo”中手动重置。只清理本 Demo 的浏览器存储；文件直开与 HTTP 入口各自保存。请使用生成的 HTML 或本机服务，不直接打开未构建的源码 HTML。

## 现在怎样找功能

- **右上角：切换用户身份。** 默认是“陈晓 · 应用开发者”，可切换为“林知远 · 平台开发者”。页面始终显示当前姓名与身份，导航、工作内容和 Coding Agent 上下文随身份变化；编辑位置和未保存内容保留。这是模拟用户视角，不是登录或权限管理。
- **应用用户左栏：应用。** 应用列表显示各应用的状态、模板、修订和上次位置。模板选择放进“新建应用”表单，不占独立导航；平台用户以“模板开发 · MOA”和“记录与诊断”分组，进入代码页仍保留所属导航。
- **应用标题：名称及切换器。** 点击名称可搜索并切换应用，也可返回列表或新建。最多保存 10 个应用；达到上限会阻止创建，不覆盖已有内容。
- **应用内横向页签：概览、开发、测试、运行记录、版本与发布。** 内容和右侧 Coding Agent 均属于当前应用。

| 开发入口 | 在这里做什么 |
| --- | --- |
| 应用设置 | 编辑角色与行为（应用层 System Prompt）、选择模型、配置系统连接；工具详情引用同一连接 |
| 能力 | 默认入口；统一查看 Agent／工作流、业务 Skill、工具，筛选类型、查看详情并添加/编辑能力；已有 Mock 与待实现草稿明确区分 |
| 编排 | 定义业务范围、接管 Agent、原任务保留与续办、业务 Skills 和操作规则；预演配置效果 |
| 文件 | 同一对象的配置与代码视图；指令、业务 Skill、映射和新增 Skill/脚本内容可编辑，能力清单、连接及编排定义为只读视图 |

“装配”是添加、配置和绑定能力的动作，不是另一套对象。预置福利 Skill、四个工具和新增草稿在同一列表中；内容文件与详情双向同步；能力详情中的“在编排中使用”进入业务分工或 Skill 过程编辑。System Prompt 定义业务 Agent 的角色、范围和回答方式，运行时还可能叠加模板规则；它不替代程序控制的权限、确认或幂等。右侧开发 Skill 则指导 Coding Agent 修改工程。

本轮面向 PC 使用。主工作区与 Coding Agent 并列，助手输入与发送保持可见，指导和对话可独立滚动。已检查 1280、1440、1920px 窗口；未新增手机专用功能。

资格校验和用户确认属于业务规则，不作为外部接口工具展示。右侧开发 Skill 指导 Coding Agent，业务 Skill 随应用执行；二者用途不同。

## 直观看请求会处理到哪里

进入 **开发 → 编排 → 处理流程**。图示读取当前应用保存的配置：

- 上方输入请求和当前任务上下文，点击“查看路径”，自动定位到图示并高亮去向。
- 三个主要分支分别为调用业务 Skill、委派已挂载 Agent、转交兜底 Agent；另展示原任务续接、先澄清和配置阻断。
- 点击节点查看具体条件、目标及可用操作，直接进入现有配置入口。查看节点不改变预演结果。
- 未保存配置不会进入图示；输入、上下文或配置修订变化后，旧高亮失效。Skill 操作是可选集合，不代表固定顺序。

这是设计预演，不是执行轨迹，也不调用后端。空 MOA 应用先配置范围和业务分工；i豆方案应用后才显示福利示例。检查记录见 [处理流程图走查](处理流程图走查.md)。

## 开发者如何配置转交与 Skill

“开发 → 编排”包含 **处理流程 / 业务范围 / 转交与续办 / 业务 Skills / 规则预演**，默认打开处理流程。当前应用是下层业务 Agent，平台维护上级的全局分发。

1. 在“业务范围”定义自己和已挂载能力能处理什么。新 MOA 应用没有 i豆职责，应用福利开发方案后才加入福利范围、Skill、操作及接管示例。
2. 在“转交与续办”选择三个配置：**范围外交给哪个 Agent、原任务未完成时怎么办、新任务结束后如何继续**。模板提供“企业总助理”作为设计示例，也可选择自己添加的 A2A Agent；需先填写其服务标识，不发现或调用真实服务。
3. 点击“保存并预演”。以“原任务尚未提交”为条件开始测试，观察保留/询问、完成/失败、稍后续办、复核和确认。返回配置页改成“切换前询问”或“自动回到原任务”，再测试，交互分支会随保存的配置变化。
4. 测试“原操作已提交，等待回执”，核查切换后原任务仍在执行、迟到回执不混入新任务且不会重复提交。“无进行中任务”无需挂起与恢复。
5. 在“业务 Skills”编辑业务内容和可用操作。Skill 是能力，不是独立业务待办；它在当前任务内调用。点击“预演 Skill 调用”，模拟多步、等待输入和返回，任务始终为 A，不新增 B。

在同一 Demo 版本的应用里，缺少策略时到“转交与续办”选择接管 Agent 并保存；缺少业务范围时先补范围。同版本内绑定与历史快照保留，不自动把旧“返回调用方”规则转换为新目标。无修改保存不加修订，暂存按应用保留；旧修订表单不能覆盖新内容。

“单条输入判断”继续提供自身处理、委派、范围外转交、澄清及配置错误的确定性示例匹配。“转交与 Skill 规则”使用固定测试条件和已保存策略，不调用 LLM、A2A 或脚本，不写业务账本、运行记录或发布证据。自动回到原任务仍要复核与确认，不自动执行业务。

文件页的 `orchestration/business-scope.json` 包含范围、分工与 `handoff` 策略；`orchestration/skills.json` 包含操作及当前任务执行归属。它们是只读设计投影，标记 `simulation: true`、`runnable: false`，不是 MOA 原生运行配置。自定义策略不能沿用固定福利 Mock 的通过报告。

源码发现见 [专项分析](../MOA业务Agent分层与转交规则分析.md)，当前检查见 [转交与续办配置走查](转交与续办配置走查.md)。真实任务检查点、恢复与 Native Skill 转交仍待模板实现；本次配置测试不证明这些能力已接通。

## 可点击路线

1. 在应用列表新建，选择 MOA 模板；可展开“模板提供什么？”查看工程骨架、开发指导和开放范围，填写内容不会丢失。名称填“员工福利助手”，目标填“为员工查询 i豆余额、查询礼品目录、提交兑换并核对结果，接入企业福利系统”。创建表单没有业务示例选择器。
2. 向 Coding Agent 发送需求，或点击“根据目标制定开发方案”。查看差异后应用到当前应用。建议明确标注为预设内容，不是模型生成。
3. 进入“开发 → 编排”：查看当前业务范围、分工、Skill 过程及操作规则，使用“请求预演”检查路径。返回“开发”：在能力列表选择 Skill 或工具查看详情，在应用设置的连接中选择“本地 Mock”并保存，在文件中编辑代码。企业环境尚未接通，选它会阻止运行。
4. 进入“测试 → 交互调试”。先查询余额，再切换“嵌套余额返回”使旧映射失败，查看 Trace、交给 Agent 修复并重新运行。原失败快照保留。
5. 在终端用户模拟器中选择礼品并确认兑换。可体验更换礼品使旧确认失效、拒绝零写入，以及写后超时后按原交易核对、不重复提交。测试输入不改变应用修订。
6. 在“测试 → 测试检查”运行示例检查。失败项可定位到对应配置、文件或未完成测试。“版本与发布”引用报告，通过后固定候选、预览交付包、下载设计 JSON、预演企业 CI/CD。如另行修改业务范围、分工或操作约束，会提示自定义编排待实现，不能沿用这条预置 Mock 的通过结果。
7. 返回应用列表再创建“采购协同助手”，目标描述采购系统需求。它只生成待补充接口的通用草稿，不误跑 i豆。再从标题切回福利应用，查看原草稿、对话、订单、运行和候选仍然保留。

模板开发者路线（身份仍为平台开发者）：

1. 从右上角切换为林知远，工程首页按维护范式、准备公共能力、编写开发指导、检查与发行进入。
2. 在公共能力中选择模板开放的 Agent／工作流、业务 Skill、工具入口，保存范围后检查与发行；新应用使用新版范围，旧应用不变。再查看公共能力卡片的职责和扩展范围。公共工具由平台维护，业务 Skill 和已开放的应用适配由应用方维护；当前不登记任意 API。
3. 进入开发 Skill，编辑应用开发指导；预览应用开发者将收到的内容。这个预览与右侧平台任务自身的指导分开。
4. 检查开放契约。可把平台指导改成不完整内容，观察检查失败和发行阻断，再恢复 `service/` 工程分层内容并重新检查。
5. 在模板发行页预览当前草稿的应用方创建体验，检查后发行新版本，查看只读发行快照与工程活动。预览不创建应用、不切换用户。
6. 切回应用用户，确认旧应用继续固定旧模板；新建应用使用新版本。平台还可查看应用运行诊断与只读 Trace，不显示无关工程检查或发行待办。

初始 MOA 模板已可使用，应用开发者不必先扮演平台维护者。新模板只影响之后创建的应用，不覆盖已有应用。应用标题下“基于 MOA · 版本”提供只读来源说明；平台发行页查看已发行说明不会自动切换用户。平台的“应用运行诊断”汇总所有应用，可按应用和结果筛选；回放不会改变应用开发者当前打开的应用。“工程活动”另记保存、检查、发行等页面操作。

新增能力的演示边界：应用方通过“开发 → 能力 → 添加能力”选择三类对象，保存为待实现草稿。支持 API/MCP/脚本方式、Skill/脚本内容编辑、刷新恢复和多应用隔离；不会发现服务、访问接口、执行脚本或获得新权限。草稿可交给 Coding Agent 讨论，不误套为余额映射或资格校验。待实现项阻止完整候选检查通过；原有 i豆 Mock 可继续调试，移除草稿后重新检查。真实接入和完整权限管理后续实现。

A2A 交互示例：新增 Agent／工作流草稿并保存，在能力详情打开“查看 A2A 交互示例”。从“等待下游执行”选择“模拟需要确认”，进入“等待用户确认”；确认后携带原任务标识续接，再模拟完成或失败。此示例不执行草稿、不生成 Trace/运行记录、不修改业务或候选。真实 Runtime 中间回调还未接通，详见 PRD 7.3。

## 中途恢复与数据范围

同一 Demo 版本内，各应用独立保存草稿、代码/表单暂存、Coding Agent 对话与待审阅方案、测试输入、待确认任务、Mock 账本、运行、报告、候选和交接记录。切换应用和刷新后可继续。手工代码未保存时可以返回列表、切换应用或角色；在应用内部换文件、执行及应用建议仍需先保存或恢复。暂存不参与执行，基础修订变化后拒绝旧暂存覆盖。

每个应用保留最近 20 次运行、10 个候选和 10 条交接，以及一个未保存文件。平台另保留一个未保存文件、10 个发行快照和 30 条工程活动。加载新版 Demo 或手工清除浏览器存储会丢失这些演示数据；没有后端保存或多人协作。已有应用的模板升级流程尚未实现。

## 演示与真实能力的边界

| 可点击能力 | 尚未接入的真实能力 |
| --- | --- |
| 双角色、多应用、MOA 模板、需求方案、差异与代码编辑 | 登录授权、真实 OpenCode 与开发 Skill 装载 |
| 系统连接选择、接口视图、查询/兑换/故障模拟 | Java/Runtime、Python 执行、企业接口 |
| 模拟 Trace、步骤输入输出、只读回放 | OTLP 接收、观测查询与业务事件存储 |
| 示例检查、固定候选、企业交接和 JSON 清单 | 可执行 JAR、可构建源码包、真实 CI/部署 |

Java/Python 只保存文本，映射预演只识别两份预置脚本。指令和数量规则可保存，但不执行模型，模拟器每次兑换 1 件。下载包含 `kind: design-only`、`simulation: true`、`runnable: false`。示例检查不是独立业务验收，不计为真实业务 E2E。

## 源文件与检查

可编辑源文件：[src/index.html](src/index.html)、[src/style.css](src/style.css)、[src/app.js](src/app.js)。单文件 HTML 随源文件一起交付。修改后按影响运行：

```bash
node --check docs/developer-prototype-v2/src/app.js
node docs/developer-prototype-v2/scripts/build.cjs
DEMO_CHECK_OUTPUT=test-results/prototype-v2-orchestration/next-check node docs/developer-prototype-v2/scripts/verify-orchestration.cjs
DEMO_CHECK_OUTPUT=test-results/prototype-v2-unified/next-check node docs/developer-prototype-v2/scripts/verify-unified.cjs
# 受影响的回归：分别设置独立 DEMO_CHECK_OUTPUT，再运行已有 verify-roles、
# verify-multiapp、verify-assembly、verify-journey、verify-stages、verify.cjs。
# 新批次请更换输出目录，不覆盖上述证据。
```

浏览器检查使用已有 `@playwright/test` 和 `/opt/google/chrome/chrome`，可通过 `DEMO_BROWSER_PATH` 更换。身份检查的 HTTP 入口需先启动预览服务；省略 `DEMO_URL` 则直接检查单文件。`verify-template.cjs` 是旅程检查的兼容入口，不重复运行。本批证据位于 `test-results/prototype-v2-unified/`；命令中的 `next-check` 仅为下一次检查示例，实际执行请使用新目录，避免覆盖。
