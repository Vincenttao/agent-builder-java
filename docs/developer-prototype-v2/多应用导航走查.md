# 多应用导航走查

日期：2026-10-24。批次：DEMO-01 导航与多应用刷新。分支：`demo/prd-v2-workbench`。受影响层：独立静态 Demo、浏览器检查及相关产品文档。

## 观察与修改

| 原问题 | 本次结果 |
| --- | --- |
| 全局左栏与应用内导航混排，不清楚当前在哪个应用 | 全局左栏仅“应用、开发模板”；进入应用后，名称与切换器下方显示五个横向页签 |
| 只保留一个应用，新建会替换原应用 | 最多保存 10 个独立应用，标题可搜索切换；列表展示各自进度和最后位置 |
| 能力与接入、代码与配置混合不同对象 | 开发页分为应用指令、业务技能、工具、连接、文件；保留源码查看和简单修改 |
| 接口工具混入资格检查、用户确认 | 四个外部接口展示输入输出；规则归入业务技能，连接单独选择环境 |
| 发布页同时承担测试执行 | 测试页执行检查并定位失败；版本与发布引用报告、固定候选和预演交接 |
| 平台诊断只看到当前应用的数据 | 汇总所有应用并可筛选，Trace 显示当时应用；回放不切换或改写应用方上下文 |

各应用独立保存代码与表单暂存、对话与方案、测试输入、待确认任务、模拟余额和订单、运行、报告、候选和交接。旧单应用数据迁入列表，历史运行和候选保持原内容，不自动升级模板。

## 验证记录

本批证据单独写入 `test-results/prototype-v2-multiapp/`，由 Git 忽略；此前批次证据未覆盖。此目录保留本批失败、最终结果和截图；临时浏览器关闭，复用原 Node 预览服务，没有新增 Java/Docker/模型工作区。

1. **红灯。** 在旧实现运行新多应用检查，`red/` 首先暴露创建表单标题差异；随后将默认入口断言前置，`red-entry/` 确认旧页面默认是模板页而非应用列表。两次失败截图保留。
2. **新增检查。** `multiapp-final/result.json`：8 组通过。覆盖全局/应用导航分层，代码、指令与规则暂存，对话恢复，余额/订单/待确认隔离，报告/候选/下载隔离，平台筛选和只读回放，桌面/手机，旧 schema-3 单应用迁移，以及 10 应用上限不覆盖数据。迁移使用删除新注册表字段的旧格式夹具，逐字比较历史运行和候选。
3. **既有检查。** `verify-journey/result.json` 4 组，`verify-stages/result.json` 7 组，`verify-final/result.json` 7 组通过。确认失效、拒绝零写入、超时核对不重复写入、陈旧建议拒绝、只读回放、候选冻结等断言保留。
4. **定位调整。** 旧脚本的系统接入/代码导航改为“开发 → 连接/文件”，工具数由混合的 6 项改为 4 个接口，另断言业务技能保留资格校验和用户确认。检查按钮改到测试页。首次回归在 `verify/` 因返回测试页后仍停留“测试检查”，找不到礼品选择器而失败；脚本显式切换“交互调试”后通过，没有修改业务预期。
5. **实际页面走查。** 使用隔离 Chrome 访问 `http://127.0.0.1:8768/`，从空列表创建福利应用，审阅方案，逐项访问开发对象，绑定 Mock，触发嵌套映射失败、查看 Trace、修复重跑、确认兑换、检查、固定候选、预演交接，再创建采购应用并切回福利应用。采购需求保持通用草稿；平台查看福利应用诊断，手机页面未横向溢出。路径记录在 `after/walkthrough.json`。
6. **视觉修正。** 人工查看手机截图发现标题被旁边按钮挤窄。仅调整手机页头样式，让名称和按钮分行；重新生成单文件后，定向复查 390px 页面，标题区域宽 360px、无整页溢出。结果为 `mobile-layout.json`，修正前截图保留，修正后为 `after/15-mobile-tools-fixed.png`。这项 CSS 调整不重复业务回归。
