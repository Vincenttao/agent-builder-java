# 双角色完整流程与页面评审

日期：2026-10-24。范围：DEMO-01 静态设计稿。依据：[PRD 2.0](../Agent开发工作台_PRD_v2.0.md)的开发责任和分阶段范围；入口：[可点击 Demo](开发工作台2.0.html)。

结论：本轮从应用开发者及模板开发者视角走通现有演示流程，并修正职责展示、需求误分类、导航定位、交接预览及 PC 布局问题。模板开发者仍属于平台开发者，不新增第三类用户。此结论仅针对明确列出的模拟路线，不代表任意业务、真实工具开发或企业系统接入已经可用。

## 1 检查方式与证据范围

- 使用隔离的 Chrome 浏览器上下文，在 `http://127.0.0.1:8768/` 从空应用开始，通过页面点击、输入和下载操作完成两条路线；不修改用户已有浏览器数据。
- 查看修改前后截图，覆盖 1280×800、1440×900、1920×1080 三种 PC 窗口；核对导航、职责、按钮、输入、内容层级、代码页、运行记录和交付结果。截图是本机视觉复查，不是客户可用性研究。
- 新增 [verify-roles.cjs](scripts/verify-roles.cjs) 六组组合检查；既有身份、多应用、旅程、阶段和交互脚本共 31 组通过。新检查覆盖真实页面行为，读取本地状态验证修订、业务模拟和历史；不通过改写状态跳过两角色流程。
- 本批证据目录为 `test-results/prototype-v2-role-review/`。`pc-final-2/result.json` 对应最终六组路线与截图；`pc-regression/` 中五个 `verify-*`/`verify` 子目录保存既有检查结果。旧批次目录和原未提交 TD15 证据不改动。

## 2 应用开发者完整路线

| 阶段 | 实际操作 | 核对结果 |
| --- | --- | --- |
| 创建 | 陈晓进入空应用列表，选择 MOA，填写员工福利助手及 i豆需求 | 无 i豆模板；名称和业务目标属于当前应用 |
| 方案 | Coding Agent 提出预设方案，查看差异并应用 | 仍为同一应用；连接待选择；明确非模型生成 |
| 工具与职责 | 查看公共工具、维护方和可修改范围；描述新增仓储库存 API | 新接口只记录需求，不再误改资格规则或余额映射，不新增可执行工具 |
| 局部开发 | 编辑本应用业务 Skill；选择企业连接，再改成本地 Mock | 业务 Skill 可保存；未接通企业环境时禁止运行，Mock 明确标识 |
| 调试与定位 | 查询余额，切为嵌套返回，查看失败 Trace，交给 Agent 修复映射后重跑 | 新运行成功；旧失败快照保持原内容 |
| 业务异常 | 发起兑换后拒绝；再模拟写后超时，按原交易核对 | 拒绝时零订单；未知结果核对后只有一笔模拟订单 |
| 交付 | 运行示例检查、固定候选、下载设计 JSON、预演企业交接 | JSON 标记 `simulation: true`、`runnable: false`；不伪装成 JAR |
| 中途返回 | 暂存未完成 Skill，切到平台后再返回；创建采购应用再切回 | 原编辑、应用、候选和历史保留；采购需求不误跑 i豆 |

最终截图：`pc-final-2/application-tools.png`、`pc-final-2/application-failed-trace.png`、`pc-final-2/application-delivery.png`。

## 3 模板开发者完整路线

| 阶段 | 实际操作 | 核对结果 |
| --- | --- | --- |
| 进入工程 | 切换林知远，查看 MOA 模板开发任务及导航 | 范式维护、公共能力、开发指导、发行构成一条任务路径 |
| 公共能力 | 查看工具/连接职责、扩展范围及相关工程入口 | 平台维护公共机制；企业系统方确认业务授权；未模拟任意 API 接通 |
| 开发指导 | 修改应用开发 Skill，并预览应用方将收到的内容 | 应用开发指导与平台任务自身指导分开；预览不改变角色 |
| 代码与检查 | 编辑代码时核对导航；故意删除平台指导的工程分层内容并检查 | 所属导航仍选中；检查失败，发行按钮不可用 |
| 修复与发行 | 恢复指导，重新检查；预览应用方创建体验；发行新模板 | 草稿与已发行版本分开；同一工程修订不能重复发行 |
| 历史与诊断 | 查看发行快照、工程活动、应用 Trace 与 Span | 历史只读；应用诊断不显示无关工程检查或发行待办 |
| 交接复用 | 切回陈晓，查看旧应用，再从新模板创建应用 | 旧应用保留原模板，新应用使用新版本；不静默升级 |

最终截图：`pc-final-2/template-overview.png`、`pc-final-2/platform-capabilities.png`、`pc-final-2/template-release.png`。

## 4 页面特性评审与修正

| 维度 | 发现的问题 | 本轮处理与判断依据 |
| --- | --- | --- |
| 导航 | 平台代码页没有选中项，代码维护与业务页面切换缺少位置反馈 | 代码页归属范式工程或开发 Skill，并有返回入口；PC 窗口核对当前项与所在工作对象一致 |
| 功能语义 | “新增仓储库存 API”被关键词匹配成资格校验建议 | 新工具/API 需求单独记录，不产生无关差异；修订不变的断言通过 |
| 职责理解 | 工具只有输入输出，看不出谁维护、哪里能改 | 工具详情展示公共归属、连接与应用可修改范围；业务 Skill 标明应用方维护；新接入说明按既有授权和机制影响划分 |
| 模板交接 | 只有机制与发行信息，缺少应用方实际会拿到什么 | 增加任务步骤、应用开发指导预览及草稿创建体验预览；与已发行只读说明区分 |
| 页面上下文 | 看应用运行时仍出现工程发行待办和检查按钮 | 诊断页面只保留运行定位及工程活动入口，不用工程修订充当运行版本 |
| 布局与易用性 | 长对话与建议会把助手输入区推到首屏下方 | PC 工作区与助手并列；指导、对话和建议独立滚动，输入与发送保持可见；未发送目标刷新恢复 |
| 阅读与美观 | 工具列表被拉成长块，辅助文字偏小，筛选表单未对齐 | 工具列表顶部对齐、提高关键说明字号与对比度；公共能力采用统一卡片；表单筛选对齐；按 PC 窗口分配代码与助手宽度；大屏内容顶部对齐，代码保存动作放在编辑器上方，长路径省略显示并提供完整路径提示 |
| 信息负担 | 责任与限制若全部铺开会增加首屏说明 | 主要对象就地说明维护者和可修改范围，次要分工折叠展示；不增加接入门户或授权配置步骤 |

整体仍沿用红、白、灰风格。红色用于主要动作和当前导航，蓝灰用于职责提示；成功、失败同时提供文字，不只依赖颜色。PC 保留工作区与助手并列，次要说明可展开阅读。上述是本轮设计判断，未用未经测量的评分或满意度替代证据。

最终 PC 截图：`pc-final-2/pc-application-1280.png`、`pc-final-2/pc-template-1440.png`、`pc-final-2/pc-diagnostics-1920.png` 等九张窗口截图，另保留工具、Trace、交付、模板工程、公共能力和发行页。以实际截图核对输入框、发送按钮、代码区、导航与筛选。

## 5 验证记录与过程问题

| 检查 | 结果与范围 |
| --- | --- |
| 新增完整路线 | 最终 6 组通过，包含新 API 误分类、两角色全流程、模板交接及 PC 布局 |
| 既有相关回归 | 身份 5、多应用 8、应用旅程 4、角色阶段 7、交互 7，共 31 组通过；原业务断言不修改 |
| 源文件与产物 | JavaScript 语法检查、单文件生成，以及生成内容与源码一致性检查 |
| 文档与交付 | 链接、术语与分期一致性、V2-AC 保持、DMO-07 按用户要求改为 PC 窗口范围，其余 DMO 保持、受影响 diff、原工作区证据保持检查 |

修改前的快速观察脚本发现库存 API 被误分类成资格校验，但最初的探测条件只排除了余额映射，不能作为通过依据；实际行为与截图保留在 `baseline.json` 和 `before-*`。正式用例改为断言“不生成任何无关方案且修订不变”，在旧单文件上失败，见 `red-corrected/failure.json`。

新增脚本第一次因弹窗打开后仍定位到背景的同名按钮而超时；首次修复版最后又因定位到手机上隐藏的桌面演示入口而超时。两次均修正选择器：优先当前弹窗，其余选择可见入口；业务断言没有放宽。失败保存在 `red/` 和 `green-1/`。`green-2/` 为中间通过记录；之后只精简诊断头部和对齐筛选，用户随后明确只需 PC，本轮撤回新增手机助手、手机路线入口与运行卡片，改为 PC 助手内部滚动布局，再执行完整路线和三种 PC 窗口检查，结果以 `pc-final-2/` 为准；中间截图仅保留过程证据。

## 6 仍保留的范围限制

1. 模板开发路线围绕现有 MOA 工程维护和发行；尚无多模板工程管理、任意模板导入或旧应用兼容升级。不能据此声称完整平台开发产品已实现。
2. 当前只执行预置福利 Mock。任意 Tool/API 开发、真实 OpenCode、真实 Skill 装载、OTel 后端、JAR 与企业 CI/CD 均未接入。真实接入和权限管理按后续技术方案讨论，第二、三阶段未启动。
3. 数据只在浏览器保存。身份切换没有认证与权限隔离，不代表独立团队协作；用户关闭或清理本地存储后的数据保护仍需真实后端。
4. 字体、布局和关键操作已做所列尺寸的截图检查；未完成跨浏览器矩阵、所有缩放比例、读屏器或真实用户任务耗时测试。手机不在本轮评审与新增功能范围。

本轮没有启动模型、Java、Docker 或新业务后端。复用已有本机静态预览服务，检查结束关闭本轮隔离浏览器。证据仅保留报告、有限截图和设计清单，不生成复制工程或大型构建目录；本地提交，不推送。
