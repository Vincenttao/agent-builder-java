## 4 推荐推进顺序

1. **先确认版本与验收收口（NEXT-01/02）。** 这是最低成本消除“我看到的页面为什么不一样”的办法。退出时用户知道打开哪个入口、哪些证据有效、哪些修改尚未发布。
2. **再完成一个页面体验切片（NEXT-03/04）。** 用“从MOA创建i豆应用，修改Skill并找到对应操作与连接”走通；只改受影响UI/API并验证PC，不重写框架或执行器。
3. **再增强设计与验证衔接（NEXT-05/06）。** 用商城/理财的一次真实运行关联编排节点、确认、回执和固定断言；Deep用材料生成及严格局部修改验收。业务Mock与真实企业系统分开标识。
4. **最后按实际需求选择扩展（NEXT-07～09）。** 不把企业治理、MCP、自动升级或生产发布作为本机Demo的前置。

沿用现有Node.js/Express、SQLite索引、Git、OpenCode、本机Java及Jaeger。当前差距不需要新前端框架、Docker编排、通用流程引擎或自建Trace存储。
