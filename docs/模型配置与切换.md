# 模型配置与切换

当前工作台通过 OpenAI 兼容接口访问模型。DeepSeek Flash 是默认测试基线，不再是唯一允许的模型名。编码助手与 Java 业务运行当前共用一组模型配置；本次没有新增模型管理页面或多协议适配层。

## 配置

在本机 `.env.local` 设置下列字段，文件权限须为 600，不提交到 Git：

```dotenv
MODEL_NAME=你的服务商实际模型ID
MODEL_BASE_URL=https://你的服务地址/兼容API前缀/v1
MODEL_API_KEY=在本机填写凭据
```

默认模型 `deepseek-flash`，默认地址 `https://api.deepseek.com`。地址填写完整 API 前缀，不含 `/chat/completions`；域名根地址会补 `/v1`，已有 `/v1` 或其他 API 前缀不再重复追加。不得包含 URL 用户名/密码、查询参数或片段。Anthropic 协议地址不能当作 OpenAI 兼容地址使用。

优先级：通用进程环境变量 → 旧进程环境变量 → 通用本机配置 → 旧本机配置 → 默认值。仍兼容 `DEEPSEEK_MODEL`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_API_KEY`，不需要迁移已有 Key。不要把 Key 写进应用定义、开发 Skill、代码、命令参数或交付包。

## 生效范围

- OpenCode：下一次新任务读取配置，实际请求中的模型 ID 与 provider 模型目录同步；不再限制只能用 deepseek-flash。
- Java：下一次新运行读取配置，路由与 Skill 使用所选模型。工作台同时传递通用字段和旧字段，保留已有 JAR 的默认启动兼容。
- 独立包：在目标环境设置同名变量后启动。新导出脚本兼容两组变量；Key 不随包导出。
- 已运行的 Java、已开始的 Coding 任务、已发行模板和旧导出不会自动变化。此前写死模型名的旧 JAR 需要升级到包含此修复的模板并重新构建，不能只改环境变量就声称已切换。

DeepSeek Flash 专用的 `thinking` 参数只在模型名为该默认值时发送，其他模型不会自动收到它。首期输出/上下文预算仍采用 Demo 的固定值，不提供服务商能力自动发现。

## 验证范围

`settings.test.ts` 验证字段与优先级；`opencode-model.test.ts` 使用本机协议桩验证 OpenCode 适配器实际发送的模型 ID、目录与 API 前缀；`ModelConfigurationTest` 使用真实 Core/OpenAI 客户端向本机 HTTP 服务发送请求，断言模型 ID 生效，非默认模型未带 DeepSeek 专用参数。这些不访问真实模型服务，也不证明某个新模型已通过工具调用、确认、A2A 或业务验收。

替换模型后，应重新验证实际工具调用与业务约束。既有 DeepSeek 业务证据仍只适用于其原模型、输入、配置和工程版本。
