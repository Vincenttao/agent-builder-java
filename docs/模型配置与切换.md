# 模型配置与切换

当前工作台通过 OpenAI 兼容接口访问模型。DeepSeek Flash 是默认测试基线，不再是唯一允许的模型名。MOA/DeepAgent 共用“应用设置→模型与运行环境”，工程选择本机配置档引用。默认档继续读取原环境变量；没有新增多协议适配层。

## 配置

在本机 `.env.local` 设置下列字段，文件权限须为 600，不提交到 Git：

```dotenv
MODEL_NAME=你的服务商实际模型ID
MODEL_BASE_URL=https://你的服务地址/兼容API前缀/v1
MODEL_API_KEY=在本机填写凭据
```

默认模型 `deepseek-flash`，默认地址 `https://api.deepseek.com`。地址填写完整 API 前缀，不含 `/chat/completions`；域名根地址会补 `/v1`，已有 `/v1` 或其他 API 前缀不再重复追加。不得包含 URL 用户名/密码、查询参数或片段。Anthropic 协议地址不能当作 OpenAI 兼容地址使用。

优先级：通用进程环境变量 → 旧进程环境变量 → 通用本机配置 → 旧本机配置 → 默认值。仍兼容 `DEEPSEEK_MODEL`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_API_KEY`，不需要迁移已有 Key。不要把 Key 写进应用定义、开发 Skill、代码、命令参数或交付包。

## 配置档与页面选择

可在权限为 600 的本机 `.env.local` 增加以下两行。JSON 必须单行，最多各 16 个条目；`keyEnv` 是凭据变量名，不能把实际 Key 填进目录：

```dotenv
MODEL_PROFILES_JSON=[{"id":"review","title":"复核模型","model":"deepseek-v4-pro","baseUrl":"https://api.deepseek.com","keyEnv":"MODEL_API_KEY"}]
WORKBENCH_ENVIRONMENTS_JSON=[{"id":"mock-local","title":"本机Mock连接","connections":{"idou":"http://127.0.0.1:8770","wealth":"http://127.0.0.1:8770"}}]
```

配置后刷新工作台页面，在应用设置中选择并点击“保存模型与环境选择”。这是本机提供的模型/环境目录，不是企业模型或权限管理系统。目录本身也可通过同名进程环境变量提供；进程环境优先。

工程只保存 `runtime-settings.json`，例如 `{"modelProfile":"review","environmentId":"mock-local"}`。环境目录中的连接覆盖项同时保存到 `application.json`；默认 `local` 保留已有连接，不自动启动 Mock。其他应用可以选择不同配置档。不存在的引用会在保存选择或执行入口报错，不静默换成默认模型。

页面显示已保存配置与待保存选择；工程有未保存文件时，须先处理草稿再独立保存模型选择。密钥从私有配置/环境注入，不进入 Git 工程、运行记录、页面或交付包。

## 生效范围

- OpenCode：下一次新任务读取配置，实际请求中的模型 ID 与 provider 模型目录同步；不再限制只能用 deepseek-flash。
- Java：新运行开始时解析引用并固定配置，构建期间修改私有目录也不改变本次启动；路由与 Skill 使用所选模型。工作台同时传递通用字段和旧字段，保留已有 JAR 的默认启动兼容。
- 独立包：包格式 v3 记录原运行实际模型/环境，启动默认值来自原运行；历史无记录时明确标为 not-recorded。目标环境可通过同名变量覆盖启动值。私有目录和 Key 不随包导出；旧格式包字节保持不变。
- 已运行的 Java、已开始的 Coding 任务、已发行模板和旧导出不会自动变化。此前写死模型名的旧 JAR 需要升级到包含此修复的模板并重新构建，不能只改环境变量就声称已切换。

DeepSeek Flash 专用的 `thinking` 参数只在模型名为该默认值时发送，其他模型不会自动收到它。首期输出/上下文预算仍采用 Demo 的固定值，不提供服务商能力自动发现。

## 验证范围

`settings.test.ts`、`execution-settings.test.ts` 验证字段优先级、私有目录和引用；`pc-execution-settings.test.ts` 验证双范式选择、旧运行不变、包内引用及三种 PC 宽度；`local-java.test.ts` 的本机进程夹具验证构建前捕获配置传给启动进程；`opencode-model.test.ts` 使用本机协议桩验证 OpenCode 适配器实际发送的模型 ID、目录与 API 前缀；`ModelConfigurationTest` 使用真实 Core/OpenAI 客户端向本机 HTTP 服务发送请求，断言模型 ID 生效，非默认模型未带 DeepSeek 专用参数。这些不访问真实模型服务，也不证明某个新模型已通过工具调用、确认、A2A 或业务验收。

替换模型后，应重新验证实际工具调用与业务约束。既有 DeepSeek 业务证据仍只适用于其原模型、输入、配置和工程版本。
