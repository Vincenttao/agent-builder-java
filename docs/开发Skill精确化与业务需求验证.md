# 开发Skill精确化与业务需求验证

日期：2026-10-25。本批承接[双范式端到端测试](端到端测试报告_双范式与Coding助手.md)，目标是验证普通用户仅描述业务目标时，开发指导是否足以支持真实OpenCode开发。不是扩大运行时能力，也不是完整PRD验收。

## 问题与修订

原DeepAgent应用Skill说明了范式约束，但缺少完整的配置关联示例、业务Skill格式、逐轮授权和交付自检。平台Skill与应用Skill的description相同，正文也基本相同。前批生成缺少YAML头与这些缺口有关；OpenCode自动缓存、运行时工具异常仍属于实现问题，不能归因于描述不准。

本批修改：

- DeepAgent应用Skill明确适用需求、读取对象、业务到文件的关联修改、自检与停止条件；详细格式和本机契约放在references/assembly-contract.md。
- DeepAgent平台Skill明确范式、工具、契约、指导和版本兼容责任，不再复述应用装配流程。
- MOA应用Skill补充从业务需求到工程修订、业务Skill文件头及静态核对；沿用原有详细本机契约。
- MOA平台Skill补充按变更层维护契约和应用指导，保留空模板与发行边界。

开发Skill指导OpenCode修改工程，业务Skill指导运行中的Agent处理业务。description服务于识别用途，正文与参考文件承载操作契约。工作台显式指定开发Skill，所以本批重点不是自动选择命中率。

## 判断边界

本批证据支持：精准开发Skill可以减少固定目录误写、配置格式猜测和工具接线描述缺失。它不能单独保证业务模型严格遵守生成后的业务Skill。尤其当前Deep仅开放整文件write_file，写后读回/完成信号不等价于“无关文本未改”；严格局部编辑还需独立内容差异验收，后续可评估受控文本替换工具，不在本批宣称已实现。

本批没有做多次随机重复、其他模型或更广业务样本，不能据一次配对给出统计成功率。平台维护仅验证了新版指导，未做旧/新平台对照；MOA属于迭代验证，不是严格配对。
