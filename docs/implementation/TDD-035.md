# TDD-035：Docker 日志保留与容量上限

日期：2026-10-22。状态：Docker 容器日志轮转已应用并核验；NF-04 其他分支仍未完成。

## 修改

- 在 Compose 中为 App、Runner、Mock 服务、迁移任务及 PostgreSQL 统一设置 `json-file` 日志驱动，单容器最多保留 3 个、每个最多 10 MiB 的日志文件，最大约 30 MiB／容器；超出后由 Docker 轮转并清理最旧文件。
- Postgres 业务 Run 事件仍保存在数据库，不受容器诊断日志轮转影响；当前不设置业务事件自动过期，避免删除仍需审阅的不可变执行证据。

## 验证

- `docker compose --env-file .env.local config --quiet` 通过。
- Compose 重建服务后逐容器读取 Docker `HostConfig.LogConfig`：App、迁移、Mock、Postgres、Runner 均为 `json-file`、`max-size=10m`、`max-file=3`。实测结果见 [日志保留配置证据](evidence/TD15-NF04-retention-config.json)。
- App `/health/ready` 返回 `ready`，所有常驻服务健康；Edge 项目导出／导入浏览器回归 1 项通过。

## 范围限制

此增量只落实容器标准输出／错误输出的容量上限和旧文件轮转，不配置 Postgres 业务事件 TTL 或清理任务。事件继续无 TTL 保留；如未来清理，需先实现按引用关系保护报告、Run、外部写入待核对证据和候选的归档／删除流程。NF-04 的轮次上限、超时终态、错误归类及整个 NF-04 仍须分别验证。
