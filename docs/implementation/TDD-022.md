# TDD-022：候选 RuntimeSpec 版本绑定

日期：2026-10-22。状态：实现与定向集成验证通过；不代表 TD-12B、完整 P0 或 TD-15 完成。

## 目标

给候选固定一份可追溯的有效 RuntimeSpec，并确保验收测试、业务请求、运行、发布和发布冒烟使用同一份规格及摘要。这是后续让开发 Agent 生成 Rail 配置并将其真正部署的必要基础。

## 实现

- Candidate 保存 `runtimeSpec`，`specDigest` 从该规格计算；新建候选先复制不可变快照规格。
- Candidate validation reference 将 `specDigest` 纳入需求、报告和发布绑定。
- TestDeployment 保存候选规格，准备阶段按该规格部署；入口校验、共享 Run 和外部动作授权沿用同一份规格。
- 发布门禁、发布实例、冒烟 Run 和发布后的业务入口沿用候选规格，并核对实际加载摘要。
- 升级前的候选、测试部署和验收报告若无候选规格字段，按原快照规格回退；不改写历史摘要。

## 限制与下一步

当前 CandidateService 创建的新候选仍从快照复制 RuntimeSpec；自动开发 Bundle 尚不能产出新的 Agent/Rail 规格。上述发布门禁测试验证候选规格传递契约，不表示生成型差异规格已经由工程任务实际产出。下一增量要让受限生成任务输出经 Schema 校验的 Rail 定义，由平台派生有效 RuntimeSpec，将定义及摘要纳入 Bundle，并用真实 SDK hook 和独立验收验证。之后仍需完成 TC 金融场景、项目导出恢复、运行中崩溃／孤儿进程、NF 性能基线和 P0 累积必测集。
