# TDD-056：Run 事件保留与当前目标恢复验收

日期：2026-10-22。状态：Run 事件 TTL、NF-05 工作区恢复及当前固定镜像上的 NF-01 场景证据已完成；P0-A 为 61/70 分支通过、9 未验证、0 失败，尚未通过。

## 目标

补上 NF-04 对业务 Run 事件保留期的验证，并刷新受当前固定 App／Runner 镜像绑定的恢复证据。容器日志轮转不等价于业务事件保留；因此业务事件必须有独立清理策略及可审计的截断标记。

## 实施

- 新增 `RunEventRetention`，默认保留 90 天，可通过 `RUN_EVENT_RETENTION_DAYS` 配置，允许范围为 1 至 3650 天；应用启动时清理一次，此后每 6 小时检查一次。
- 只清理终态 Run 的过期事件。活动 Run 的事件保持不变。
- 清理与 `run.event_history_pruned` 标记在同一事务中提交。标记记录删除水位、删除条数、截止时间和保留天数，供后续事件消费端识别历史不完整。
- 保留 Run 事件不可变约束。迁移 015 仅允许持有事务级本地开关的清理事务删除事件；其他 DELETE 仍由数据库触发器拒绝。
- 新增集成测试覆盖过期事件删除、活动 Run 保留、截断标记及普通 DELETE 拒绝。
- Docker 部署阶段因 pnpm deploy 在离线模式下缺少元数据／包缓存而失败。保留 frozen lockfile 安装，部署步骤改为允许从已配置 registry 读取元数据，并启用 `forceLegacyDeploy`，随后完整 Docker 镜像构建通过。
