# TDD-010：已发布 Agent 的业务入口

日期：2026-10-22。接通 `/agent-api` 和工作台内的模拟企业 App。此批验证覆盖已发布版本调用、请求恢复与身份绑定；金融业务、候选测试入口和完整阶段验收仍未完成。

## 实现

- 业务入口采用 PRD 约定的 `POST /agent-api/agents/{agentId}/messages`、请求查询、动作决策与取消路径。请求正文仅允许消息、客户端请求编号与可选会话编号。
- 工作台通过受管理会话、Origin 和 CSRF 保护的 `/api/demo-sessions` 签发模拟业务凭据，固定 Agent、环境和 U1001／U1002 身份。业务凭据与管理 Cookie 分离；正文不能覆盖身份或部署，跨身份、环境、Agent 的会话和请求均拒绝。凭据只在服务和页面内存中保存，服务重启后需重新签发。
- 请求先在 PostgreSQL 按 Agent、环境、身份和客户端请求编号去重，再为新会话解析发布指针。原请求与输入摘要、会话、不可变发布版本及预分配 Run ID 一起保存；发布切换、回滚、刷新和响应丢失不会重新选目标。
- 业务会话固定版本；同一会话有未结束请求时拒绝下一条。新会话使用现行发布记录，实际执行前检查目标就绪、制品、规格、快照和模型摘要。不就绪或不匹配则阻塞在原目标，不回退其他版本。
- 登记请求后由后台准入。Run 创建与请求转为已准入在同一事务完成；取消与准入锁定同一请求行。即使部署检查迟到，已取消请求也不能创建 Run。多个准入 worker 重复处理只会创建同一个 Run；网络调用位于数据库事务之外。
- 已准入请求共用 Run 的取消、动作参数摘要、确认期限和决策幂等规则。查询及决策先校验所属业务请求，不让业务身份读取管理端任意 Run。
- 模拟 App 在同一标签页保存请求编号、会话编号和待重试消息。刷新后重新选择身份可恢复原请求；发送失败保留原键重试，切换身份清除当前视图。页面仅将执行端确认的终态显示为完成／取消。

## 边界与后续

业务会话目前保证版本、环境、身份和请求顺序绑定；每条消息仍使用独立的 SDK 会话，尚未提供跨消息模型上下文或 SDK 检查点恢复。页面已要求每条消息包含完整问题，不能据此判完整多轮会话验收通过。
