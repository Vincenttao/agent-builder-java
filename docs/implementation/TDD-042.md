# TDD-042：Runner 重启后安全退役已退出的 JVM

日期：2026-10-22。状态：TDD 通过；待 Docker 故障场景复验。

## 问题

TDD-041 的 Runner 容器故障后，Run 与 Runner journal 正确进入 `interrupted`，Mock 外部写入没有重放。但候选 TestDeployment 长期处于 `stopping`：Runner 对 `interrupted` 部署执行 retire 时，因无法确认进程已停而返回 `STOP_UNCONFIRMED`。部署管理器没有保存子 JVM PID，因此即使进程实际已退出，也无法区别“已退出”与“可能仍在运行”。

## 测试先行与修复

- 新增真实 Java Bridge 适配测试：Runner 替代启动时，旧部署记录仍显示 `ready`，但此前由 Runner 管理的 JVM 已经退出。新 Runner 将其标记为 `interrupted`；退役操作检查持久化 PID，确认该 PID 不存在后才把部署置为 `stopped`，并永久拒绝使用已退役 ID 再次启动。
- 新增反向测试：如果旧 PID 仍存活，部署保持 `interrupted` 且 retire 返回 `STOP_UNCONFIRMED`，不谎报停止。
- Runner 的 DeploymentRecord 现在持久化 JVM `processId`。对旧记录中没有 PID、PID 仍存活或进程检查无法确认的情况，仍保持拒绝停止。PID 可能被复用时会保守地保持隔离，不会误报成功。

## 验证
