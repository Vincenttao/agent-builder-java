# TDD-007：独立验收基线与项目验证报告

日期：2026-10-22。已部署到本地 Docker 的 8080 入口。完成设备只读模板的基线审阅、真实执行、逐项断言、证据保存和报告恢复；TD-06 的发布／回滚／导出尚未完成。

## 实现与边界

- 基线绑定需求修订，可用于同一需求的多个实现快照。确认请求核对用户审阅的内容摘要；数据库拒绝修改或删除已确认基线。需求来源和 BR／TC 映射保留。
- 设备只读模板含正常查询、缺设备编号、工具超时三个必测场景。工单模板另含批准、拒绝、过期、参数变化、写后超时。只读基线不能用于带写工具的快照。
- 平台持久化验收任务并分配稳定 Run ID。执行器走正常 Run／审批服务、真实 Java DeepAgent、工具代理和 Mock HTTP 接口；各场景使用独立数据实例和固定故障配置。普通浏览器请求不能传入故障配置、伪造判定或替换用例集。
- 报告绑定基线、快照、Java 制品、模型配置、测试集、Mock 实现摘要和兼容键。Runner 将模型配置写入记录并与 JVM manifest 核对；执行期间依赖版本改变会阻塞。
- 断言同时检查输出契约、实际工具调用及业务状态。模型替身即使全部断言通过，也只能得到“未验证”；未知规则、空测试集、缺证据或未接通场景不能成为通过结果。
- 证据与报告不可变，读取时重新检查摘要；JSON 持久化前统一序列化，避免 PostgreSQL 时间戳对象导致摘要变化。旧执行失败保留，新验证生成独立记录。
- 验收 worker 使用租约和递增令牌，过期 worker 不能覆盖新 worker 保存的结果。取消待执行任务时逐一核对预分配 Run。运行中取消和租约交错时的外部执行准入仍需进一步验证与加固。
- 只读 HTTP 超时、传输或响应契约错误以明确的失败结果交回模型，同时保留 tool_error 事件。写工具继续保留失败／未知状态及原键核对，不自动重写。
