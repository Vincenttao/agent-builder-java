# TDD-071：打通余额查询的固定 HTTP Tool 代理

日期：2026-10-23。状态：代理层与真实 Mock 集成通过；金融组件生成和业务 Agent 验收仍未完成。

## 问题

`wealth-balance-java@1` 已登记为受限生成 Profile，但仍因生成模板未实现而安全拒绝。金融 Mock 已提供余额查询，Server 的 HTTP Tool 代理却没有余额操作入口，导致即使后续生成正确的适配器，也不能经过固定 Run 上下文调用该接口。

## TDD 实施

先新增 Server 代理测试，要求固定的 `getAccountBalance` 操作接受 `accountId`，只在快照绑定该操作时执行，并把 Run、环境和 actor 上下文传给调用端。未实现时测试以 404 失败。随后增加固定路径 `/internal/tool-proxy/operations/getAccountBalance`，请求体只接受必填 `accountId`；身份通过现有代理令牌和 Session ID 解析，未绑定操作返回 403，额外字段由 JSON Schema 拒绝。该路径不接受调用方提供 endpoint、actor 或其他操作名。

同时补入真实 HTTP 集成验证：通过 `HttpMock` 请求 Mock 服务的余额和产品列表，确认余额值与种子数据一致、Mock 审计记录包含真实 Run 与 actor，并拒绝未绑定的余额操作。集成测试首次被 Vitest 的 15 秒初始化钩子超时；实测独立 schema 初始化和该文件的真实数据库测试需要约 74 秒，因此将 integration 项目的测试／钩子上限设为 90 秒后整套通过。
