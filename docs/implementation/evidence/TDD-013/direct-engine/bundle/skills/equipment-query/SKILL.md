# 设备查询 Skill

## 目的

回答用户关于某台模拟设备当前状态的问题，只使用 `get_equipment` 工具返回的事实，输出 `equipment-report@1` 结构的状态与来源。本 Skill 是业务指令加 Tool 适配说明，不执行任何外部脚本。

## 何时使用

- 用户询问某台设备的状态、温度或数据来源。
- 用户要求基于设备事实给出建议（建议必须建立在工具返回的事实之上）。

## 工具

- 工具名：`get_equipment`
- 类型：只读查询，不产生写入，不改变设备状态。
- 传输层负责 HTTP、认证引用与超时；模型只提供 `equipmentId`，不得提供凭据、身份（如 `actorId`）或服务地址（如 `endpoint`）。

## 输入

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `equipmentId` | string | 是 | 设备编号，必须非空，例如 `PUMP-001`。 |

只接受这一个字段。任何额外字段（包括 `actorId`、`endpoint`）都会被工具以 `TOOL_INPUT_CONTRACT_INVALID` 拒绝。

## 调用步骤

1. 从用户消息中解析设备编号。若存在明确的设备编号，将其作为 `equipmentId`。
2. 若缺少 `equipmentId` 或其为空白，**先向用户追问设备编号**，不要调用工具，也不要猜测编号。
3. 仅以 `equipmentId` 调用 `get_equipment`；不要附加身份、凭据或端点参数。
4. 读取工具返回的四个原始字段，按 `equipment-report@1` 组织回答。
5. 可基于 `status` 与 `temperatureCelsius` 给出建议，但必须注明建议依据的是工具返回的事实。

## 响应字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `equipmentId` | string | 设备编号，应与查询输入一致。 |
| `status` | string | 设备状态，例如 `normal`、`warning`。 |
| `temperatureCelsius` | Integer 或 Long | 摄氏温度；`0` 与负数均为合法值，必须原样保留，不得取绝对值或四舍五入。 |
| `source` | string | 事实来源标识，例如 `seed-equipment-001@1`；回答中应标注来源。 |

## 错误与不编造规则

- 输入不合法（缺少设备编号、空白、非字符串、含额外字段）时工具报 `TOOL_INPUT_CONTRACT_INVALID`：向用户追问或说明只能查询单个设备编号，不调用工具。
- 响应不合法（缺少字段、类型错误、字符串温度等）时工具报 `TOOL_RESPONSE_CONTRACT_INVALID`：明确告知用户本次查询未能取得有效设备事实，不输出任何推测的状态、温度或来源。
- 工具超时或传输失败：如实说明读取失败（例如“读取设备状态超时”），可以建议稍后重试，但**不得**编造状态、温度、来源或缓存中的旧值。
- 任何失败情况下都不要伪造 `source`，不要把默认值（如 0℃、`normal`）当作真实事实返回。
- 失败时保留错误证据（错误类型或消息），以便排查；不要在失败后自动重试写入类操作。
