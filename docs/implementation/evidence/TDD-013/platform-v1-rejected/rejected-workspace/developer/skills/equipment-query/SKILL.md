# 设备状态查询（equipment-query）

## 适用场景

用户询问某台设备当前状态、温度或数据来源时使用。本 Skill 只做只读查询，不执行写入、控制、脚本或网络请求。

## 调用步骤

1. 从用户消息中提取设备编号，作为 `equipmentId`。
2. 只有拿到非空 `equipmentId` 后才调用工具 `get_equipment`。
3. 调用时只传一个输入字段：

   ```json
   { "equipmentId": "PUMP-001" }
   ```

4. 读取工具返回的四个字段，用其中的原始值回答用户。

## 输入

- `equipmentId`（必填，字符串，非空）：设备编号，例如 `PUMP-001`。
- 不要传入 `actorId`、`endpoint`、超时、凭据或其他字段。身份、认证、端点和超时由已绑定的 transport 负责。

## 输出字段

- `equipmentId`：本次查询的设备编号。
- `status`：设备状态原文，例如 `warning`。
- `temperatureCelsius`：设备温度（摄氏度），整数；可能为 0 或负数，必须原样保留。
- `source`：事实来源标识，例如 `seed-equipment-001@1`。

## 缺失参数

用户没有提供设备编号，或编号为空/仅空白时，不要调用 `get_equipment`。直接用一句话追问设备编号，例如：“请提供要查询的设备编号（例如 PUMP-001）。”

## 错误与不编造规则

- 工具调用失败（超时、网络错误、权限错误等）时，明确告知用户本次查询失败，并说明无法取得设备状态。
- 工具返回内容缺失、类型不符或不符合报告契约时，同样告知查询失败。
- 不得猜测、补全或编造 `status`、`temperatureCelsius`、`source` 或设备编号。
- 不得把字符串数字当作温度，也不得因为异常而返回“正常”等默认状态。
- 工具失败时不自动反复重试；如实报告失败即可。
