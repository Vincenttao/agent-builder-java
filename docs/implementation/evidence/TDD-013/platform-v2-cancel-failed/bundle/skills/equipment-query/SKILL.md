# 设备查询（equipment-query）

## 适用场景

当用户需要查询某台模拟设备的运行状态、温度或来源，并希望得到一份设备状态报告时使用本 Skill。查询必须通过已绑定的 `get_equipment` 工具取得事实，不执行任何外部脚本。

## 输入

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `equipmentId` | string | 是 | 设备编号，必须为非空字符串，例如 `PUMP-001`。前后空白视为未提供有效编号。 |

约束：

- 只允许 `equipmentId` 一个业务输入字段。
- 不要接受或传递 `actorId`、`endpoint`、凭据、令牌等模型侧参数。身份、认证与端点由运行时绑定的 transport 负责。
- 若用户未提供设备编号，或编号为空/纯空白，先向用户追问设备编号，**不要调用工具**。

## 调用步骤

1. 从用户消息中提取设备编号，检查其是否为非空字符串。
2. 编号缺失或无效时，直接追问用户，例如：“请提供需要查询的设备编号。”
3. 编号有效时，调用 `get_equipment`，参数仅为一个对象：
   ```json
   { "equipmentId": "PUMP-001" }
   ```
4. 保留运行时传入的可信 kwargs，不要在模型参数中自行构造身份、端点或凭证。
5. 读取工具返回的四个字段，并据此撰写设备状态报告；报告中的事实必须与工具返回值一致。

## 响应字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `equipmentId` | string | 被查询的设备编号。 |
| `status` | string | 设备状态，例如 `normal`、`warning`。 |
| `temperatureCelsius` | integer | 设备温度（摄氏度），可能为负数或零，必须原样保留。 |
| `source` | string | 事实来源标识，例如 `seed-equipment-001@1`。 |

工具只返回以上四个字段。报告中不要补充工具未返回的状态、温度、来源或其他字段。

## 报告要求

- 明确列出设备编号、状态、温度（摄氏度）和来源。
- 数值必须与工具返回完全一致，负数与零不得改写。
- 可以给出基于事实的建议，但必须与返回状态相符，不得虚构未提供的遥测数据。

## 错误与不编造处理

- `TOOL_INPUT_CONTRACT_INVALID`：说明输入不符合要求（只接受非空 `equipmentId`），请用户补充或更正设备编号。不要重试猜测参数，也不要调用其他工具替代。
- `TOOL_RESPONSE_CONTRACT_INVALID`：告知用户当前无法取得有效的设备数据。不要猜测、补齐或编造缺失字段。
- 传输异常或超时：明确报告本次查询失败。不要编造设备状态、温度或来源，不要声称已读取未实际返回的数据。
- 任何失败场景下都不得写入或修改设备状态；本 Skill 仅执行只读查询。
