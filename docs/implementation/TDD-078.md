# TDD-078：AC-30 Mock 场景种子与实例隔离

## 目标

按 TD-15 P0-B AC-30，在当前 NF-01 Docker Mock 服务验证同一种子创建多个环境后的初始状态一致、实例数据隔离、运行期间重置保护和重置后的历史保留。

## 实现

新增 `scripts/verify-td15-ac30-mock-isolation-live.mjs`，直接在当前 Mock 容器内调用受认证的控制 API 与业务 API。测试为每次运行创建独立环境 ID，并记录 App／Runner／Mock 镜像 ID、验收制品摘要、兼容键、环境 ID 和外部状态观察；不输出 Mock 凭据。将该脚本登记到验收清单，并在 `scripts/assemble-td15-acceptance-evidence.mjs` 校验当前镜像和候选绑定后生成五项 AC-30 分支结果。

该回归验证的是 Docker Mock 环境 API 和状态管理行为。它没有调用业务 Agent，也不替代 Agent 在两个测试部署中运行的端到端验证。

## 结果

- 同 seed、同 clock 创建的两个实例初始状态相同。
- 对实例 A 的模拟申购将余额从 1,000,000 分变为 990,000；实例 B 仍为 1,000,000 分。
- 活动运行期间重置被拒绝，错误码为 `ENVIRONMENT_IN_USE`。
- 写操作在服务端提交后客户端超时；仍有活动运行预留时，按最新 revision 重置仍被拒绝；外部状态确认余额已变更。
- 释放运行后重置恢复种子状态，先前的业务调用记录仍可读取。
- AC-30 五个分支及 NF-06“独立环境”分支在 P0-B 和 P0-C 均通过。最终报告：`test-results/acceptance/P0-A-1792744901510.json`、`P0-B-1792744901859.json`、`P0-C-1792744902264.json`。
- 累积门禁：P0-A 70/70；P0-B 96/170（74 项未验证）；P0-C 101/235（134 项未验证）。验收制品摘要为 `99785dfe3233b68650fa62789f15d8c05ea1364075e9279b343a7087aa020f35`，App／Runner 镜像与当前 NF-01 Docker 目标一致。
