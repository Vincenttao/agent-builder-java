# TDD-054：远程 MCP Tool 受控装配与协议适配

## 目标

为 FR-007 固定 MCP 首版远程传输和 Java SDK，并用真实协议交互验证工具发现、参数转发和结果适配；Mock 环境通过同一业务 Repository 提供 MCP 设备查询端点，确保 MCP 与 HTTP 共享数据及调用记录。

## TDD 实施

- 先添加 `RegisteredMcpToolTest`，验证 MCP `initialize`、`tools/list`、`tools/call` 顺序、登记工具参数、连接凭据只在认证头中传递，以及工具输入不能覆盖 endpoint。缺少适配器时测试按预期编译失败。
- 新增 `RegisteredMcpTool`，采用上游传递的 MCP Java SDK 1.1.1 Streamable HTTP 客户端。适配器发现登记工具，校验远端 `_meta.version`、输入 Schema 和结果字段；不支持版本、认证失败、未登记工具、版本不符和错误结果分类处理。
- 扩展 `RuntimeSpec` 和部署契约，MCP Tool 固定绑定 `protocol=mcp`、`enterprise-mock-mcp@1`、远端工具名和版本。装配界面可将它与 HTTP Tool 同时加入快照；未绑定版本或连接的 MCP 配置会被拒绝。
- 运行时 MCP 客户端把当前 Run 会话 ID 放在受控请求头。平台 Tool Proxy 据此解析快照允许的操作和真实环境／主体上下文，再向 Mock MCP 转发；连接凭据不进入模型参数。
- 在 Mock Services 增加无状态 Streamable HTTP `/mcp` 端点，只发布设备只读能力；调用经既有 `MockRepository.invoke`，与 HTTP 查询共用环境和调用记录。
- HTTP 与 MCP 运行事件都记录协议、连接引用、工具版本、参数／结果摘要、耗时和 Run ID；MCP 额外记录服务端名称／版本。原始业务输入输出仍以 Mock 外部调用记录核验。
- 增加装配、Runner 契约、代理上下文、Mock 协议端点及 Web 选择测试。
- 真实 Docker 联调暴露 MCP SDK 的两个默认值与平台不兼容：默认 endpoint `/mcp` 会丢失反向代理前缀，默认协议优先级会协商 Mock 未实现的 2025-11-25。显式设置完整 endpoint path，并将支持协议限制为 Mock 实现的 2025-06-18、2025-03-26；新增带 `/internal/tool-proxy/mcp` 前缀的 Java 协议测试。
- Streamable HTTP MCP 服务端不提供服务端推送 GET 流时，代理对 GET 明确返回 405 `Allow: POST`，避免返回无关的应用 404。
