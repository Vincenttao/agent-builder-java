# TDD-089：放宽受限开发流程的 OpenCode API 超时

日期：2026-10-24。范围：修复 Tester／Developer 生成流程与 OpenCode HTTP API 交互时固定 15 秒超时的问题；不改 App、Runner 业务运行时或验收规则。

## 问题证据

- AC-32 余额发布验证在 NF-01 目标上启动后失败，Tester 写入验收方案但没有生成回复，任务以 `ENGINEERING_EXECUTION_FAILED` 结束。
- 使用同一 App／Runner 基础镜像的独立 AC-32 栈复现：任务写入 OpenCode 用户消息后没有 Assistant 回复，随后以相同诊断结束。独立栈内存占用约 288 MiB，避免了 NF-01 Runner 既有部署带来的内存压力。
- OpenCode 会话数据库没有 Assistant 错误消息，当前证据无法确认具体失败 HTTP 请求。代码审查发现 `OpenCodeEngine.api()` 对所有 OpenCode API 请求固定设置 15 秒超时；这可能过早中止较慢的提示提交或会话轮询，是待现场复测的故障假设，不是已证明的根因。
- DeepSeek API 的独立连通性探测返回 HTTP 200 和有效 JSON；这仅证明探测时凭据和模型端点可用，不证明 OpenCode 生成流程通过。

## TDD 与实现

- 先新增两个超时行为单测，红测确认可配置值和默认值都被固定的 15000 毫秒覆盖。
- `EngineOptions` 新增 `apiTimeoutMs`；`OpenCodeEngine.api()` 改为使用此配置，默认 60000 毫秒。开发任务仍受既有 900 秒总预算限制。
- 定向单测 2 项通过；全仓 TypeScript 类型检查通过；`git diff --check` 通过。

## 未完成验证

- 独立 AC-32 栈已使用 `--no-build` 启动并保持 App、Runner、Mock、Postgres 健康；但重新生成任务仍在 API 调用阶段失败，未形成候选或发布版本。
- 为验证超时修复而单独重建 Runner 镜像时，Docker Desktop BuildKit 在 Runtime Bridge Maven 步骤停滞；Docker Desktop API 随后持续返回 500，连容器状态查询也不可用。已中止该次构建，没有重建 App／Runner，也没有修改 NF-01 容器。
- 因修复尚未进入运行镜像，不能声称解决了 AC-32。模拟企业 App → 已发布金融 Agent → Mock 的余额调用、理财产品查询和版本绑定仍未验证；AC-32 三个门禁分支保持未验证。

本记录只说明本地代码和单元测试的结果。待 Docker Desktop API 恢复后，应在独立栈构建并部署 Runner 一次，再复跑金融生成；如果任务通过，继续发布固定候选并从模拟 App 查询余额。理财产品查询还需要单独的生成与运行能力，不可复用余额结果代替。
