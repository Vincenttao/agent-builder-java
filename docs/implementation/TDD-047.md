# TDD-047：双身份交错运行与生成 Rail 计数隔离

日期：2026-10-22。状态：AC-17 和 NF-01 的双会话分支在隔离 Docker 上通过受管门禁；其余 TD-15 必测仍未完成。

## 场景与结果

新增 `scripts/verify-td15-nf01-two-sessions.mjs`。它创建设备查询需求和确认基线，使用真实 Tester／Developer 双角色生成受限 Rail，构建 Candidate 并部署到 TestDeployment。Rail 要求每个 Run 最多三次工具调用；U1001、U1002 交错运行，各自继续使用自己的 conversationId。

第一次尝试用“最多调用工具一次”的措辞，结果任务虽成功构建，但候选没有 Rail。原因是当前 GenerationProfile 仅识别固定格式“每次运行最多 N 次工具调用”，而空 Rail 对没有命中该格式的目标是合法产物。测试改用已支持的规范句式，且构建后明确断言 Rail 参数和 Candidate RuntimeSpec 均为上限 3，避免将空 Rail 当作成功结果。

最终证据 [双会话运行报告](evidence/TD15-NF01-two-sessions.json) 记录四个成功 Run：两个身份各两个请求、各自 conversationId 保持稳定、每个 Run 对对应设备恰好执行三次 `equipment-status`；将 U1001 的 conversationId 用于 U1002 请求时服务返回 404。TestDeployment 已停止，目标镜像身份与既定平台 target 一致。

## 门禁

AC-17 `interleaved-sessions` 和 NF-01 `two-sessions` 均接入统一 target、manifest 摘要和受管执行证据。最新 P0-A 报告 `test-results/acceptance/P0-A-1792665812282.json` 显示 7/70 分支通过、63 个未验证、0 个失败。此场景只覆盖已生成的工具调用上限 Rail 与两种测试身份，不代表所有 Rail 状态、刷新重连、生产身份或完整 NFR-03。
