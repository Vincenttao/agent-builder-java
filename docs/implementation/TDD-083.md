# TDD-083：修复 GitHub Actions 首轮失败

日期：2026-10-24。范围：manifest 摘要同步与 Java Adapter CI 的首次上游检出。

## 根因

GitHub Actions 运行 `2d4b740e3d799810ea7fa29f32187d8e6aae0a10` 时，两个 job 各有一项首要失败：

- `deterministic` 的 `acceptance-manifest.test.ts` 比较 PRD／验收基线摘要时失败。需求文档和验收规则已经更新，但 `tests/acceptance/manifest.json` 仍保存旧 `baselineDigest`（`b262943f…`，实际应为 `8dabf65d…`）。
- `java-adapter` 在 `scripts/bootstrap-java.ps1` 第 14 行失败。CI 对 `git clone --no-checkout` 创建的新仓库立即执行工作区干净检查；此时索引已有跟踪文件而工作区尚未检出，Git 将它们报告为删除，脚本误报上游源码被本地修改。后续 Adapter 测试因此跳过，Artifact 上传无文件是连带告警，不是根因。

## 修复

- 通过 `scripts/generate-acceptance-manifest.mjs` 重新生成 manifest 摘要，保留 88 项及其原用例映射。
- 新克隆先 fetch 并检出锁定提交，再检查工作区干净；已有缓存仍在切换提交前检查，防止覆盖本地修改；检出后再次检查。
- Java Adapter 测试证据缺失时将 Artifact 上传改为 warning，避免掩盖真正失败步骤。

## 验证

- `acceptance-manifest.test.ts`：1 项通过。
- 完整单元／契约测试：35 个文件、130 项通过；类型检查通过。
- CI 同款 `scripts/bootstrap-java.ps1`：Core、Runtime 构建成功；Bridge 23 项测试全部通过。
- 一次本地完整测试曾与类型检查、Adapter 测试和 Maven 同时运行，导致超时；停止并发负载后完整单元／契约测试复跑通过。Adapter 本地复跑未完成，不据此判断；由 GitHub CI 验证该步骤。
