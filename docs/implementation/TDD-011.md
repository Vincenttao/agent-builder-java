# TDD-011：运行接管、迟到命令与依赖恢复

日期：2026-10-22。已部署到本地 Docker 8080 入口，完成真实模型升级及重启探测。完整 TD-15／PRD 尚未验收。

## 实现

- Run worker 每次领取递增接管编号，并使用 120 秒租约、20 秒心跳。续租必须仍持有有效租约，不能复活已过期的租约。领取、续租和释放均匹配所属 worker 与编号。
- Run 状态、执行事件、终态和 worker 触发的审批登记／过期处理，在短事务中核对当前租约。旧 worker 的迟到结果和失败不能修改新 owner 的记录；终态另受数据库不可变触发器保护。
- Runner 的启动、续接和取消 HTTP 命令必须携带已登记的接管编号。Runner 持久记录最大编号，在同一执行编号内串行受理命令；旧编号和缺少编号的 HTTP 请求拒绝。尚未创建执行时也能登记取消，后续启动或续接不能绕过取消；重启读取同一记录。
- 取消共享执行仍只影响目标 Run。独占部署结束时记录退役编号，防止迟到部署请求重新创建 JVM。取消完成前必须由执行端确认；不能把网络超时当作停止成功。
- Mock 的释放记录可先于环境创建落库；相同环境／Run 的迟到预留不能重新占用环境。已有账本和调用证据保留。
- 连续依赖失败达到重试阈值后进入核对状态，继续观察同一 executionId，不伪造停止或新建执行。依赖恢复且没有待核对动作时，恢复正常运行／审批处理；仍不重放原任务。
- 发布业务入口在准入时检查实际 Mock 实现摘要。服务发生变化时保留原请求与目标并阻塞，要求重新验收发布；重复旧请求仍返回原请求记录。

公开业务请求不能提供接管编号。Runner 对外 HTTP 契约始终要求编号；少量直接调用内部 Journal 的底层探针保留无 worker 模式，但一旦执行登记过接管编号，未带编号的内部命令也被拒绝。

## 验证与证据

已保留以下行为红灯及修复后结果：旧 worker 在接管后继续部署、迟到结果覆盖终态、迟到异常追加错误证据、Runner 缺少持久命令保护、取消前未建环境导致迟到预留、发布后业务服务变化未被检查，以及依赖恢复后仍无法继续运行。

PostgreSQL 测试包含独立 worker 的接管、心跳续租、终态不可变、20 次依赖失败后的运行和审批恢复。原生测试让真实 JVM 先准备就绪，再延迟启动 HTTP 请求；新 worker 接管并完成取消，随后放行旧请求，核对原 Run 不变、JVM 停止、模型及业务接口零调用、Mock 无重新预留。

一次原生回归发现 HTTP 适配器将 Runner 的明确拒绝码折叠为通用错误。已通过有限的已知错误码集合保留控制错误，其他错误仍不透传上游详情；使用专用假哨兵验证错误脱敏。对应原生失败记录保留。另一次并行运行的错误码测试在实现更新后才加载代码，因此不算有效红灯，只保留为辅助执行记录。
