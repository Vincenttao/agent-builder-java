# TDD-049：无模型保存、移动端草稿恢复与固定目标复验

## 目标

验证无模型连接时仍可保存需求，但在创建固定快照后不能启动业务 Run；修复 390px 视口下项目选择器导致的横向溢出。由于 App 镜像变化，所有依赖固定 App／Runner 镜像的已通过运行证据都在新镜像上重跑。

## 实施

- 草稿列表的项目选择器添加容器宽度约束，避免长项目名将页面撑宽。
- Playwright 回归改用当前项目下拉框恢复草稿；确认 `model=not_configured`、草稿保存／刷新恢复／修订更新、固定快照后的 Run 被 `ENVIRONMENT_BLOCKED` 拒绝，以及 390px 页面无横向溢出。
- 新增 `scripts/verify-td15-ac01-no-model.mjs`，在关闭模型凭据的隔离 App／Runner 上核对环境阻塞码、保存与持久化，并在有效快照上尝试启动 Run。
- 修复 NF-05 验证器的 Compose 环境优先级：临时端口、来源和随机凭据显式覆盖当前 Shell 从本地环境文件继承的变量，确保新工作区真正使用独立配置。
- 修正 NF-01 双会话验收脚本。原场景同时要求模型执行三次设备查询，而内部 `skill_tool` 也计入三次总工具调用，导致第四次请求按 Rail 规则被阻止。新场景验证每个身份／Run 的 Rail 计数独立从 1 开始、不超过 3 且 Run 成功。
- NF-01 重启事件检查按持久事件记录数量不减、事件序号唯一和快照绑定稳定判定；全局序列会因其他 Run 产生合法跳号，因此不要求单个 Run 的序号连续。
