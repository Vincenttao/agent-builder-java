# TDD-009：真实发布准备、只读冒烟与回滚

日期：2026-10-22。已部署到本地 Docker 的 8080 入口。完成发布管理链路及共享 Run 适配；面向模拟 App 的 agent-api 业务调用入口尚未接通，不能据此判完整 AC-15／16／39 或整个平台通过。

## 实现

- 发布门禁读取已确认基线、真实模型验收报告及证据，重新检查快照、制品、模型、Mock 与兼容键。模拟执行、缺项和绑定变化不能发布。
- 实际发布执行器准备独立 JVM，核对 Runner 已验证的制品、规格和模型摘要；使用基线中的正常读取场景执行冒烟。平台根据原始调用、输出契约、事实及零写入要求判定，全部满足后才原子切换发布指针。
- 内部 createShared 将 Run 固定到不可变发布版本或当前发布冒烟目标。公开调试请求不能提交内部参数；冒烟准入在同一事务内核对发布租约、递增令牌和预分配 Run ID。
- 完成／取消共享 Run 不停止整个 JVM；共享部署事件必须具有匹配的会话标识。冒烟 Run 仅能通过代理读取设备，不能获得写入权限。
- 发布失败先在有效租约下提交终态，再取消未结束的冒烟 Run 并清理部署。Runner 持久记录退役编号，阻止迟到的启动请求在清理完成后创建 JVM；重启后继续有效。活动执行存在时不能停止／退役整个部署。
- 发布轮询按最近领取时间调度，等待模型的任务不会持续占用最早位置而饿死其他 Agent 的发布。
- 管理页面支持审阅报告后发布、异步进度、失败原因、历史版本、只读冒烟证据及回滚。回滚新建部署和版本记录，保留演示环境、业务账本和历史 Run。
- 管理 API：POST/GET /api/drafts/:id/releases、GET /api/releases/:id。发布写请求继续使用本地会话、Origin 与 CSRF 校验；请求不能提供通过结论。

原生发布测试使用真实 JVM、Runner HTTP、平台 Run、工具代理及 PostgreSQL Mock。通过测试进程内临时限制可执行路径制造实际 JVM 启动失败；另由固定模型返回错误温度制造冒烟失败。两种情况保留原指针，随后旧版本仍能完成真实查询。回滚前通过 Mock HTTP 创建一条模拟工单，回滚后账本内容完全相同。该原生测试的模型和完整验收准入明确使用测试端口；真实模型准入由浏览器流程另行证明。

重启探测最初错误地只期待 interrupted，实际正常重启会调用 Runner 优雅关闭并保存 stopped。已修正为区分正常停止与异常中断，保留失败记录。恢复验证没有直接把旧实例标为 Ready，而是显式重新发布同一验证目标并完成新的只读冒烟。运行中崩溃、孤儿进程及自动恢复不在此项证据范围内。

类型检查、镜像构建和四服务健康检查通过。390px 页面无横向溢出，发布面板截图已目视检查。本轮未修改 Java Bridge 源码，沿用 TDD-008 的 10 项 JUnit 证据，不声称重新执行了该部分测试。
