# TDD-082：固定候选的一次构建、多项验收

日期：2026-10-24。状态：测试与门禁要求已同步至 PRD、测试基线和 TDD 计划；TD-15 运行保持暂停。

## 调整内容

- 同一源码、依赖锁文件和镜像构建输入只构建一次 App／Runner 候选；该候选可承载一个阶段验收批次中的多项 AC、TC、NF 用例。
- 每项用例各自保留结果、环境实例 ID 和证据，但绑定相同候选及 App／Runner 镜像摘要；用例可使用不同 Compose 项目或环境配置。
- 只读用例可复用服务；业务写入、发布切换和故障配置使用隔离部署／数据空间或经验证的重置；Runner 停止、重启、崩溃场景隔离执行或排在批次末尾。
- 测试或环境失败不自动触发镜像重建。源码、依赖或镜像构建配置修复后创建新候选；该候选须在一次构建后完成阶段完整累积必测集合。不同镜像摘要的旧通过结果不计入新候选门禁，除非未来建立经过验证的影响分析和证据复用机制；原失败证据保留。
- 单纯镜像存储迁移且摘要与运行配置不变时，迁移后做健康检查并沿用功能验收证据。

## 保留的门禁

PRD 中 P0-A/B/C 累积必测集合、真实候选运行、外部业务状态核对、隔离／幂等／审批／故障恢复断言、NF-01～NF-06 和构建产物完整性均未删减。变更仅减少每个用例或每次服务启动重复构建镜像。
