# TDD-020：四流程页签与单版本工作区

日期：2026-10-22。状态：前端生产构建完成，本地 Docker 页面已更新；本批未运行测试。

## 已实现

- 工作区改为“需求录入 → 环境与装配 → 开发与测试 → 发布与验证”四个页签。
- 左侧项目区用选择框切换项目，替代纵向展开全部项目卡片。
- 项目工作区只显示一个当前测试版本；版本选择器切换历史快照，验收与发布内容绑定所选快照。
- 环境诊断移入“环境与装配”；保留组件目录、Agent 指令、验收基线和固定版本操作。
- “开发与测试”集中展示当前快照、运行调试、开发任务、固定候选、自动验收与证据。
- “发布与验证”集中展示发布状态和业务对话。检测到项目实际发布指针后才显示企业模拟 App；发布前显示入口说明。
- 切换页签使用 `hidden` 保留子组件挂载，使开发和验收轮询继续运行；切换项目／需求修订时重新读取其快照。
- 切换项目时如有未保存需求或装配修改，会提示是否放弃后切换。

- `tsc --noEmit` 通过。
- Vite 生产构建通过。
- 本地 Docker app 静态资源已更新；HTTP 页面引用新 JS/CSS，`/health/ready` 返回 `ready`。
- 按本批约束未运行单元、契约或浏览器测试；未验证完整发布业务链路和移动浏览器布局。
- 本次用 `docker cp` 更新运行容器内的前端静态文件，没有重建 Docker 镜像。重建或重新创建容器时从当前工作区构建可保留这次改动。

四页签页面属于现有能力的重新编排。它没有增加新组件生成类型、自动验收范围或发布目标。
