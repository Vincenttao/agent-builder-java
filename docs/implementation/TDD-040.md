# TDD-040：Runner 恢复期间不重放进行中的执行

日期：2026-10-22。状态：真实 JVM 适配测试通过；Docker 进程故障验收仍未完成。

## 测试

在 `tests/adapters/deployment-recovery.test.ts` 增加进行中执行恢复测试。测试启动真实 Java Bridge Agent，并将模型 HTTP 响应暂停；Runner execution journal 已持久化为 `running` 且模型端确认收到 1 次请求。随后用同一部署持久目录创建新的 `JavaDeploymentManager`，并将该进行中记录作为新启动时读取的 durable journal 输入。

恢复后的 journal 将执行标成 `interrupted` 并加入 `restartUnsafeDeployments`；部署恢复器跳过该部署；相同 execution ID 重试仍返回 `interrupted`；查询该部署被 `DEPLOYMENT_NOT_READY` 拒绝；模型端请求数保持 1。测试释放原始模型响应并清理 JVM。

这条适配测试比仅手写 `waiting_confirmation` 记录更接近运行中恢复：模型请求和 Java Agent 都是真实进程交互。但测试通过拷贝持久执行记录模拟 Runner 新启动，没有实际杀死 Docker Runner，也没有触发 Mock 业务写操作。因此它证明重放防护决策，不证明容器故障后的外部写对账或完整 NF-01。
