# TDD-002：真实 Java 执行链与验收门禁

日期：2026-10-22。状态：适配切片完成，平台运行流程与阶段验收未完成。

## 交付与证据边界

- 固定 Core `0.1.17`、Runtime `0.1.4` 源码提交，构建依赖；Bridge 使用 JDK 21、Spring Boot 4.0.7。上游依赖构建跳过上游测试，不声称上游全部测试通过。
- Bridge 通过真实 `DeepAgent` 和 `JiuwenCoreAgentHandler` 运行，上游 AgentServer 提供 `/v1/query`。没有在 TypeScript 中重写 Agent Loop。
- 审计 Rail 记录模型／工具事件与会话计数；工具白名单 Rail 在实际 hook 中阻止未绑定工具。允许列表是正常调用入口的策略，不是宿主隔离。
- HTTP Tool 仅调用预绑定地址，用独立连接令牌认证；参数不能携带 URL。缺参数、额外字段、响应缺字段均失败。首个契约子集是必填平铺标量字段。
- JVM 的 `/bridge/manifest` 报告实际 JAR 摘要和已读取规格摘要。测试类目录返回空制品摘要，不能冒充可交付 JAR。内部入口要求独立运行令牌。
- 一次真实 DeepSeek → AgentServer → DeepAgent → Tool → 临时 Mock 的调用通过，Mock 收到一次设备查询，回答包含外部返回的 86°C 与来源。Rail 事件与实际装载摘要已核对；见[保留证据](evidence/TDD-002-live/result.json)。

当前只验证设备只读适配，不把这次探测视为完整 AC-05/07/08/17 或阶段验收。温度判断、建议质量尚未按完整设备验收用例评分。SDK 使用内存检查点，进程重启恢复明确为不支持。

本轮 40 条 TS 快速测试、6 条 Java 测试、TypeScript 类型检查、生产构建、Docker app 构建和 Compose 配置检查通过。Docker 构建内同样执行快速测试。未重新执行既有数据库／浏览器用例，因为本轮没有修改这些行为；它们仍按 TDD-001 的执行时间记录。Windows／Linux 换行统一处理后，文档基线摘要不受 CRLF 差异影响。

## 验收门禁

机器清单包含 56 个展开的平台条目、26 个业务条目、6 个非功能条目，共 88 项。清单验证引用、唯一性、分支和阶段数量；尚未实现的阶段测试文件保留 null。

门禁要求固定需求／制品／用例集／环境兼容键；模型评分不能覆盖断言失败。缺测试、跳过、模拟执行、缺外部证据、证据不可读、摘要变化、重复结果都不能通过。CLI 使用独立目标及实际制品摘要，不从待检查报告中取得期望版本。

`pnpm test:acceptance --phase P0-A` 当前正确输出 `unverified` 和非零退出；该命令尚未调度完整阶段用例。没有任何完整 AC／NF 因组件测试成功而自动晋级。
