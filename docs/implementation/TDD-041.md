# TDD-041：提交写入响应期间的真实容器故障

日期：2026-10-22。状态：已获得一次独立 Docker 故障注入证据；NF-01 整体验收未闭合。

## 验证目标

在独立 Compose 项目中运行固定 `equipment-workorder@1` 基线。对 TC-008 配置 `write-after-timeout`，在 Mock 工单写入已提交、延迟响应期间同时 SIGKILL App 与 Runner。检查重启后 Runner journal、Run 状态、动作状态和 Mock 外部业务状态，确认不会重放写入。

## 结果

- 使用独立项目 `agent-builder-td15-nf01`、Postgres／Runner 持久卷和宿主端口 18080；主演示项目 `agent-builder-platform` 保持健康。
- TC-008 Run：`6e7c4f99-d86b-4ae8-8826-38db03a9a89b`。故障配置为 `write-after-timeout`。对 App 和 Runner 执行 SIGKILL 后，Runner journal 为 `interrupted`，错误为 `RUNNER_RESTART_REQUIRES_RECONCILIATION`，Run 也以相同诊断进入 `interrupted`。
- Mock 独立状态显示 `equipment-status`、`work-order-create`、`work-order-by-key` 各一次；工单写调用一次、工单状态一笔。未观察到重复写入。
- 整体验收未完成：TC-008 仍为 `running`，测试部署处于 `stopping`，因此没有终态验收报告。该证据只支持“Runner 重启不重放已提交外部写入”，不支持 Run 成功恢复或 NF-01 全项通过。

## 故障与脚本修正

第一次恢复时脚本没有把 `APP_PORT=18080` 传给后续 Compose 调用，导致 App 端口回退并与主演示的 8080 冲突。主演示仍健康；隔离 App 随后通过显式端口设置恢复。脚本已改为每次 Docker 调用都固定传入 `APP_PORT` 和 `APP_ORIGIN`。此脚本问题及人工恢复均保留在 [故障证据](evidence/TD15-NF01-active-write-restart.json) 中，不将本次运行计为完整自动恢复通过。

故障注入后的隔离 Compose 项目及其专用卷已删除；主演示 `/health/ready` 返回 `ready`，原四个服务均健康。`APP_PORT`／`APP_ORIGIN` 现由故障脚本的每次 Docker 调用显式传入。

后续运行中发现的 JVM 退役卡点及修复见 [TDD-042](TDD-042.md)。需要在新隔离项目中重跑完整固定基线，确认 TC-008 能够终结并生成完整报告；P0-A/B/C 仍按各自受管分支报告验收。
