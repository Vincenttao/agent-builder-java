# TDD-072：按产物清单装载生成的 Tool 与 Skill

日期：2026-10-23。状态：Java Bridge 与 Runner 制品登记支持通用单 Tool／单 Skill 清单；金融双角色生成流程尚未实现。

## 问题

生成组件运行时把 `EquipmentTool`、`get_equipment` 和 `equipment-query` 写死在 Runner 制品登记、Java Bridge 类装载、Skill Rail 和候选摘要校验中。即使余额 Profile 生成了自己的 Java Tool 和 Skill，产物也会因设备专属名称而无法进入候选运行。

## TDD 实施

新增 Java Bridge 测试，构建实际的 `AccountBalanceTool` 类和 `skills/balance-query/SKILL.md`，并提供含类名、Tool 名、操作名和 Skill 名／路径的摘要清单。测试先因旧 Bridge 拒绝清单而失败，之后实现通用装载。

新清单使用 `generated-tool-skill@1`，绑定 `toolClassName`、`toolName`、`operationId`、`skillName` 和 `skillPath`。Runner 制品登记只接纳一个受约束命名的生成 Tool 类、一个 Skill 文件及一个 RuntimeSpec Tool；按实际清单路径校验归档，并逐项记录 class digest。候选服务按清单中的 Skill 路径核验摘要。Java Bridge 在执行生成代码前验证类／Skill 摘要、类继承关系、Tool 名与 operationId；Skill Rail 只发现并读取该清单指定的 Skill。旧 `equipment-tool-skill@1` 清单仍按既有默认绑定加载，以兼容已发布设备候选。

## 范围边界与后续

本批证明 Java Bridge 可以加载金融命名的 Tool／Skill fixture，并按清单绑定运行；它没有生成真实金融候选，也没有证明开发 Agent 产出的代码、Skill 会经全链路验证。Runner 的生成 Profile、工作区文件权限、冻结测试、平台合同测试和 Bundle 文件校验仍以设备 Profile 为准；余额 Tool 尚未动态写入 RuntimeSpec。没有构建部署新 Docker 镜像，TDD-070 的 P0-A/B/C 数字仍是此前部署目标证据，不能用来代表本批代码。
