## 目标

## 发现与处理

- 首次运行等待超时。容器不是根因：隔离测试启动真实 Java Runtime 时加载了旧的 `java/runtime-bridge/target/runtime-bridge-0.1.0.jar`。该 JAR 的 `ToolDescriptor` 不接受当前候选 RuntimeSpec 的 `connectionRef`，部署在调用开始前失败。
- 执行 `mvn -q test package` 重新构建 Bridge JAR 后，同一测试通过。Java Bridge 的 Surefire 报告显示组件测试均为 0 failures。
- 固化该测试为受限范围证据：替换 worker 受理取消后，Run 到达 `cancelled`，业务 JVM 停止；无模型调用、无外部工具调用；旧 worker 的延迟启动被拒绝，已退休 Run 和 Mock reservation 也被拒绝。
- 证据包含 Java Bridge JAR SHA-256 及 Run 事件顺序，并明确标注 `deterministic-fixture-adapter`，不冒充实时 Docker / live-mock 验收。
