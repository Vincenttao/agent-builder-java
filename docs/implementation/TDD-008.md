# TDD-008：取消、租约接管与发布门禁

日期：2026-10-22。本轮已部署到本地 Docker 的 8080 入口，回归和终态重启验证通过。平台整体仍未通过阶段验收。

## 变更

- 验收 worker 的租约检查扩展到 Run 创建、取消和审批决定。同一事务检查执行编号、租约持有人、递增令牌及有效期。取消验收任务立即阻止预分配 Run 的后续准入和批准；旧 worker 不能取消新 worker 已接管的 Run。
- Runner 对同一 JVM 的调用排队，取消只针对目标会话。Java Bridge 记录原生调用生命周期，取消模型等待并阻止后续模型／工具调用；只有原生调用返回才确认取消。平台专用调试 JVM 在运行结束后回收；共享 JVM 保留其他会话。
- 固定 SDK 的模型接口可能同步阻塞 HTTP。Bridge 使用受会话跟踪的虚拟线程调用供应商，取消时解除原生 Agent 的等待并中断对应线程。迟到响应不能恢复业务执行。该机制不承诺供应商侧立即停止生成或计费。
- 内部会话标识在模型适配器中移除，不发送给模型供应商。当前 Runner 使用非流式 SDK 调用；平台通过持久化事件流展示过程。未受控的原生流式入口明确拒绝。
- 活动执行存在时，Runner 拒绝停止整个部署。运行事件按会话过滤；模型响应失败不再直接杀死共享 JVM。结果未知的传输错误隔离部署的新调用并请求取消目标会话。
- 发布后台已有不可变历史、验证报告门禁、目标摘要核对、只读冒烟门禁、原子入口切换和回滚状态模型。门禁拒绝模拟执行、失败／未验证报告、缺用例／断言／证据和绑定变化。
- 发布失败先在有效租约下提交终态，再清理独立部署。旧 worker 失去租约后不能清理继任者成功发布的实例；未完成清理持久化并重试。

发布后台目前只通过注入执行端口的组件测试。真实发布执行器、管理 API／页面、业务入口及旧会话版本固定尚未接通，不能从当前产品发布 Agent。
