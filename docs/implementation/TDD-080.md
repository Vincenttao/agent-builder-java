# TDD-080：修正工具故障“无事实输出”验收并刷新 Docker 目标

## 问题与范围

AC-26 的真实 `read-timeout` 场景中，运行轨迹记录了 `tool_error`，助手说明查询超时并明确表示无法确认设备状态、温度和来源。验收器却只接受带 `kind=tool-error` 的 JSON，因此把符合“工具失败时不编造状态或来源”的自然语言答复判为失败。固定基线要求没有规定该 JSON 响应格式。

本次将断言改为检查回答中是否泄露本次 Tool 返回的状态、温度、来源、币种、余额或时间值；仍要求答复非空，结构化 `tool-error` 仍需带有效错误码与消息。确定性规则不再强制一种未列入需求的措辞或格式。验收规则版本升版，旧基线保留但不能用于新验证。

## 镜像迁移与重复检验边界

此前将 Docker 镜像存储迁移到 D 盘属于存储位置迁移，没有重建镜像。若迁移前后 App／Runner 镜像摘要、Compose 配置、环境变量、挂载、网络和数据状态均一致，且迁移后的服务健康检查通过，则已有验收证据继续有效；**不因这次迁移重复执行功能验收**。迁移记录与迁移后健康检查作为运维证据留存。

本次 TDD-080 后续确实修改了验收器并重新构建、部署 App／Runner，镜像摘要发生变化。因此需要评估并刷新受代码或运行时影响的证据。这是代码／镜像变更触发的证据新鲜度要求，与此前单纯迁移存储位置无关。纯迁移可标记为“无需重复功能检验”；只有上述摘要或运行配置发生变化、迁移后健康检查失败，或验收目标无法证明与原目标等价时，才重新检验受影响项。
