# TDD-081：移除 Docker 镜像构建中的重复质量门禁

日期：2026-10-24。目的：降低开发期间 Docker 镜像重建成本，同时保留 PRD 和 TD-15 要求的质量与部署验收。

## 发现

- CI 已在宿主构建环境执行 `pnpm typecheck`、单元／契约测试、PostgreSQL 集成测试、生产构建和浏览器 E2E。
- App Dockerfile 又执行类型检查及单元／契约测试；其中 `pnpm build` 本身会执行生产 TypeScript 编译。
- Runner Dockerfile 执行 `pnpm typecheck` 后又运行 `tsc -p tsconfig.build.json`；后者已经承担 Runner 生产编译和类型检查。
- CI 的 Java Adapter job 已运行 `mvn verify`；Runner 镜像再次执行 Bridge 测试没有增加独立验收覆盖。

## 调整

- App 镜像构建只执行 `pnpm build` 和生产依赖部署。
- Runner 镜像构建只执行生产 TypeScript 编译、生产依赖部署、Bridge JAR 编译打包，以及 OpenCode 可执行文件版本校验。
- PRD 的 P0-A/B/C 累积必测集合、真实 Docker 运行验收、外部状态核验、构建产物校验和候选完整性检查均保留。
- README 说明代码变更时先运行质量检查、只构建受影响镜像；代码未变时启动已有镜像，不使用 `--build`。

## 验证边界

本次只调整 Dockerfile 的重复检查步骤与操作说明。按用户要求，本批不运行 Docker 重建，也不启动 TD-15 回归；因此尚未取得新 Dockerfile 的构建证据。现有运行服务仍使用之前构建的镜像。首次后续构建应验证 App／Runner 镜像能成功生成并通过健康检查；构建失败时不得发布该候选。
