# TDD-025：生成任务 TDD 红测有效性与真实 Rail 生成

日期：2026-10-22。状态：TDD 红测门禁修复及一次真实 Rail 定义生成已验证；Rail 业务边界验收未完成。

## 问题与测试

真实双角色生成试运行发现，单靠命令返回非零不能证明 TDD 红测有效：测试可能因 fixture 初始化错误而失败，开发 Agent 也可能在多次改写测试后才得到通过结果。此时平台会把无效测试误当成红测证据。

新增 `isValidRedExecution` 策略及单测，要求首次红测必须满足：测试已编译并执行、输出未截断、失败来自未修改的 `IMPLEMENTATION_REQUIRED` stub。修复任务必须在原始源码上复现 `REPAIR_REGRESSION_FAILED`。Runner 在首个可运行测试后记录测试摘要并冻结测试文件；修复工作区也校验原源码与冻结的验收计划。策略诊断会返回明确错误码。

## 验证

- 单测覆盖有效红测、fixture 错误、通过、输出截断和修复复现规则。
- `pnpm test`：26 个文件、90 项通过。
- `pnpm test:integration`：16 个文件、95 项通过；包含修正后的设备 Tool 初始化 fixture。
- `pnpm typecheck`：通过。
- Docker Runner 更新并健康检查通过。
- 真实 DeepSeek/OpenCode 任务 `28696a98-867e-4f71-b25a-400867872304`：Tester 和 Developer 均完成，固定需求生成 `tool-call-limit@1:3` 定义，Runner 校验并构建 Bundle；RuntimeSpec 和 JAR 摘要见 [任务证据](evidence/TDD-023-live-rail-generation-28696a98-867e-4f71-b25a-400867872304.json)。

前两次运行暴露了测试 fixture 不可运行和 Rail JSON 字段不符合契约；另一次运行因生成测试包含相互矛盾的 null kwargs 断言而被门禁拒绝。这些失败没有被当作候选通过。修正提示后，以上成功任务完成了定义生成和候选构建。

## 边界

这次真实任务未运行生成候选的 TestDeployment，也未证明 Rail 达到上限后真实 Tool 调用为零、Rail 事件存在或跨 Run 计数重置。一次成功也不足以证明生成成功率。后续应先生成由平台固定预期的 Rail 行为测试，再进行独立候选执行与发布冒烟。
