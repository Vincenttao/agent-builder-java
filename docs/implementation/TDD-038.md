# TDD-038：部署候选的 Agent 轮次上限证据

日期：2026-10-22。状态：单轮上限行为与诊断回归通过；NF-04 及 TD-15 整体仍未通过。

## 问题

TDD-037 只在 OpenJiuwen Harness 确定性替身测试中检查 `maxIterations=1`，没有在平台创建的固定候选上运行。此前部署态探索显示 Runner 会返回通用 `JVM_QUERY_FAILED`，难以区分达到轮次上限和其他 JVM 查询错误。

## 修改

- `AuditRail` 按每次 Invoke 记录模型调用次数；工具回调发生时，如果模型调用数已达到快照中的 `maxIterations`，写入结构化 `iteration_limit_reached` 事件，并带上上限和实际调用数。
- Run 终态归类仅在 Run 失败码为 `JVM_QUERY_FAILED` 且同一 Run 的 Runtime 轨迹含轮次上限事件时，映射到 `ITERATION_LIMIT_REACHED`。原始错误保存在终态事件的 `runtimeError` 字段；其他 JVM 错误保持原分类。
- 添加 Postgres 集成回归，覆盖上述限定映射；扩展 Java 装配测试检查上限事件元数据。
