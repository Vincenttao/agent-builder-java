# TDD-004：Runner 进程与 JVM 部署适配

日期：2026-10-22。状态：适配组件通过，Runner HTTP 服务与平台 Run 编排尚未接通。

已完成进程树停止、实际退出码、分段日志脱敏，以及固定 JAR／规格的 JVM 部署管理。输入按部署 ID 和摘要去重；同 ID 改输入冲突。规格和 JAR 在调用前后核对摘要，JVM 启动后还会核对实际装载清单。

每个部署独立 JVM，首个执行配置限制每 JVM 同时一个调用；不同 JVM 可并行。状态、规格、SDK 事件和过程日志写入受控目录；令牌不写进状态文件，Java 子进程不继承数据库凭据。Runner 重新初始化后不会自动重放旧调用，历史活动部署标记为待核对。

6 条实际进程适配测试通过，未跳过：

1. 取消后父进程和可观察子进程停止写入。
2. 分两段输出的假凭据均被脱敏，实际非零退出码保留。
3. 不存在的可执行文件明确失败。
4. 两个真实 JVM 返回可区分结果；重复输入不重建，停止一个不影响另一个。
5. 越界部署目录与错误制品摘要拒绝。
6. 规格被改动后拒绝调用并停止该 JVM；重建管理对象后终态和证据可读。

节点测试使用真实 Java AgentServer 和 Core，模型服务是确定性本地替身，不能作为 live 模型验收。Java Bridge 的 6 条测试也重新通过。原始红灯与绿灯位于 `test-results/tdd-004/`。源码级 JAR 摘要读取已改成流式处理，避免启动时将整个 182 MB 文件放入 Java 堆。
