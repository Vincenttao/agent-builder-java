# 本机工作台运行说明（开发中）

当前分支已接通工程、模板、Coding 审阅和真实 Java 运行 API。PC 页面、Coding 多文件业务修订及交付下载尚未完成；`npm run demo` 仍是静态原型，不能据此判断真实链路已通过。

## 1 本机依赖与启动

使用 WSL Linux 的 Node 22.12+、Git、JDK 17+、Linux Maven、Python3。Coding 使用 OpenCode 1.18.9；Trace 使用本机 Jaeger 2.22.0。不需要 Docker。Core 0.1.17、Runtime 0.1.4 及其 BOM 须已安装到 Maven 仓库，固定来源见 [开发计划](DEV-02_可运行Demo开发计划.md)。

模型 Key 只放在被忽略的 `.env.local`，文件权限 `600`；字段使用 `DEEPSEEK_API_KEY`，Base URL 为 `https://api.deepseek.com`，本 Demo 使用 `deepseek-flash`。不要将真实值写进工程、Git、日志或命令参数。

- `npm run start:mock`：独立业务 Mock，默认 `127.0.0.1:8770`，重启清空模拟账本。
- `npm run start:workbench`：工作台 API，默认 `127.0.0.1:8768`；当前尚不提供新的 PC 页面。
- 当前准备好的本机 Jaeger 使用查询端口 `16686`、OTLP HTTP 端口 `14318`，须独立运行。

工作台端口可用 `WORKBENCH_PORT` 指定，数据目录用 `WORKBENCH_DATA_DIR` 指定。优先使用已准备的 `.tools/apache-maven-3.9.11/bin/mvn`；也可通过 `MAVEN_BIN` 指向 Linux Maven。`JAVA_BIN` 可指定 Java；`WORKBENCH_OFFLINE=1` 只使用已缓存 Maven 依赖。

## 2 已实现 API

本机通过 `x-workbench-role: platform|application` 模拟身份，不是企业登录。平台可诊断应用的运行记录；发起业务、停止和删除仍由运行发起身份操作。

| 操作 | 接口与输入 |
| --- | --- |
| 查看模板工程 | `GET /api/projects/moa-platform`，平台身份 |
| 保存已审阅文件 | `PUT /api/projects/:id/files`，`{baseHead, changes}` |
| 发行固定模板版本 | `POST /api/templates/:id/releases`，`{version}` |
| 从发行版创建空应用 | `POST /api/projects`，`{releaseId, name}` |
| 发起编码 / 审阅差异 | `POST /api/projects/:id/jobs`、`GET /api/jobs/:id`、`POST /api/jobs/:id/apply|reject` |
| 构建并启动保存版本 | `POST /api/projects/:id/runs`，`{baseHead}`；返回 202，后续查询原 runId |
| 查看运行与日志 | `GET /api/runs/:id` |
| 明确停止 / 重新核验原进程 | `POST /api/runs/:id/stop|reconnect` |
| 发起业务消息 | `POST /api/runs/:id/messages`，`{conversationId?, query}` |
| 查看原会话 / 回放数据 | `GET /api/runs/:id/conversations/:conversation`，只读 |
| 核对丢失响应的原会话 | `POST /api/runs/:id/conversations/:conversation/observe`，只读取 Java 状态并更新观察快照 |
| 原任务确认、切换、恢复、查单 | `POST /api/runs/:id/conversations/:conversation/reply|decide|resume|receipt`；输入见 [Java 接口](../runtime-template-java/README.md) |
| 清理不再引用的历史运行 | `DELETE /api/runs/:id`；只允许已停止且归属核验通过的运行目录 |

同时仅一个构建/Java 运行，最多 24 份运行记录。构建在固定提交副本中进行，不污染工程工作树；后续保存不会改变原运行。工作台核验 PID、进程启动时间和 runId 后接管原进程；服务未就绪时保留原记录，不重复启动。一个数据目录只允许一个工作台拥有。

业务请求前先预留会话 ID；请求丢失响应后保留原 ID，不自动重发。运行中的状态归 Java；Node 的停止后快照仅供查看，未完成或未核对的状态明确标记，不能继续确认或自动恢复。正常关闭工作台会停止其拥有的 Java/OpenCode 进程；浏览器刷新不会停止进程。

## 3 验证边界

Node 的契约/本机进程测试不调用真实模型；模拟适配器记录 `contract-fixture` 或 `process-fixture`，不计为 Java 业务验证。

`node --import tsx verification/live-workbench-runtime.ts` 使用真实工程发行、固定提交 Maven 构建、Java 和 Flash。当前一条查询通过；随后实测也出现了 `MODEL_ENDED_WITHOUT_VERIFIED_RESULT`，发现基础提示与业务 Skill 的只读收束指导冲突，本地参考修订已通过确定性测试，真实 OpenCode 复核因外发源码授权被自动审批拒绝而待完成。失败不计为 Demo 验收通过，相关记录在 `test-results/dev-workbench-v2/p4/`。不自动切换模型或重新提交业务请求。
