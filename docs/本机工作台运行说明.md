# 本机工作台运行说明（开发中）

当前分支已接通工程、模板、Coding 审阅和真实 Java 运行 API。PC 页面已接入模板发行、创建应用、文件编辑、业务配置/装配、处理流程、Coding 审阅、调试运行、只读事件回放及固定版本技术导出。真实多文件业务修订、双角色业务联调和导出包独立业务验收尚未完成。`npm run demo` 仍是静态原型，不能据此判断真实链路已通过。

## 1 本机依赖与启动

使用 WSL Linux 的 Node 22.12+、Git、JDK 17+、Linux Maven、Python3。Coding 使用 OpenCode 1.18.9；Trace 使用本机 Jaeger 2.22.0。不需要 Docker。Core 0.1.17、Runtime 0.1.4 及其 BOM 须已安装到 Maven 仓库，固定来源见 [开发计划](DEV-02_可运行Demo开发计划.md)。

模型 Key 只放在被忽略的 `.env.local`，文件权限 `600`；字段使用 `DEEPSEEK_API_KEY`，Base URL 为 `https://api.deepseek.com`，本 Demo 使用 `deepseek-flash`。不要将真实值写进工程、Git、日志或命令参数。

- `npm run start:mock`：独立业务 Mock，默认 `127.0.0.1:8770`，重启清空模拟账本。
- `npm run start:workbench`：工作台与 PC 页面，默认 `http://127.0.0.1:8768`。
- 当前准备好的本机 Jaeger 使用查询端口 `16686`、OTLP HTTP 端口 `14318`，须独立运行。

工作台端口可用 `WORKBENCH_PORT` 指定，数据目录用 `WORKBENCH_DATA_DIR` 指定。优先使用已准备的 `.tools/apache-maven-3.9.11/bin/mvn`；也可通过 `MAVEN_BIN` 指向 Linux Maven。`JAVA_BIN` 可指定 Java；`WORKBENCH_OFFLINE=1` 只使用已缓存 Maven 依赖。

## 2 已实现 API

本机通过 `x-workbench-role: platform|application` 模拟身份，不是企业登录。平台可诊断应用的运行记录；发起业务、停止和删除仍由运行发起身份操作。

| 操作 | 接口与输入 |
| --- | --- |
| 查看模板工程 | `GET /api/projects/moa-platform`，平台身份 |
| 保存已审阅文件 | `PUT /api/projects/:id/files`，`{baseHead, changes}` |
| 发行固定模板版本 | `POST /api/templates/:id/releases`，`{version}` |
| 从发行版创建空应用 | `POST /api/projects`，`{releaseId, name}` |
| 发起编码 / 审阅差异 | `POST /api/projects/:id/jobs`、`GET /api/jobs/:id`、`POST /api/jobs/:id/apply|reject` |
| 构建并启动保存版本 | `POST /api/projects/:id/runs`，`{baseHead}`；返回 202，后续查询原 runId |
| 查看运行与日志 | `GET /api/runs/:id` |
| 明确停止 / 重新核验原进程 | `POST /api/runs/:id/stop|reconnect` |
| 发起业务消息 | `POST /api/runs/:id/messages`，`{conversationId?, query}` |
| 查看原会话 / 回放数据 | `GET /api/runs/:id/conversations/:conversation`，只读 |
| 核对丢失响应的原会话 | `POST /api/runs/:id/conversations/:conversation/observe`，只读取 Java 状态并更新观察快照 |
| 原任务确认、切换、恢复、查单 | `POST /api/runs/:id/conversations/:conversation/reply|decide|resume|receipt`；输入见 [Java 接口](../runtime-template-java/README.md) |
| 清理不再引用的历史运行 | `DELETE /api/runs/:id`；只允许已停止且归属核验通过的运行目录 |

同时仅一个构建/Java 运行，最多 24 份运行记录。构建在固定提交副本中进行，不污染工程工作树；后续保存不会改变原运行。工作台核验 PID、进程启动时间和 runId 后接管原进程；服务未就绪时保留原记录，不重复启动。一个数据目录只允许一个工作台拥有。

业务请求前先预留会话 ID；请求丢失响应后保留原 ID，不自动重发。运行中的状态归 Java；Node 的停止后快照仅供查看，未完成或未核对的状态明确标记，不能继续确认或自动恢复。正常关闭工作台会停止其拥有的 Java/OpenCode 进程；浏览器刷新不会停止进程。

## 3 验证边界

Node 的契约/本机进程测试不调用真实模型；模拟适配器记录 `contract-fixture` 或 `process-fixture`，不计为 Java 业务验证。

`node --import tsx verification/live-workbench-runtime.ts` 使用真实工程发行、固定提交 Maven 构建、Java 和 Flash。当前一条查询通过；随后实测也出现了 `MODEL_ENDED_WITHOUT_VERIFIED_RESULT`，发现基础提示与业务 Skill 的只读收束指导冲突，本地参考修订已通过确定性测试，真实 OpenCode 复核因外发源码授权被自动审批拒绝而待完成。失败不计为 Demo 验收通过，相关记录在 `test-results/dev-workbench-v2/p4/`。不自动切换模型或重新提交业务请求。

## 4 PC 页面当前路线

页面源码在 `workbench-ui/`，由工作台按固定文件白名单提供；不对外开放仓库文件。原 `npm run demo` 仍是独立的静态设计稿，不能代替新工作台。

1. 新数据目录默认没有应用或已发行模板。切换为林知远（平台开发者），进入 MOA 模板，在“模板发行”中发行已保存版本。
2. 切换为陈晓（应用开发者），选择 MOA 版本，填写应用名称，创建空白应用；没有 i豆模板，也不预置业务 Skill。
3. 进入“文件与指令”，修改 `instructions.md` 或 `application.json`，点击“保存所有修改”。保存创建真实 Git 提交，过期版本由后端拒绝。工程切换器位于工程标题右侧，页面内用横向页签区分功能。
4. 草稿在当前页面内按工程隔离；切换身份/工程保留，刷新或关闭前需要保存。平台查看应用时只显示已保存内容，不能修改应用。

UI 内容摘要变化后清除旧原型专属模拟存储；旧页面检测到版本变化后禁止写入。实际 Git 工程、运行记录、业务账本和历史验证证据不属于浏览器模拟数据，不随页面更新删除。当前没有伪造运行成功或交付下载按钮。运行页面已接入真实控制 API；完整真实业务路线与独立交付继续验证。

PC 入口自动检查：`node --import tsx --test verification/api.test.ts verification/pc-entry.test.ts`。使用真实本机 Git/SQLite/HTTP 与 Chromium，核对两角色路线、只读诊断、草稿保留、保存结果及 1280/1440/1920 无水平溢出；不调用模型，不证明完整业务端到端成功。

### 业务配置与处理流程

应用内“业务配置”编辑自身/委派/范围外业务、应用层 System Prompt、业务 Skill 指导和可用操作、已挂载 Agent、范围外接管及原任务策略。Skill 和 Agent 添加先进入工程草稿，统一“保存所有修改”后成为 Git 版本。新 Skill 自动生成原生文件头；没有可执行操作时明确标为指导草稿，不声称可运行。操作定义来自 `adapters/operations.json`，执行脚本和契约仍须开发、检查后装配。

“处理流程”展示已保存定义；未保存草稿不进入图。图示区分自身 Skill、委派 Agent、明确范围外接管、澄清、冲突阻断及 A→B→A 恢复规则。点击节点进入相应配置区，不调用模型、工具或业务服务；语义匹配和真实执行路径必须在后续运行/Trace 页面核查。平台模板对应“范式默认配置/默认处理流程”，应用诊断只读。连接编辑不提供新系统认证或企业授权。

检查命令增加 `verification/pc-configuration.test.ts`；使用本地测试资产验证表单/文件双向同步、Skill 操作勾选、Agent 挂载、已保存流程及无业务调用。该测试不证明新 Skill 语义正确或实际服务接通。

### Coding 助手与差异审阅

进入工程的“Coding 助手”，描述需求后生成建议；建议在隔离的 Git worktree 中产生，当前工程在应用前不变化。平台模板使用 `moa-platform-development`，应用使用 `moa-application-development`；页面展示对应开发指导、实际工具读取记录、会话、引擎与模型。历史未声明引擎或测试引擎不计为真实 OpenCode 验证。

选择文件查看基础版本与建议内容；基础版本通过 `/api/jobs/:id/review` 从原提交读取，不能拿后来修改的文件冒充。拒绝不会改变工程，应用全部差异会创建真实 Git 提交。存在未保存草稿或过期基础版本时禁止应用。平台诊断应用只能读记录，不能生成、回答或应用。

澄清回答绑定原任务和原问题；取消只作用于原编码任务。页面只轮询既有任务，不自动重试生成，切换页面或身份不会取消任务。回答草稿与焦点在状态刷新中保留。运行和澄清任务按后端期限结束，不无限占用进程。

界面文件按工作台启动时的同一份内容提供，并绑定摘要。修改 UI 源码后需要重启工作台；旧浏览器携带的版本若与新服务不一致，写操作被拒绝，避免旧页面继续改工程。浏览器模拟数据清理不删除真实工程。

本批检查：`node --import tsx --test verification/coding.test.ts verification/api.test.ts verification/pc-entry.test.ts verification/pc-configuration.test.ts verification/pc-coding.test.ts`。PC Coding 检查注入 `contract-fixture`，验证多文件审阅、拒绝、人工修改保护、原问题回答、取消、双角色指导选择及三种 PC 宽度。**没有启动真实 OpenCode 或向 DeepSeek 发送源码**；真实多文件修订及一致性复核仍等待此前的具体源码外发授权，不把本批测试计为 RD-02 全项完成。

### 调试运行、原任务与只读事件回放

“调试运行”以已保存提交构建并启动。页面显示启动版本、日志、JAR 摘要及引擎来源；工程后续保存不会改变原运行。全局只允许一个活动构建或 Java 进程，其他应用可通过“查看原运行”找回，不自动另起进程。平台诊断应用不能发送消息、停止或清理应用运行。

新需求进入业务范围判断；参数补充、A2A 等待回答和确认走“原任务”入口，绑定原 taskId 与确认标识。切换先展示保留/暂不切换/放弃未提交任务；保留 A 后展示 A 与 B，B 结束再复核续办 A，旧确认不能复用。已提交但结果未知的操作只核对原状态/原键回执，不重发；第三层阻断、定义冲突、过期确认及复核失败保留原因。

真实 Java 运行的任务/事件关联 Trace ID，可打开本机 Jaeger 查看；测试引擎的标识不当作真实 Trace。“进入只读回放”冻结已取得的事件，停止轮询，通过位置和前后步骤查看原事件。任务卡明确展示冻结快照的状态，不声称还原任意历史时刻的全部 Core 状态，也不重执行模型、Skill 或 Agent。返回当前状态后才恢复观察。

明确停止会中断尚未结束的会话，不撤销已提交业务；停止后仅显示最后观察快照。历史清理核验本次运行目录归属，不删除工程或其他运行。正常关闭工作台也会停止其拥有的进程；离开浏览器页面不会自动停止。

本批测试为 `verification/pc-runtime.test.ts` 与 `verification/runs.test.ts`。PC 测试通过 `contract-fixture` 走原任务确认、A/B 续办、第三层提示、未知结果、跨应用找回、固定运行版本、只读诊断与清理；回放期间 HTTP/测试引擎计数及观察文件字节不变。该结果不替代真实 Java/Flash/HTTP/A2A/Trace 的端到端验收。运行测试先因入口缺失失败；后续清理断言的空状态文字预期修正为页面实际提示，保留 HTTP 204 与数据库删除断言，没有放宽业务条件。

### 固定版本技术导出

应用内“版本与导出”选择已构建并启动过的运行，一次形成应用包和源码包；同一运行重复导出返回同一份记录。当前工程的新编辑不进入旧包。平台诊断可只读查看，不得创建或清理应用交付。

- 应用包：`application/application.jar`、`assets/` 业务定义/Prompt/Skill/适配资产、来源声明、`manifest.json`、`SHA256SUMS`、`verify.sh`、`start.sh`、无 Key 的配置样例及 `DELIVERY.md`。
- 源码包：`source/` 下的固定源码、Maven 配置、相同业务资产和测试夹具，另含 `build.sh` 与启动/校验说明。开发指导 `.opencode/` 不作为部署依赖复制；Git 元数据、工作台索引、运行日志/会话和本地配置不进入包。
- 解压后先执行 `sh verify.sh`。源码执行 `sh build.sh`，需要 Java 17+、Maven 和已安装的 Core 0.1.17/Runtime 0.1.4 依赖（实际以包内 POM/BOM 为准）。通过外部环境注入 `DEEPSEEK_API_KEY` 后执行 `sh start.sh`；默认监听 `127.0.0.1:8780`。源码重建后的 JAR 需要重新记录摘要与验收，不复用原二进制结论。

导出前校验原 Git 内容、运行构建输入和 JAR 摘要；下载前重新核对归档摘要。原运行被交付记录引用时不能清理；用户明确清理交付包后才解除引用。最多保留 8 份交付目录（包括需核对的打包中断目录），单文件 400 MB、输入文本共 64 MB/2000 文件。临时打包目录在完成/失败后清理；不自动删除历史归档。

归档只表明“技术导出”，清单和页面均不宣称独立运行、业务或发布已通过。`contract-fixture` 包的启动脚本明确拒绝把测试包当真实 Java 服务，不能用本次测试替代 RD-06。实际固定 JAR/源码构建与停止工作台后的独立查询、确认及两层续办还需另行验证。包不包含独立 Mock、Jaeger 或企业系统；这些依赖须单独准备。

API：`GET/POST /api/projects/:id/exports`，创建输入 `{runId}`；`GET /api/exports/:id/manifest`；`GET /api/exports/:id/files/application|source`；`DELETE /api/exports/:id`。新建返回 201，同一运行复用返回 200，下载提供 `X-Content-SHA256`。

检查：`verification/exports.test.ts`、`verification/pc-delivery.test.ts`。使用本地契约引擎验证两种真实归档/下载、旧提交保持、排除本地 Key/状态、缺资产/改源码/改 JAR/改归档拒绝、校验脚本、测试包禁止冒充服务、引用保护和三个 PC 宽度。未运行 Java 构建或外部模型。
