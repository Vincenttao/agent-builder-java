## 4 页面体验还可改善的地方

本次截图确认后端版是 PC 布局：左侧全局导航、工程内横向导航、中央编辑区、右侧 Coding。以下是体验建议，不等同于功能缺失：

- **文件列表信息密度偏高**：业务文件与平台只读指导混排，长文件名截断。默认突出应用可编辑资产，开发指导分组折叠，保留完整路径查看入口。
- **重复 Coding 入口**：常驻右栏与“Coding 助手”页签同时存在。明确前者用于提需求/看状态，后者用于完整记录及差异审阅，避免两个入口看起来是不同助手。
- **状态提示占用编辑区**：标题操作、阶段横幅和双层页签叠加。可压缩已知状态，保留阻塞原因与下一步按钮，减少编辑首屏纵向占用。
- **业务概念和技术概念仍并列**：能力、Skill、操作与连接需在选中对象时解释关系。例如“理财 Skill → 转账操作 → Mock连接”；不增加第二套路由配置。

## 5 建议实施顺序

1. **先收尾业务测试的一个 i豆切片。** 用已有实现完成页面、取消、失败及外部状态验证；再扩展理财和 Deep，避免同时重写执行器。
2. **完成冲突修订闭环。** 诊断绑定输入版本；Coding修改仍沿用现有差异审阅；修复后复核并运行受影响业务用例。
3. **绑定候选与交付证据。** 复用前两步报告与运行记录，只增加引用和状态，不另建发布平台。
4. **统一端到端收口，再同步远端。** 固定候选对应的源码、模型、JAR与包，完成双角色PC走查和独立包启动；明确Mock成功与企业系统验收的边界。是否实施和推送以用户后续授权为准。

继续采用当前 Node.js/Express + SQLite索引 + Git版本 + OpenCode + 本机Java，不为页面补齐引入新前端框架、Docker或流程引擎。企业权限、通用工具接入、生产流水线发布和跨重启恢复继续后置，不作为这轮Demo补齐前置。
