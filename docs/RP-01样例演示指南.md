# RP-01 样例演示指南

此演示复用平台既有的设备查询模板候选，包含预构建 Tool、审计和白名单 Rail；查询流程由固定 Agent 指令定义，没有单独生成的 Skill 资产。它验证平台的验收、发布与真实业务调用流程；本次没有启动两个开发角色，也不代表任意新需求都已实现自动生成。

## 启动与登录

本地调试可在 `.env.local` 设置 `LOCAL_DEBUG_AUTH=true`，更新 `app` 服务后，打开页面会自动进入工作台，无需填写访问令牌。关闭此开关后恢复令牌登录。调试模式保留会话、Origin 和 CSRF 校验；Compose 端口继续只绑定本机。以下令牌登录步骤仅适用于关闭调试模式时。

当前本地主服务为 Compose 项目 `agent-builder-td15-nf01`，API 地址 `http://127.0.0.1:18080`。保留这套服务和候选数据即可，无需构建镜像。

在 `D:\agent-builder-java` 执行：

```powershell
corepack pnpm demo
```

访问 **http://127.0.0.1:5173/?demo=equipment**。使用 `.env.local` 中的 `LOCAL_BOOTSTRAP_TOKEN` 登录。也可访问根地址，点击“体验预构建样例”。不要把访问令牌或模型密钥写入报告。

前端连接已有后端，不会自动启动 Docker。前端终端按 Ctrl+C 停止，不会停止后端和已发布 Agent。若主服务已停止，先用下列命令恢复这套现有环境（不重建）：

```powershell
$env:APP_PORT='18080'
docker compose -p agent-builder-td15-nf01 --env-file .env.local up -d --wait
```

如端口已有占用，先检查所属进程，不要重复启动。其他主环境可在启动前配置 `BUILDER_API_TARGET`（实际 API 地址）和 `BUILDER_API_ORIGIN`（后端接受的 Origin）。默认分别为 `http://127.0.0.1:18080`、`http://127.0.0.1:8080`；Origin 与映射端口不同来自现有主环境配置。代理只转换本机前端的同源请求。

## 四步操作

| 页签 | 操作及输入含义 | 应看到的结果 |
| --- | --- | --- |
| 需求说明 | 查看目标使用者、业务目标、交付内容；均为只读固定需求 | 设备查询、固定需求及三项验收场景（需求还提及历史回滚，本批仅验证查询演示） |
| 环境与装配 | 查看 `get_equipment` Tool、Skill 装载状态，以及审计、白名单 Rail；“重新检测环境”刷新依赖状态 | 实际候选装配，模型已配置但尚需真实运行核验 |
| 测试与证据 | 候选与基线已锁定；点击“运行验收用例”，会调用真实 DeepSeek 并使用独立 Mock 数据 | 正常查询、缺编号、工具超时三项结果；展开场景查看断言和证据 |
| 发布与对话 | 审阅通过报告，勾选同意切换入口，点击“发布此验证版本”；发布成功后选择 U1002，进入模拟 App，输入完整问题并发送 | 独立发布实例通过冒烟；对话返回设备结果，证据显示实际 Mock 调用 |

建议业务请求：`查询 PUMP-001 的状态、温度和来源，输出设备报告。`

Mock 固定数据为 PUMP-001、warning、86°C，来源 `seed-equipment-001@1`。这些是虚构测试数据。每条消息目前都应带完整问题；“新建业务会话”清空当前会话引用，“进入模拟 App”获取选定模拟身份的业务访问凭据。

若当前已经验收并发布，可直接进入第四页签体验对话，无需重复验收和发布。需重现完整流程时再执行上述四步。页面关闭不会取消正在运行的验收；重新进入可查看记录，取消请使用“取消验证”。

## 如何展示失败处理

在“测试与证据”展开 **TC-003**，点击“查看证据 TC-003”。执行器对这一项注入 `read-timeout`，检查工具错误证据、没有伪造设备事实、写入次数为 0。该场景显示“通过”表示失败被正确处理，并不表示工具查询成功。

TC-002 展示缺少设备编号时先追问、业务调用为 0。未取得通过的真实验收报告或未确认审阅时，发布按钮保持禁用。模型调用或环境出现异常时保留原报告，修复对应问题后决定是否重测，不降低断言。

## 样例来源与边界

- 固定候选：`0c9bc4d9-c934-4480-9ce4-184a1ca9f82a`；来源类型：`assembled-template`。
- 来源为主环境现存候选 API 记录及其固定快照、基线，本批证据保存读取内容。当前 RP-01 结果单独记录，旧证据不会变成新目标的通过记录。
- 页面校验候选、需求快照、基线及摘要；缺少数据或不匹配时明确报错，不自动生成替代品。不能仅克隆代码就在空数据库重放该样例。
- 发布依然经过既有真实模型验收和只读冒烟。脚本化模型结果不能用于正式演示发布。
- 使用已有 Java JAR 与 SDK；本批不实现 RP-02 缓存/回收改造，也不宣称完整 TD-15 通过。
- 最新结果与限制见 [RP-01 实施记录](implementation/RP-01.md)。

```powershell
corepack pnpm exec vitest run --project unit apps/web/src/prebuilt-sample.test.ts
corepack pnpm typecheck
corepack pnpm --filter @agent-builder/web build
$env:RUN_LIVE_E2E='1'
node --env-file=.env.local node_modules/@playwright/test/cli.js test -c playwright.demo.config.ts
```

最后一条需要已启动的前端和主服务，会运行真实模型验收并发布样例，输出 `test-results/rp-01`。默认使用本机 Edge。只有浏览器后续步骤失败、已有验收任务无需重做时，设置 `RP01_VALIDATION_ID` 为实际记录 ID，可继续观察并使用原验收结果；不能用它替换其他候选的验收。常规体验不需要运行这些命令。
