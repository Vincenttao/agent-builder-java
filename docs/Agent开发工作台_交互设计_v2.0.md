# Agent 开发工作台交互设计 2.0

日期：2026-10-24。依据：[PRD 2.0](Agent开发工作台_PRD_v2.0.md)。本版已提供[可点击设计稿](developer-prototype-v2/开发工作台2.0.html)与[演示说明](developer-prototype-v2/README.md)，只代表第一阶段交互交付。

## 1 两种用户、两个工作区

| 角色 | 默认入口与导航 | 编辑对象 | 交付对象 |
| --- | --- | --- | --- |
| 平台开发者 | 范式工程、公共能力、开发 Skill、模板发行、工程活动、应用运行诊断 | 公开 API/SPI 下的范式与接线、Rail/Tool、开发 Skill、开放契约 | 固定版本的范式、开发 Skill 与开发模板 |
| 应用开发者 | 全局左栏仅应用，模板在新建流程选择；进入应用后横向显示概览、开发、测试、运行记录、版本与发布 | 业务配置、已开放规则、业务 Skill、映射脚本与局部扩展 | 固定场景应用及企业 CI/CD 交接材料 |

右上角提供一个“切换用户身份”入口，显示当前姓名与身份。Demo 提供“陈晓 · 应用开发者”和“林知远 · 平台开发者”两位模拟用户；切换后展示各自的导航、任务与 Coding Agent 指导，恢复原编辑位置和未保存内容，刷新保留所选身份。平台发行页不提供直接切成应用用户的按钮。真实产品由登录身份和项目授权决定工作区；本 Demo 没有认证或权限后端，切换不改写已有应用、运行或候选。

应用列表只显示全局内容；不再提供独立的应用方模板页。进入应用后，标题处显示名称与可搜索的应用切换器，标题下是应用横向页签，中央为当前工作对象，右侧为该应用的 Coding Agent。平台继续使用独立的角色导航。代码入口始终可达；Coding Agent 负责依据范式开发 Skill 辅助编排和修改，不把开发能力限制为聊天。

模板开发属于平台开发者的任务。平台左栏以“模板开发 · MOA”和“记录与诊断”分组；工程首页提供维护范式、准备公共能力、编写开发指导、检查与发行四步入口。代码页按正在编辑的对象保持范式工程或开发 Skill 选中，并提供返回入口。应用运行诊断不显示工程检查按钮、发行待办或当前工程修订，以免混淆运行版本。

## 2 从新应用开发者出发

新用户默认进入空应用列表，可从已发行的 MOA 开发模板新建应用，没有 i豆模板、预置应用或当前应用导航。MOA 提供工程结构、机制、扩展契约和开发指导；i豆来自开发者后续提出的业务需求。

```mermaid
flowchart LR
  A[选择 MOA 模板] --> B[创建应用和填写目标]
  B --> C[Coding Agent 提出开发方案]
  C --> D[审阅差异并应用到同一工程]
  D --> E[配置系统接入与修改代码]
  E --> F[模拟用户调试与 Trace 定位]
  F --> G[评测与固定候选]
  G --> H[企业 CI/CD 交付]
```

创建表单先选择已发行的 MOA 模板，再填写应用名称与目标；模板说明原地展开，不丢失表单输入，没有 i豆业务选择器。创建后从标题下的模板版本查看只读来源，已有应用继续固定原版本。应用创建后即有 Coding Agent 输入框，可继续补充需求。根据 i豆目标展示预设开发方案，应用后保留名称与目标，添加配置、接口契约、业务 Skill 和映射；连接仍待绑定。其他需求只整理通用草稿，不误装配或执行 i豆。

开发首页展示应用目标和开发进度。“开发”页分为应用指令、业务技能、工具、连接和文件：指令描述职责及回答方式；业务技能维护任务指导和规则；工具展示外部接口的输入/输出与映射；连接选择环境和授权方式；文件保留源码查看与简单修改。查询余额、礼品目录、提交兑换、查询回执是四个接口工具，资格校验和用户确认属于规则。当前 Demo 仅 Mock 可用；选择企业环境会阻止运行，避免伪造真实接入成功。

平台团队预先提供可用的 MOA 模板（Demo 1.3.0），已开放资格校验配置。应用开发者可独立走完流程。平台工作区用于单独维护范式、开发指导和发行新版本；发行不覆盖已有应用。旧草稿仍保留原模板及历史，不静默升级。

开发 Skill 的知识来源固定到 `agent-solution` 的二开指南：MOA 快照 `1a92265cd`，`guides/docs-java` 快照 `68fcb1c31`。两者分别版本化，不能未经兼容验证混合 API。内容包括选择路径、工程分层、公开扩展、注册接线、允许范围和分层检查。

开发 Skill 给 OpenCode 使用；业务 Skill 随应用执行。设计稿分别展示两者，不把 `SKILL.md` 文件名相同当作用途相同。当前只展示指导文本，真实 Skill 包发现、装载与调用证据属于后续实现。

业务技能页显示“应用开发者维护”；工具页展示平台维护的公共工具、输入输出、使用连接和应用可修改范围。“需要新工具？”说明应用专用工具与新系统接入的责任，可以把需求带到 Coding Agent 继续讨论；本 Demo 不生成新工具、不发起审批，也不以现有映射或资格规则冒充接入。连接页说明调用身份、凭据来源及企业业务权限，当前仍只有本地 Mock 可执行。

平台公共能力采用职责卡片，分别解释 MOA 机制、工具与系统连接、业务 Skill 与应用扩展、开发指导与开放契约。福利接口是可按应用需求选用的预置示例，不是 MOA 通用模板固有业务。公共能力详情可进入相关工程或开发指导；完整接入门户和权限管理后置。

### 2.1 从中途进入

工作区按实际状态提示下一步。顶部阶段提示不依赖用户点击了第几个页签；检查或交付之后继续修改，显示新草稿的待办。应用列表按应用展示阶段、模板版本和上次位置，提供“继续开发”“运行记录”“版本与发布”。列表不展示特定应用的右侧助手。新建应用不会替换旧应用；标题切换器支持按名称搜索。

| 进入时的阶段 | 应用开发者 | 平台开发者 |
| --- | --- | --- |
| 开发到一半 | 返回上次页签和文件；恢复代码暂存、配置暂存、未发送目标及待审阅方案 | 返回工程位置；恢复本角色代码暂存、目标及待审阅方案 |
| 修改已有内容 | 保存后新修订待检查；旧运行、候选和交接记录保持原版本 | 工程草稿与已发行版本并列；修改不影响应用已固定的模板 |
| 需要定位问题 | 从“运行记录”查看历史，即使当前连接不可用；可回到未完成的测试处理确认或核对 | “应用运行诊断”查看应用 Trace；“工程活动”查看保存、检查、发行记录 |
| 准备交付/发行 | 失败项进入对应配置或文件；通过后固定候选，再预演交接 | 检查报告关联工程修订；未通过或已发行的同一修订不能再发行 |
| 已交付/发行后回来 | 可查看和下载指定历史候选；当前草稿是否已交接单独判断 | 可查看固定发行快照；新工程修改显示“未发行”，不覆盖旧版 |

平台工程活动仅记录本页面实际发生的操作，没有真实 OpenCode/构建执行轨迹。具体组合与证据见[双角色阶段走查](developer-prototype-v2/双角色阶段走查.md)。

## 3 Coding Agent、编排与代码

1. 用户在当前工程提出目标。面板显示角色、应用/工程修订、开发 Skill 和可修改范围。
2. Agent 提出编排与文件差异。用户可查看修改前后，应用前草稿保持原内容。
3. 应用差异时核对基础修订。手工保存后旧建议不可覆盖新文件，需要重新生成。
4. 编排视图与代码引用同一修订。各应用及平台工程的未保存代码分别在本浏览器暂存，刷新恢复；暂存不等于保存。手工代码未保存时，可返回列表、切换应用或角色，回来恢复该文件；应用内部换文件、执行及应用建议仍需先保存或恢复。应用名称、指令/模型、规则、连接选择也保留暂存，执行仍使用已保存配置；基础修订变化时拒绝旧暂存覆盖，可放弃并重新编辑。
5. 应用配置、连接和代码变化生成新修订，旧快照和候选不被改写；旧检查失效。撤销形成新修订，需要重新检查。调试消息、礼品与夹具属于测试输入，不改变应用修订；运行记录单独保存这些输入。

应用首页不使用“选择礼品、用户确认”等终端用户步骤充当开发流程。开发页按对象展示接口契约及配置；只有实际支持的业务才能执行。自由 Python/Java 代码不会在浏览器运行，也不能靠图形显示或静态检查宣布验证成功。

本轮只评审 PC 页面，在 1280×800、1440×900、1920×1080 窗口核对布局。工作区与 Coding Agent 并列，助手的指导、对话和建议独立滚动，输入与发送保持可见；切换页面和刷新保留未发送目标。表单、说明文字、卡片和按钮统一间距及层级，次要责任说明折叠展示。此前已有窄窗口降级保留，不新增手机专用入口或移动端功能。

## 4 联合调试与 Trace

调试直接从草稿保存快照，无需先固定交付候选。界面分为开发者测试设置、明确标识的终端用户模拟器、执行轨迹及当前执行依据。礼品选择、消息和兑换确认只在模拟器内出现。标准接口可成功查询；嵌套接口夹具使旧映射失败；修复后重新运行产生新快照，原失败保留。

确认与写操作使用独立状态：待确认、确认失效、拒绝、成功、结果未知。改变礼品/应用修订使原确认失效。未知结果先查询原交易，不允许重新提交；取消或拒绝不能被表述为撤销已经发生的交易。

“运行记录”独立于当前调试准备条件，支持按结果筛选，展示应用、执行修订、模板版本与测试输入。打开旧 Trace 不替换当前草稿；执行快照只读。浏览其他运行后，可从状态提示回到未完成测试。旧记录没有保存的字段标为未记录，不用当前配置补齐。

| Trace 区域 | 应用开发者 | 平台开发者 |
| --- | --- | --- |
| 执行列表 | 当前应用的运行、修订和结果 | 应用运行诊断汇总所有应用，按应用和结果筛选；查看其他应用不改变应用方当前上下文 |
| 分步详情 | 业务步骤、输入输出、错误与脚本定位 | 增加 Span/父 Span 标识；真实产品再显示实际采集的跨服务关系 |
| 回放控制 | 播放、暂停、上一步、下一步、指定步骤 | 同样只读；不因平台角色而允许重放交易 |
| 缺失数据 | 真实产品标记未采样/截断/未记录 | 额外提示传播和版本兼容边界，不虚构因果 |

Core/Runtime 已具备 OTel 上报源码。后续工作台主要接查询与版本关联；OTLP 接收、观测存储查询和业务事件保存需分别讨论。只读回放消费保存的数据，不是重运行或断点恢复。当前 Trace、Span、时间及载荷全部为模拟。

## 5 测试与企业交付

“测试”页内分交互调试与测试检查；示例检查验证已保存草稿，失败明确列出并提供处理入口。“版本与发布”引用报告并提供返回测试页的入口，通过后固定演示候选；修改草稿使当前交接按钮失效，历史交接注明所属修订。新候选固定后仍能单独预览和下载旧候选，下载内容固定到所选候选，不偷偷带入后续草稿修改。同一修订不重复固定候选。

平台发行页同时展示当前工程草稿、当前供应用使用的版本、检查报告和发行历史。检查关联工程修订；修改后报告过期。一次发行冻结模板、开发指导及已记录的工程内容，同一修订不能重复发行。已有应用看到新版提示，仍使用原固定版本；Demo 尚未提供已有应用的兼容升级流程。

当前草稿提供“预览应用方创建体验”，展示发行后将开放的参数和指导；开发 Skill 页可预览应用开发者将收到的内容。二者均标明草稿范围，不创建应用、不切身份、不把草稿当作已经发行的版本。已发行模板说明及发行快照继续只读。

Demo 最多保存 10 个独立应用，达到上限时阻止新建且不覆盖已有数据。每个应用分别保留最近 20 次运行、10 个候选、10 条交接，以及代码/配置暂存、对话、测试状态和最后位置。平台另保留 10 个发行快照、30 条工程活动及一个暂存文件。旧单应用数据自动迁入列表，历史快照和候选不改写。清除浏览器存储会丢失这些数据，不代表后端持久化或多人协作已实现。

页面区分目标交付包结构、JSON 设计清单与企业交接预演。当前不生成 JAR、不执行 CI、不真正停止工作台。后续真实产品必须在已验证应用包上证明：停止工作台及专用代理后，导出服务仍可独立完成业务。

导航与多应用的上一批记录见[多应用导航走查](developer-prototype-v2/多应用导航走查.md)。本批用户身份与模板入口验证见[走查记录](developer-prototype-v2/用户身份与模板入口走查.md)。

最新一轮从应用开发者和模板开发者完整走查，覆盖职责、导航、功能、布局、美观与易用性，问题及证据见[双角色完整流程与页面评审](developer-prototype-v2/双角色完整流程与页面评审.md)。此前记录保留其原始验证范围。

## 6 分阶段落实

- DEMO-01：本版双角色静态网页，浏览器本地模拟即可；应用旅程检查和交互回归与真实业务验收分开。
- DEV-02：先讨论本机 Node.js + OpenCode + Java 方案，再实现应用开发者的界面和后端；平台供给可先固定。
- FULL-03：先讨论方案，再补平台工程、公共能力、开发 Skill/模板发行及真实双角色协作。

本轮不启动 DEV-02/FULL-03，不部署新 Runtime 或观测服务。Demo 可直接打开 HTML 或使用 Node 静态服务，不以 Docker 作为前置条件。
