# DEV-02 可运行 Demo：演示与交付指南

本指南对应架构第 13.2 节 RD-01～06。本机 Mock 模拟企业业务系统，实际执行链使用 OpenCode、Java/Core/MOA、模型和 HTTP/A2A；不是生产企业集成。完整 PRD 中的权限治理、多人协作、跨重启恢复和企业 CI/CD 不属于本次 Demo 的已实现承诺。当前验收结论以 [RD 核对](DEV-02_RD验收核对.md) 为准。

## 启动与依赖

在 Linux/WSL 仓库目录执行 `npm ci`。真实工作台使用 `npm run start:workbench`，打开 http://127.0.0.1:8768/；静态设计稿使用同一默认端口，两者只启动一个。依赖 Node.js 22.12+、Git、OpenCode 1.18.9、Java 17+、Linux Maven、Python 3，以及 POM 声明的 Core/Runtime 依赖。本地验证使用 Core 0.1.17/Runtime 0.1.4；源码快照见模板的 `runtime-source.json`。

模型按 [配置说明](模型配置与切换.md) 设置。Key 只在外部环境或本机权限 600 的 `.env.local`，不进入工程、交付包或截图。默认 deepseek-flash/OpenAI 兼容接口；更换模型需重新验证工具调用行为。编码助手与业务运行当前共用配置。此次外发授权目的地为 api.deepseek.com，不包含真实企业数据或其他服务商。

另一个终端执行 `npm run start:mock`，默认 http://127.0.0.1:8770。连接配置必须指向实际可达的 Mock。已有本机 Jaeger 提供查询/UI 16686、OTLP HTTP 14318；工作台不负责自动安装或管理 Jaeger。一个工作目录只允许一个工作台，一个工作台只允许一个活动构建/Java 运行。退出工作台使用所属终端 Ctrl+C；Mock、Jaeger 分别管理。

默认工作目录 `.workbench/data` 从空 MOA 模板开始。要查看本机已留证工程，可在验证进程全部结束后单独启动：

```bash
WORKBENCH_DATA_DIR=.workbench/verification/opencode-refusal-2026-10-25T03-10-57-473Z npm run start:workbench
```

这是本机证据工作目录，不随 Git 分发。请保留历史运行与导出，勿用它进行批量清理。最终 PC 应用 ID 为 `ae879b4b-e5ec-4eed-93bc-8f4efef56af8`，映射修正后的工程修订为 `1f77013fb40045b48dfd4266011829a8e62ba373`。历史运行显示“已停止”时只能读历史；新演示需要明确构建并启动，不能从历史确认按钮恢复任务。

## 平台到应用

1. 左侧切换平台开发者，进入 MOA 开发模板。查看基础代码、默认规则和 `.opencode/skills/` 开发指导；由 Coding 助手提出修改，审阅差异后应用，也可手工保存小修改。发行模板固定 Git 提交。
2. 切换应用开发者，从 MOA 发行版创建空白应用。此时没有 i豆业务；在 Coding 助手提出余额、礼品兑换、采购转交等 i豆应用需求。助手按模板开发 Skill 修改应用指令、业务配置、Skill/脚本和操作目录；审阅后应用并检查。
3. 从“业务配置”查看自己负责、可委派、范围外接管、Skill 操作及连接。“处理流程”显示已保存规则，不是实际运行轨迹。System Prompt 在 `instructions.md`；Skill 指导在相应 `SKILL.md`。定义冲突交给 Coding 助手统一修订，不靠运行时越过规则。

真实留证中的业务资产来自先前空应用的实际 OpenCode 9 文件方案；后续修正模板的新应用显式复用了该方案。平台拒绝收束建议经过手工审阅修正，原建议编译失败及被拒记录均保留。不要把这条来源链描述成最终应用在一次浏览器会话中从零生成、无失败完成全部开发。

## 应用业务走查

保存工程后到“调试运行”，点击“构建并启动保存版本”。运行绑定启动时提交；修改文件不会改变正在运行的 Java。

| 操作 | 页面与业务检查 |
| --- | --- |
| 发送“查询我的i豆余额，查询后结束。” | 正常映射读取 1280；任务完成，不写入业务系统 |
| 将余额路径改为 `employee.wallet.wrongField`，保存并启动新运行 | 查询失败且零写入；停止后修正为 `employee.wallet.availablePoints`，保存并启动新版本验证 |
| 新建业务会话，发送“我要兑换1张咖啡券，giftId是coffee，quantity是1。请发起确认。” | 等待原任务确认，尚未提交兑换 |
| 待确认时发送“我要申请采购一台办公电脑，这是采购业务，请转交采购Agent处理。” | 先选择保留/放弃；选择“保留原任务并切换”后显示 A/B 两张任务卡 |
| A/B 同在时提出范围外人事问题 | 第三层阻断，不调用兜底 Agent |
| 在 B 的“原任务补充回答”中填写“确认”并回复 | B 结束后出现“复核并续办原任务”；复核产生新确认，旧确认不能使用 |
| 对恢复的 A 点击“确认原操作” | 兑换提交一次；重复确认被阻断 |
| 另开会话发起兑换并拒绝 | 正常结束，结果为拒绝，不新增兑换写入 |

B 失败后仍可复核 A；未知写入结果只能按原幂等键核对，不新建键重发。迟到 A 回执归属 A，不抢占 B。这些分支的完整业务验收由 `verification/fixtures/standalone-business.ts` 驱动真实模型与独立 Mock；不将脚本成功替代页面逐按钮验收。

## Trace 与回放

展开“Trace 关联”，打开本机 Jaeger，核对真实 Trace 的路由、LLM 和工具调用。Trace、执行事件和最终业务结果一起查看；存在 Trace 不代表业务成功。

应用方进入只读回放，调整事件位置。平台方切换身份，从同一应用的“查看诊断”进入同一运行/会话；不能发业务消息或停止应用。回放冻结观察快照，只按原事件顺序展示，不重新执行。任务卡显示冻结时状态，不声称复原任意事件时刻的完整内存。当前验证覆盖回放期间运行 API 请求新增 0、Mock 状态及观察文件不变；没有独立抓取模型网络流量计数。

## 固定版本交付

应用方在“版本与导出”选择正确运行，核对完整 Git 提交后导出。分别下载应用包与源码包，对照页面 SHA-256。导出不会自动标为已发布或业务验收通过，平台只能只读查看。

在新的目录解压；应用包执行 `sh verify.sh`，外部注入模型配置后执行 `sh start.sh`。源码包先执行 `sh verify.sh`、`sh build.sh`，再启动；可用 `MAVEN_BIN` 指定 Maven，离线构建需本地已有声明依赖。目标环境仍需模型、业务 HTTP/A2A、Python，查看 Trace 还需 Jaeger。交付包不包含工作台、OpenCode、Mock、模型 Key 或会话数据库。

独立服务默认 127.0.0.1:8780，可用 `APP_PORT`、`JAVA_BIN`、`WORKBENCH_STATE_DIR` 调整。定义接口为 `GET /workbench/application`，业务入口为 `POST /workbench/messages`。确认/续办必须使用服务返回的原任务 ID 与新令牌。停止工作台后业务可独立运行；重启独立 Java 不会自动恢复未完成任务。新重建 JAR 单独记录摘要与业务结果，不冒用旧二进制结果。
