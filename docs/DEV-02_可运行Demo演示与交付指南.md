# DEV-02 可运行 Demo：演示与交付指南

本指南对应架构第 13.2 节 RD-01～06。本机 Mock 模拟企业业务系统，实际执行链使用 OpenCode、Java/Core/MOA、模型和 HTTP/A2A；不是生产企业集成。完整 PRD 中的权限治理、多人协作、跨重启恢复和企业 CI/CD 不属于本次 Demo 的已实现承诺。当前验收结论以 [RD 核对](DEV-02_RD验收核对.md) 为准。

## 启动与依赖

在 Linux/WSL 仓库目录执行 `npm ci`。真实工作台使用 `npm run start:workbench`，打开 http://127.0.0.1:8768/；静态设计稿使用同一默认端口，两者只启动一个。依赖 Node.js 22.12+、Git、OpenCode 1.18.9、Java 17+、Linux Maven、Python 3，以及 POM 声明的 Core/Runtime 依赖。本地验证使用 Core 0.1.17/Runtime 0.1.4；源码快照见模板的 `runtime-source.json`。

模型按 [配置说明](模型配置与切换.md) 设置。Key 只在外部环境或本机权限 600 的 `.env.local`，不进入工程、交付包或截图。默认 deepseek-flash/OpenAI 兼容接口；更换模型需重新验证工具调用行为。编码助手与业务运行当前共用配置。此次外发授权目的地为 api.deepseek.com，不包含真实企业数据或其他服务商。

另一个终端执行 `npm run start:mock`，默认 http://127.0.0.1:8770。连接配置必须指向实际可达的 Mock。已有本机 Jaeger 提供查询/UI 16686、OTLP HTTP 14318；工作台不负责自动安装或管理 Jaeger。一个工作目录只允许一个工作台，一个工作台只允许一个活动构建/Java 运行。退出工作台使用所属终端 Ctrl+C；Mock、Jaeger 分别管理。

默认工作目录 `.workbench/data` 从空 MOA 模板开始。要查看本机已留证工程，可在验证进程全部结束后单独启动：

```bash
WORKBENCH_DATA_DIR=.workbench/verification/opencode-refusal-2026-10-25T03-10-57-473Z npm run start:workbench
```

这是本机证据工作目录，不随 Git 分发。请保留历史运行与导出，勿用它进行批量清理。最终 PC 应用 ID 为 `ae879b4b-e5ec-4eed-93bc-8f4efef56af8`，映射修正后的工程修订为 `1f77013fb40045b48dfd4266011829a8e62ba373`。历史运行显示“已停止”时只能读历史；新演示需要明确构建并启动，不能从历史确认按钮恢复任务。

## 桌面工作区

真实界面沿用原 Demo 的 PC 框架。身份切换在右上角；工程标题旁可切换工程、保存版本。进入工程后，横向页签切换中央工作对象，右侧 Coding Agent 保持可见，可跨页描述开发需求、查看任务状态。完整差异与原问题在中央“Coding 助手”页审阅。业务配置上方可快速定位范围/Skill/Agent/续办/映射；中央和助手分别滚动。界面版本更新会清理本 Demo 浏览器暂存，请先保存需要保留的工程草稿。

## 平台到应用

1. 右上角切换平台开发者，进入 MOA 开发模板。查看基础代码、默认规则和 `.opencode/skills/` 开发指导；由 Coding 助手提出修改，审阅差异后应用，也可手工保存小修改。发行模板固定 Git 提交。
2. 切换应用开发者，从 MOA 发行版创建空白应用。此时没有 i豆业务；在 Coding 助手提出余额、礼品兑换、采购转交等 i豆应用需求。助手按模板开发 Skill 修改应用指令、业务配置、Skill/脚本和操作目录；审阅后应用并检查。
3. 从“开发 → 应用设置”查看自己负责、可委派、范围外接管、Skill 操作及连接。“开发 → 编排 → 处理流程”显示已保存规则，不是实际运行轨迹。System Prompt 在 `instructions.md`；Skill 指导在相应 `SKILL.md`。定义冲突交给 Coding 助手统一修订，不靠运行时越过规则。

真实留证中的业务资产来自先前空应用的实际 OpenCode 9 文件方案；后续修正模板的新应用显式复用了该方案。平台拒绝收束建议经过手工审阅修正，原建议编译失败及被拒记录均保留。不要把这条来源链描述成最终应用在一次浏览器会话中从零生成、无失败完成全部开发。

## 应用业务走查

保存工程后到“测试 → 调试运行”，点击“构建并启动保存版本”。运行绑定启动时提交；修改文件不会改变正在运行的 Java。

| 操作 | 页面与业务检查 |
| --- | --- |
| 发送“查询我的i豆余额，查询后结束。” | 正常映射读取 1280；任务完成，不写入业务系统 |
| 将余额路径改为 `employee.wallet.wrongField`，保存并启动新运行 | 查询失败且零写入；停止后修正为 `employee.wallet.availablePoints`，保存并启动新版本验证 |
| 新建业务会话，发送“我要兑换1张咖啡券，giftId是coffee，quantity是1。请发起确认。” | 等待原任务确认，尚未提交兑换 |
| 待确认时发送“我要申请采购一台办公电脑，这是采购业务，请转交采购Agent处理。” | 先选择保留/放弃；选择“保留原任务并切换”后显示 A/B 两张任务卡 |
| A/B 同在时提出范围外人事问题 | 第三层阻断，不调用兜底 Agent |
| 在 B 的“原任务补充回答”中填写“确认”并回复 | B 结束后出现“复核并续办原任务”；复核产生新确认，旧确认不能使用 |
| 对恢复的 A 点击“确认原操作” | 兑换提交一次；重复确认被阻断 |
| 另开会话发起兑换并拒绝 | 正常结束，结果为拒绝，不新增兑换写入 |

B 失败后仍可复核 A；未知写入结果只能按原幂等键核对，不新建键重发。迟到 A 回执归属 A，不抢占 B。这些分支的完整业务验收由 `verification/fixtures/standalone-business.ts` 驱动真实模型与独立 Mock；不将脚本成功替代页面逐按钮验收。

## Trace 与回放

展开“Trace 关联”，打开本机 Jaeger，核对真实 Trace 的路由、LLM 和工具调用。Trace、执行事件和最终业务结果一起查看；存在 Trace 不代表业务成功。

应用方进入只读回放，调整事件位置。平台方切换身份，从同一应用的“查看诊断”进入同一运行/会话；不能发业务消息或停止应用。回放冻结观察快照，只按原事件顺序展示，不重新执行。任务卡显示冻结时状态，不声称复原任意事件时刻的完整内存。当前验证覆盖回放期间运行 API 请求新增 0、Mock 状态及观察文件不变；没有独立抓取模型网络流量计数。

## 固定版本交付

应用方在“版本与导出”选择正确运行，核对完整 Git 提交后导出。分别下载应用包与源码包，对照页面 SHA-256。导出不会自动标为已发布或业务验收通过，平台只能只读查看。

在新的目录解压；应用包执行 `sh verify.sh`，外部注入模型配置后执行 `sh start.sh`。源码包先执行 `sh verify.sh`、`sh build.sh`，再启动；可用 `MAVEN_BIN` 指定 Maven，离线构建需本地已有声明依赖。目标环境仍需模型、业务 HTTP/A2A、Python，查看 Trace 还需 Jaeger。交付包不包含工作台、OpenCode、Mock、模型 Key 或会话数据库。

独立服务默认 127.0.0.1:8780，可用 `APP_PORT`、`JAVA_BIN`、`WORKBENCH_STATE_DIR` 调整。定义接口为 `GET /workbench/application`，业务入口为 `POST /workbench/messages`。确认/续办必须使用服务返回的原任务 ID 与新令牌。停止工作台后业务可独立运行；重启独立 Java 不会自动恢复未完成任务。新重建 JAR 单独记录摘要与业务结果，不冒用旧二进制结果。

## 原 Demo 内容补齐（2026-10-25）

真实工作台已恢复两级工作对象导航：应用内为“概览 / 开发 / 测试 / 运行记录 / 版本与发布”；开发内为“应用设置 / 能力 / 编排 / 文件与指令 / Coding 助手”。平台还提供公共能力、开发 Skill、工程活动及模板发行入口。运行记录只读；执行入口在“测试 → 调试运行”。

- **编排**分为处理流程、业务范围、转交与续办、业务 Skills、规则预演。处理流程有七个可点击节点、连线、条件详情、示例与手动分支预演。点击节点只查规则，不改变请求去向。图和预演绑定已保存提交；草稿、输入或版本变化后需重新预演。
- **路由预演**精确匹配 `tests/routing-examples.json` 的预期示例，或按手动选择的分支模拟。它不调用模型、业务系统或 Agent；没有匹配示例时提示澄清，不自动判为范围外。目标失效、空业务或第三层请求会显示阻断。
- **业务过程图**从 `skills/<id>/flow.json` 读取可编辑说明。i豆展示余额、礼品、确认、兑换和原回执；理财展示资金不足时询问转账、转账后重新查询、再次确认购买。`designOnly: true` 表示设计说明，不是新的工作流执行引擎；实际执行仍由 Skill、模型和执行端约束负责。
- **能力目录**统一展示 Skill、A2A Agent、工具操作及待接线草稿；可查看来源文件、维护角色、执行方式、输入输出契约、确认和次数约束。HTTP/MCP/新增脚本的接入草稿不等于适配器已经可用，存在草稿时结构检查不通过。
- **测试与候选**实际检查保存版本的定义、能力引用、指定写操作确认、Python 语法和设计说明。报告存入工作台数据库，旧版本报告保留并标为过期。通过后可固定源码技术候选，绑定提交与报告；它只证明结构检查通过，明确标记业务未验证、未发布。已有运行与固定制品导出沿用原校验路径；候选、构建制品与企业发布分别展示。
- **平台页面**显示工程中真实 `.opencode/skills/*/SKILL.md`，可进入文件编辑及 Coding 差异审阅；活动读取 Git 提交和检查报告。工具权限治理和企业接入授权仍属后续范围，不把角色提示当作企业权限系统。
- **模型配置**在应用设置展示当前模型、API 来源及凭据是否配置，不返回 Key。当前仍采用本机共享配置；切换方式见[模型配置与切换](模型配置与切换.md)，尚未实现每应用独立模型选择器。

三个预制示例可再次运行 `node --import tsx scripts/install-business-examples.ts` 补入缺失的流程说明和预期示例。脚本先核对安装标记与工程提交，仅处理未被修改的安装示例；只补缺失说明文件，不覆盖业务编辑，也不调用模型。界面版本升级只清理本 Demo 浏览器缓存，不删除工程、运行、检查报告或导出历史。

本批测试：18 项相关浏览器/API/工程/配置测试通过；最后对预演进度恢复与运行记录只读补做 2 项定向复测，通过；TypeScript 检查通过。浏览器覆盖双角色及 1280/1440/1920 桌面宽度，保留原有 Coding 审阅、草稿、A/B 调试、只读回放和固定导出断言。测试使用临时工程与确定性执行器，不计为新增真实模型、Java 金融业务或企业 CI/CD 验收。本机证据位于 `test-results/demo-restoration-20261025/`，临时测试目录由测试清理，历史证据不变。

刷新后的实际服务也已走查：i豆商城、理财购买、综合业务主Agent 三个示例的当前保存版本均通过结构检查；逐一打开编排图及业务过程图，再检查平台开发 Skill/工程活动。浏览器错误 0、模型/业务执行请求 0，历史运行数量和状态未改变。该结果证明页面与检查链可用，不新增金融交易或模型路由的业务通过结论。

## 选择DeepAgent范式并装配业务

MOA和DeepAgent共用新建、设置、能力、编排、测试、运行与交付流程。两者是不同执行范式；DeepAgent模板不预置短材料业务。选择DeepAgent发行版创建空业务应用后，可从能力/业务Skills添加指导，再选择CORE文件工具。Coding助手读取deepagent-application-development辅助编排；平台从“切换开发模板”维护范式和deepagent-platform-development。

本机装配示例为“短材料整理（装配示例）”：在空模板上添加material-notes Skill和read_file/write_file/list_files。先发“整理本周进展：登录已完成；支付偶发超时，小王负责，周五前排查”，同一会话再发“支付排查截止时间改为下周一，保留其他事项”。运行端每轮先加载Skill，工具集合必须属于该Skill；结果显示真实brief.md和读写/核实事件，只读回放不重复执行。

当前DeepAgent发行版只接通Skill和CORE文件工具。Agent/A2A、HTTP/MCP等明确显示未接通或草稿；未接入OTel，不制造Trace。后续执行器接通后复用同一装配页。资料与边界见[设计与验证](DeepAgent模板_设计与验证.md)。

`node --import tsx scripts/install-deepagent-template.ts`首次发行空模板并安装业务示例。对于本批早先的场景试作，它仅在安装标记、模板提交和旧示例提交均吻合时发行新的不可变版本，保留旧版本和旧应用；任何人工修改都会阻止覆盖。无标记模板与当前源码不一致时停止，需先核对。
