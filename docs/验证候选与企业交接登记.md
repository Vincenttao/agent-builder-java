# 验证候选与企业交接登记

入口为“版本与发布”。保留原有源码技术候选与独立技术导出；它们不要求业务已通过，也不标为企业发布成功。新增“验证证据候选”用于绑定已取得的真实来源，不改写旧报告或旧包。

## 固定验证证据

1. 对当前保存版本完成结构检查、[一致性诊断](一致性诊断与关联修订.md)和[业务回归](业务回归测试用例与执行.md)。三种报告各自证明不同事项。
2. 在原有技术导出区域选择业务报告的同一次运行，导出应用包及源码包。无业务报告也可技术导出，但不能把它标成验证候选。
3. 选择通过的业务报告及其原运行交付包，固定验证证据。服务端核对源码head、结构报告、业务用例摘要、runId、JAR摘要、公开模型配置、诊断输入摘要和制品摘要，并校验两份归档实际字节。相同源码的另一次运行也不能混用。
4. 查看不可变候选记录。包含契约引擎或缺少真实来源时显示“contract-only / 业务未验证”；只有实际Java、公开模型来源、实际OpenCode诊断及对应受控用例齐备才显示受控业务通过。Mock成功不代表企业系统验收。

候选绑定原运行、报告、诊断与交付包的数据库引用；引用中的报告、包和运行禁止清理。包内格式不变，不在导出后追加诊断或验收信息，旧归档SHA保持不变。重复固定完全相同的证据返回原候选。源码或测试变化后旧候选标为旧版本，不能用来证明新代码。

同一候选定义后来被诊断出冲突时，页面显示阻断状态，保留历史报告和包，不再作为当前可交付候选；阻止新候选及“通过”登记，先关联修订和复核。纯测试变更可按既有规则复用语义诊断，但不能复用旧业务报告。

## 企业结果登记

候选下可以追加“企业验收”或“交接”结果，填写负责人、标题、结果（待核对/通过/失败）、依据说明及可选HTTP(S)链接。结果显式标为“用户登记 / 工作台未执行”，不请求链接、不发起企业流水线、不改变原业务报告或包、不自动标为发布成功。

登记固定candidateId、exportId、原源码head与清单摘要，可对保留的历史候选登记实际企业结果，页面明确其原版本。后续登记追加新记录，不覆盖先前结果。平台身份只读查看应用候选与登记。

当前最多保留48份验证候选、96份企业登记，每个候选最多12份登记。超限拒绝新建，不自动删除证据；正式长期归档与企业流水线对接另行设计。本轮验证覆盖本机契约/API/PC与最终独立Mock业务，不将企业登记示例当作企业实际验收证据。
