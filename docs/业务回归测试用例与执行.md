# 业务回归测试：用例与执行

业务测试从工程已保存的 `tests/business-cases.json` 读取固定输入和独立断言。结构检查只检查资产格式；设计预演不执行模型；业务测试会通过所选活动运行调用模型/工具。三者的通过结论分开记录。

## 使用流程

1. 在开发页编辑用例，或请 Coding 助手生成可审阅的文件修改。保存后，构建并启动同一版本。
2. 在“测试 → 业务回归”选择当前版本的活动运行。MOA 需明确允许调用独立 Mock，包括用例声明的写入和故障注入。
3. 执行一次后观察原报告。取消只阻止后续步骤，等待已发出的请求核对，不撤回交易、不自动重试。测试期间该运行不接受人工消息或停止操作。
4. 查看每项断言实际值、调用/写入统计、原会话与版本来源。历史报告保留原版本；修改代码或测试后不会自动视为当前通过。

首批 MOA 只接受所有业务连接都指向同一 `http://127.0.0.1:<port>` 的独立业务 Mock，通过健康检查及只读账本核对。建议每次真实验收使用新的隔离 Mock；执行器不重置账户、订单和历史。故障注入后恢复原控制配置。不要在同一 Mock 同时进行其他业务测试，否则调用增量会混入其他活动。

DeepAgent 使用所选运行的原会话与文件资产。每条用例新建一个会话，步骤在该会话内连续执行。当前交付物断言读取 `brief.md`。

## 用例格式

```json
{
  "schemaVersion": 1,
  "family": "moa",
  "mockConnection": "idou",
  "cases": [{
    "id": "decline",
    "title": "拒绝兑换不写入",
    "steps": [
      {"id":"ask","type":"message","query":"兑换咖啡","assertions":[
        {"source":"task","path":"state","operator":"equals","value":"WAITING_INPUT"}
      ]},
      {"id":"no","type":"reply","answer":"拒绝","assertions":[
        {"source":"task","path":"state","operator":"equals","value":"COMPLETED"},
        {"source":"delta","path":"writes","operator":"equals","value":0}
      ]}
    ]
  }]
}
```

这只是格式示例，实际业务名称和输入必须与工程定义一致。完整示例在 `examples/idou/tests/business-cases.json`、`examples/commerce-wealth/tests/business-cases.json`、`examples/deepagent-materials/tests/business-cases.json`；空开发模板不预装这些业务。

| 字段 | 含义 |
| --- | --- |
| family | `moa` 或 `deepagent`，必须与工程一致 |
| mockConnection | MOA 指向 application.json 中已有连接标识 |
| cases[].id / title | 唯一标识和说明；标识使用小写字母、数字、下划线或短横线，字母开头 |
| steps[].type | `message` 新输入、`reply` 回答原确认、`receipt` 核对原回执、`controls` 故障注入、`assert` 只观察断言 |
| query / answer | 消息内容 / 原确认答复 |
| fromStep | reply/receipt 采用先前步骤的任务及确认，不制造新确认；默认采用上一步状态 |
| expectedError | 仅允许原请求的 `STALE_TASK_INPUT`（旧令牌）、`TASK_NOT_CURRENT`（原任务已结束/不在当前位）、`TASK_DEPTH_LIMIT`、`NO_WAITING_INPUT`；没有观察到预期拒绝即失败 |
| control | 仅 `redemptionDelayMs`（0～5000毫秒）和 `nextA2aFailure`（布尔值） |

DeepAgent 只允许 message/assert。最多12条用例、每条20步、合计80步，每步最多5项断言，每条用例至少1项。执行最多10分钟，超时阻止下一步，已发出的请求沿用原请求期限。报告上限48份，引用中的报告/运行不能清理。

## 断言与证据

`source` 取 `view`（原运行响应）、`task`（当前或最新任务）、`mock`（i豆账本）、`wealth`（理财账本）、`delta`（相对本用例开始的调用/写入增量）、`artifact`（brief.md内容）。`path` 使用点分隔自有字段，例如 `state`、`calls.idou.redeem`，空路径表示整个来源。

| operator | 判断方式 |
| --- | --- |
| equals | actual与value严格相等，支持JSON值 |
| contains | 字符串或序列化JSON包含value |
| gte | 数值actual不小于数值value |
| absent | 指定字段不存在 |
| notEqualsFrom | 当前view/task的path与fromStep相同字段均存在且不同；用于重新确认的令牌校验 |
| sameExcept | 仅artifact且路径为空；严格等于fromStep原稿全部oldText替换成newText后的内容，其余字符不变 |

常用增量：`writes`、`transferWrites`、`purchaseWrites`、`a2aCalls`、`calls.idou.balance/gifts/redeem/receipt`、`calls.wealth.plan/transfer/purchase/receipt`。COMPLETED不替代账本写入、确认隔离和内容保留断言。断言不通过不会自动改预期或再次执行。

报告固定源码head、用例摘要、runId、引擎、公开模型配置、JAR摘要、步骤/任务/Trace引用及实际值。大段内容显示摘要和截断提示，原内容仍在原运行资产中。契约引擎通过只能标为契约验证；真实Java/模型配合Mock通过也不是企业系统验收。工作台重启后未完成报告标为中断，不自动重放。
