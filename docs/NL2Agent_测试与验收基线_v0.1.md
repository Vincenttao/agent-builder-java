## 1 三类验证分别记录

| 类别 | 对象与目的 | 结果规则 |
| --- | --- | --- |
| 平台功能验收 | agent-builder 自身的 FR／NFR 与 AC | 当前阶段必测项逐项通过；失败、阻塞或缺证据均不通过阶段验收 |
| 生成项目业务验收 | 某个候选对应的 BR／TC | 固定候选和数据执行；不能用平台功能通过替代该候选通过 |
| 原型交付能力评测 | 固定开发任务集上的端到端交付成功率 | 原型完成后执行，保留全部任务尝试，首轮建立基线；现阶段不承诺成功率阈值 |

模型评分仅辅助语义解释。功能验收、模型评分和交付成功率分开显示。测试设计现在开始，运行与指标测量随实现开展；没有实际执行证据时本文件中的项目均为“未验证”。

| AC-42a | P0-A | 查看执行模式并经平台配置真实生产业务连接 | 明示 trusted-local、未启用沙箱；P0 连接入口拒绝生产业务类型，不自动注入生产凭据 |
| AC-42b | P0-B | 向业务代理提交伪造身份、未登记操作、任意 URL 或 Mock 管理路径 | 代理不信任正文身份，不执行未登记／管理操作；正常余额查询仍可成功 |
| AC-42c | P0-B | 通过正常任务入口检查生成 Tool 的调用模板；无连接身份直接调用 Mock API | 生成适配使用登记代理；不注入管理凭据；无身份请求由 Mock 拒绝。这不证明宿主上无法窃取凭据 |
| AC-42d | P0-C | 经正常代理发起未确认、已拒绝、已过期、跨 Run 或参数变化的写请求 | 代理逐项拒绝，下游写接口零调用；有效确认后才执行，幂等检查不因确认重复而失效 |

AC-23 的目录、依赖、命令和连接四类输入均需负向检查；范围是平台策略入口，不执行宿主逃逸攻击。AC-24 须覆盖开发目录变化、测试角色经平台尝试修改实现、候选副本被改动后摘要异常三个分支。摘要检查至少发生在测试装载前和执行结束后；异常结果不得通过。

AC-25 同时验证开发角色删除必测项、测试角色降低预期均不能自行改基线。AC-26 使用一个固定的字段映射缺陷：原失败证据保留，修复产生新候选，以同一断言重跑；不把修改预期值当作修复。

AC-28 分别注入“Agent 声称成功但外部结果不符”和“环境不可用”，前者失败、后者阻塞；两者都不通过。AC-30 必须验证同种子初态一致、并行实例数据互不影响、活动 Run／待核对操作期间重置拒绝、重置后旧证据保留。

## 6 测试执行与证据规则

1. 固定平台版本、SDK／模型配置、工程 Skill、GenerationProfile、需求、候选、测试集和场景包；准备每个用例的身份、种子、故障和预期。代码修复新建候选，基线修订按既定审阅流程处理。
2. **按固定候选批量测试：**每个代码／依赖／构建配置修订只构建一次 App／Runner 候选并记录镜像摘要；同一候选可连续执行多项验收用例。切换 AC、TC 或 NF 用例不触发 Docker 重建。不得在批次执行期间修改候选或将新代码写入运行镜像。
3. P0-A 使用快照运行与测试记录；P0-B/C 自动开发使用 TestDeployment 和 `/test-api`。每个用例前后核对制品摘要；同一验收批次中的报告必须绑定相同候选及 App／Runner 镜像摘要。用例可以使用不同环境实例或 Compose 项目，但须分别记录环境配置与实例 ID；不得混用发布版本与候选结果。
4. 用例可共用固定镜像，但不得因此共用可变业务状态。只读用例可顺序运行；修改账户、订单、发布指针、故障注入或进程状态的用例，须使用独立 TestDeployment／数据命名空间或经过验证的重置，并串行执行。停止 Runner、重启或崩溃注入等破坏性用例应使用隔离部署或放在批次末尾，随后验证服务恢复。
5. 每个用例独立记录输入、预期、实际、请求／Run、部署、环境／状态批次、外部调用及数据证据，并输出通过、失败、阻塞或未验证。构建、单测、业务验收、演示就绪分别判断；Agent 回答“成功”但外部状态不匹配时断言失败，缺证据时不通过。
6. 用例失败不自动触发重建。先区分实现缺陷、测试脚本错误和环境阻塞；脚本错误修正后在原候选重跑该用例，环境恢复后在环境兼容且候选摘要未变时重跑受阻用例。实现代码、依赖或构建配置修复后才生成新候选并重建受影响镜像；新候选须用一次构建完成本阶段完整累积必测批次。不同镜像摘要的旧用例结果不计入新候选门禁，除非未来增加经验证的影响分析和证据复用规则。历史失败记录保留。
7. 镜像存储位置迁移本身不触发功能回归；迁移前后镜像摘要和运行配置一致且服务健康检查通过时沿用原验收证据。镜像、配置或环境兼容键发生变化时，按对应变更重新验证。
8. 通过后按环境兼容规则将同一制品部署到独立演示实例；就绪与只读冒烟通过才切换。发布、回滚、停止及数据重置都保留历史证据。

## 7 原型完成后的交付成功率评测

评测单位是一次固定需求的完整开发任务尝试，不是一个 AC 或一次模型调用。以下是首批任务包；开始评测前锁定包版本、验收用例、重复次数与预算。每次重复从干净工程和新数据状态开始。暂不要求新的指标页面，记录导出加评审报告即可。
