# 静态 Demo 与真实工作台：页面差异、待补齐功能及实现路径

审阅日期：2026-10-25。范围：页面、导航、开发配置及其后端落地；本次不实施功能，不重新执行模型、Java 构建或业务交易。

## 1 结论

真实工作台已经恢复了静态 Demo 的主要框架，并增加真实 Git 工程、OpenCode、Java 调试与导出。问题不是“编排功能整体没有迁移”，而是**配置体验不完整、生命周期状态没有串联、模板供给与验证交付的产品闭环仍有缺口**。

建议保留现有 Node.js / Git / SQLite / 原生页面模块，沿原 Demo 补齐体验。先完善双角色工作流、操作约束编辑及模板发行，再接业务回归与候选证据。不重新开发一套工作台，也不恢复旧版 v1。

必须区分两种差距：

- **相对原 Demo 的体验退化**：模板说明与发行历史、操作规则表单、分阶段引导、运行筛选、草稿能力的编辑/移除等。
- **PRD 的真实能力尚未产品化**：测试集执行、证据绑定、模型/环境选择、升级兼容等。原 Demo 也只做过模拟，不能说这些真实能力“原来已实现，现在丢了”。

## 4 视觉与易用性判断

本次截图显示真实工作台已经是 PC 布局：左侧角色导航、工程标题、横向生命周期页签、中央工作区、右侧 Coding 助手。不能再概括为“手机版”。不过它仍比设计稿更像工程控制台：

1. **导航重复**：平台侧栏“公共能力/开发 Skill/编码任务/版本发行”，与工程页签内的入口重叠；模板工程的设置仍沿用“应用设置”文案。应保留角色差异，同时明确全局、模板、工程内三个层级。
2. **表单过长**：“应用设置”同时展开范围、Prompt、所有 Skill、Agent、续办与连接；编排页又投影同一组内容。应保留一个数据源，通过分区/选中对象编辑，不让用户反复滚动找字段。
3. **主操作不突出**：保存、放弃、版本 SHA 长期占据标题区，但用户更需要知道“现在可以做什么、还缺什么”。原 Demo 的状态横幅值得恢复。
4. **编排首屏取舍**：真实版把图放在输入预演之前，1280 宽度时首屏能看图，却看不到预演输入。建议将紧凑的输入/上下文条固定在图上方，节点详情按需展开；不要删除现有图。
5. **技术信息直接暴露**：概览的 release UUID、能力页的原始 JSON、Deep 工具“单任务最多 未声明 次”增加理解成本。应以模板名称/版本、字段表格和“当前范式不适用”代替无意义空值，详细原文折叠保留。
6. **状态不够精确**：Coding 面板的“已接入”来自页面呈现，不等于本次 OpenCode/模型可用性探测通过；能力维护方按当前工程角色推定，也没有区分模板来源与应用覆盖。需要显示可核对的状态和来源。

建议维持当前红/白/灰 PC 基线，统一选中态、按钮层级和间距；不引入新 UI 框架，也不以大规模视觉重做替代功能补齐。

## 6 推荐实现顺序与退出条件

每批只交付一个可观察结果，相关层验证通过后提交；下一批不自动成为上一批的验收前置条件。

| 批次 | 用户可观察的结果 | 范围 / 前置 | 最小验证及退出条件 |
| --- | --- | --- | --- |
| A：把现在的能力说清楚、找得到 | 新用户能选模板、理解来源；开发到一半能看到下一步；两角色导航清晰 | GAP-01/02，GAP-10 的只读说明、GAP-11 的展示一致性；仅 UI/读取投影 | 双角色×MOA/Deep 页面走查；1280/1440/1920；已有编排/Coding入口不退化；不构建 Java、不调用模型 |
| B：完成配置与平台发行 | 应用方可编辑 Skill 操作规则和引用，平台方检查后发行并查看版本历史 | GAP-03/04，GAP-11 的最小契约校验 | 文件/表单双向一致；过期与固定约束负例；发行 API 门禁；仅当改到执行器约束时做对应 Java 定向测试 |
| C：让设计与运行能互相核对 | 用户看懂请求去向、Skill 过程及真实事件差异，能从错误进入修订 | GAP-05/08，GAP-09 的诊断入口；复用现有执行器 | 保存版本一致、预演不执行业务、回放只读；真实 Trace 联调单列，不以 UI 通过代替 |

建议下一次实施从 **A 批**开始。它能够最快消除“页面丢了、内容看不懂”的感受，并暴露真实待办；不需要先做新 runtime、新数据库、Docker 或完整企业治理。

## 7 明确后置的能力

- 完整企业服务目录、业务账号权限与跨团队授权管理。当前先区分能力开放范围与业务调用身份，落实已接通执行边界；不以本机角色切换冒充企业权限系统。
- 通用 HTTP/MCP 接入平台、Agent 市场、工作流设计器。先将现有 SCRIPT/A2A/CORE 路径及接线状态表达清楚，再按实际企业需求增加适配器。现有脚本发 HTTP 不等于已有通用 HTTP 工具配置器。
